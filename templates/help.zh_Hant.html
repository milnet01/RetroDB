安裝

系統需求

  • Python 3.8+ 及 pip
  • 網頁瀏覽器（Chrome、Firefox、Safari、Edge）
  • 作業系統：Linux、Windows 10/11 或 macOS

快速安裝

  1. 將 RetroDB 的 ZIP 解壓到你選擇的目錄
  2. 在該目錄中開啟終端機／命令提示字元
  3. 執行：python install.py
  4. 啟動伺服器：
    • Linux：./start.sh
    • Windows：雙擊 start.bat
    • macOS：雙擊 start.command
  5. 在瀏覽器中開啟 http://localhost:5000

圖形介面安裝程式

在 Linux 上，你還可以執行 ./setup.sh 來啟動圖形化安裝精靈。它會自動檢查 Python／pip／tkinter，然後透過可視化的進度日誌引導你完成每一個安裝步驟。

install.py 的作用

  • 驗證 Python 3.8+ 和 pip 是否可用
  • 從 requirements.txt 安裝 Python 相依套件
  • 從範例範本建立 config.py
  • 建立所需的目錄（資料庫、日誌、媒體資料夾）
  • 建置 CSS 和 JS 套件

快速上手

首次設定

首次啟動時，RetroDB 會顯示一個設定精靈，引導你完成以下步驟：

  1. 管理員帳戶 — 建立你的使用者名稱和密碼
  2. 遊戲庫路徑 — 設定你的 ROM 目錄
  3. ES-DE 整合 — 可選地關聯 ES-DE 遊戲列表和媒體
  4. API 金鑰 — 可選地新增抓取器 API 金鑰

完成精靈後，點擊儀表板上的「掃描遊戲庫」以發現你的 ROM。

快速開始流程

  1. 掃描你的遊戲庫以匯入 ROM
  2. 按系統瀏覽，或在遊戲庫中查看所有遊戲
  3. 逐個抓取中繼資料，或使用批次抓取
  4. 使用標籤、列表和願望單進行整理
  5. 透過完成狀態和成就追蹤你的進度

ROM 遊戲庫結構

RetroDB 期望你的 ROM 在遊戲庫路徑下按系統資料夾組織：

ROM Library/
  nes/
    Super Mario Bros. (USA).nes
  snes/
    Chrono Trigger (USA).sfc
  psx/
    Final Fantasy VII (USA)/
      Final Fantasy VII (USA) (Disc 1).chd
      Final Fantasy VII (USA) (Disc 2).chd

每個系統資料夾都應包含一個 ES-DE systeminfo.txt 檔案，用於定義支援的檔案副檔名。RetroDB 在掃描時讀取該檔案，以識別哪些檔案是每個系統的有效 ROM。

提示：如果你已經用 ES-DE 抓取過，RetroDB 可以匯入那些資料！ 在設定 → ES-DE 整合中，或在設定精靈期間配置 ES-DE 路徑。

平台說明

Linux

  • 已在 Ubuntu、Fedora、openSUSE 和 Arch Linux 上測試
  • ROM 工具需要：sudo apt install p7zip-full unrar mame-tools（Debian/Ubuntu），或你所用發行版的等效命令
  • 如果使用系統 Python，安裝程式會自動處理 --break-system-packages
  • 支援 AMD GPU 的 ROCm GPU 加速（Real-ESRGAN 圖片放大）

Windows

  • 從 python.org 下載 Python（安裝時勾選 "Add to PATH"）
  • ROM 工具：安裝 7-Zip、WinRAR 和 MAME（用於 chdman）
  • 使用 start.bat 啟動，或從命令提示字元執行 python app.py

macOS

  • 可透過 Homebrew 安裝 Python 3：brew install python3
  • ROM 工具：brew install p7zip unrar rom-tools
  • 在 Finder 中雙擊 start.command 啟動
  • 支援 Apple Silicon 的 CoreML 加速（Real-ESRGAN 圖片放大）

運作原理

  • 主題會覆蓋 CSS 顏色變數 — 所有 UI 元素都會自動適配
  • 畫布效果包含自動硬體等級偵測（高／中／低），在可用時使用 GPU 加速，在低端裝置上回退到 CPU
  • 當標籤頁不可見時，效果會暫停以節省資源
  • Cyberpunk 煙霧狀態在頁面導覽間保持，以實現無縫過渡
  • 細微的 CRT 風格掃描線疊加層會適配每種主題的配色方案
  • 你的主題偏好會儲存在瀏覽器中，並在多次工作階段間保留

主題感知圖示

通知圖示、任務狀態指示器和操作圖示會自動適配當前主題。例如，成功圖示在 Cyberpunk 上可能顯示為綠色對勾，而在 Matrix 上則顯示為其他符號，以匹配黑底綠字的美學。

儀表板

合集健康度評分

一個環形進度圈以百分比形式顯示你合集的整體健康度，並按品質用顏色標識：

  • 綠色（80%+）— 中繼資料覆蓋極佳
  • 青色（60–79%）— 覆蓋良好，但有一些空缺
  • 橙色（40–59%）— 覆蓋一般，可考慮批量抓取
  • 紅色（<40%）— 中繼資料空缺較多

下方的細分小環顯示封面完整度、簡介完整度和成就覆蓋度。

任務恢復

如果 RetroDB 在後台任務（批量抓取、RA 同步、圖片縮放等）運行期間重啟，被中斷的任務會出現在恢復橫幅中。選項：

  • 恢復 — 重新啟動單個被中斷的任務
  • 全部恢復 — 重新啟動所有被中斷的任務
  • 忽略 — 從恢復列表中清除單個任務
  • 全部忽略 — 清除所有被中斷的任務

API 金鑰設定指南

API 金鑰是可選的，但可啟用豐富的中繼資料抓取和額外功能。在 設定 → 抓取 → API 金鑰 中配置它們。

中繼資料抓取器

TheGamesDB

  1. 前往 api.thegamesdb.net/key.php
  2. 申請 API 金鑰（免費，人工審核）— 你將收到一個 公鑰（Public） 和一個 私鑰（Private）
  3. 在 設定 → API 金鑰 → TheGamesDB 中輸入這兩個金鑰
  4. 公鑰（按 IP 限速）用作抓取的主金鑰
  5. 私鑰（共享月度額度池）在公鑰失敗時用作後備

IGDB（透過 Twitch）

  1. 在 twitch.tv 建立一個 Twitch 帳戶
  2. 前往 dev.twitch.tv/console
  3. 註冊一個新應用（任意名稱、任意類別，OAuth 重新導向填 http://localhost）
  4. 複製 Client ID 並生成一個 Client Secret
  5. 在 設定 → API 金鑰 → IGDB 中輸入兩者

RAWG.io

  1. 前往 rawg.io/apidocs
  2. 點擊 “Get API Key” 並建立一個帳戶
  3. 從儀表板複製你的 API 金鑰
  4. 在 設定 → API 金鑰 → RAWG 中輸入

免費額度：每月 20,000 次請求

ScreenScraper

  1. 在 screenscraper.fr 建立一個帳戶
  2. 在 設定 → API 金鑰 → ScreenScraper 中輸入你的使用者名稱和密碼

注意：ScreenScraper 根據你的帳戶等級設有每日請求限額。為資料庫做貢獻可提高你的限額。

成就與獎盃

RetroAchievements

  1. 在 retroachievements.org 建立一個帳戶
  2. 在你的個人資料上前往 設定 → API 金鑰
  3. 複製你的 API 金鑰
  4. 在 設定 → 帳戶 → RetroAchievements 中輸入你的使用者名稱和 API 金鑰

Steam Web API

  1. 前往 steamcommunity.com/dev/apikey
  2. 註冊一個 Steam Web API 金鑰（需要 Steam 帳戶）

設定

設定分為 6 個標籤頁，每個標籤頁都有多個子部分。

帳戶標籤頁

  • 我的資料 — 頭像上傳／移除、顯示名稱、角色資訊、修改密碼
  • RetroAchievements — 用於 RA 整合的使用者名稱和 API 金鑰
  • PSN — 用於 PlayStation Network 獎盃同步的 NPSSO cookie
  • 時區 — 設定你的時區，用於整個應用中的日期顯示
  • 使用者 — 使用者管理：新增、編輯、刪除使用者並分配角色（僅限管理員）

遊戲庫標籤頁

  • 路徑 — ROM 遊戲庫路徑、資料庫位置
  • 顯示 — 主題選擇、封面樣式（2D/3D）、偏好的年齡分級系統、每頁項目數
  • ROM 命名 — 冠詞位置（前置／後置的 “The”）、地區選項列表、預設地區、命名規範
  • 備份 — 建立和恢復資料庫備份

抓取標籤頁

  • ES-DE — 用於本地資料匯入的 ES-DE 遊戲列表和媒體路徑
  • 抓取器 — 啟用／停用單個抓取器、拖放優先級排序、每個抓取器的限速設定
  • API 金鑰 — 所有抓取器憑據（TGDB、IGDB、RAWG、ScreenScraper）、AI 提供商選擇和模型選擇（Gemini、OpenAI、Claude）

資料標籤頁

  • 統計 — 遊戲庫統計概覽（遊戲總數、系統數、儲存佔用）
  • 獎盃 — 用於本地 PS3 獎盃掃描的 RPCS3 獎盃路徑配置
  • 下拉選項 — 自訂地區選項和整個應用中使用的其他下拉值
  • 規範化 — 類型和模式的規範化規則 — 新增自訂映射以統一抓取器輸出

自訂標籤頁

  • 通知 — 通知超時偏好（成功、資訊、警告、錯誤 — 每種均可獨立配置）
  • 手把 — 管理手把庫、為每個系統設定預設手把、新增自訂手把。在中繼資料獲取期間，預設手把會覆蓋抓取／AI 的值。
  • 徽標 — 系統徽標自訂 — 匯入系統徽標或從預設恢復

系統標籤頁

  • 維護 — 資料庫優化（VACUUM/ANALYZE）、孤立媒體清理、清理缺失的 ROM、清除抓取資料、清除 CLZ 匯入、批量圖片標準化
  • 伺服器 — 伺服器配置（主機、連接埠、除錯模式）
  • 日誌 — 不同類別的日誌級別設定
  • 故障排除 — 清除卡住的批量抓取、清除 RA 同步佇列、清除 PSN 重新整理、清除博物館生成、重啟伺服器

混合抓取

RetroDB 會自動合併來自多個來源的資料，以最大化中繼資料的覆蓋範圍：

  • 文字中繼資料來自優先級最高的可用來源
  • 當主來源沒有圖片和媒體時，從次要來源獲取
  • 跨抓取器自動補全空缺，以獲得最大覆蓋
  • 抓取過程中會根據遊戲標題自動生成排序標題

媒體處理

  • 媒體欄位（封面、3D 封面、螢幕截圖、同人圖、影片、說明書）在正常抓取時絕不會被替換 — 只在為空時填充
  • 螢幕截圖始終是追加，絕不替換
  • 若要重新下載媒體，請先在編輯彈窗中清除現有圖片，然後重新抓取
  • 完全重新抓取模式會覆蓋此規則並替換所有內容
  • 失效的媒體引用（檔案已刪除但檔案名仍在資料庫中）會在抓取前自動清除，以便下載新的媒體
  • 下載的圖片會自動標準化為目標尺寸（參見圖片標準化）

抓取器優先級

在 設定 → 抓取 → 抓取器 中配置哪些抓取器優先運行以及哪些啟用/停用。拖放可重新排序優先級。停用的抓取器在抓取時不會被嘗試，也不會在儀表板上觸發 API 狀態警告。

速率限制

每個抓取器都有可配置的速率限制，以防止 API 被限流。預設延遲設定得較為保守。降低延遲需自行承擔風險 — 超出 API 速率限制可能導致相應服務對你臨時封禁。

AI 填充

它的作用

AI 填充使用大語言模型（Gemini、OpenAI 或 Claude）智能地填充缺失或不完整的遊戲中繼資料。它比常規抓取更聰明，因為它利用關於遊戲的上下文知識來提供抓取器可能沒有的準確資料。

如何使用

  1. 打開遊戲的詳情彈窗（或完整詳情頁）
  2. 點擊 "AI 填充"（需要在設定中配置 AI API 密鑰）
  3. AI 分析遊戲標題和系統，然後填充缺失的欄位
  4. 查看結果 — 更改會自動儲存

AI 填充可提供的內容

  • 類型、簡介、開發商、發行商、發行日期
  • 玩家人數、遊玩模式（單人、多人、合作等）
  • 戰役資訊和遊戲結構
  • 全部 8 個分級系統（ESRB、PEGI、CERO、USK、ACB、FPB、GRAC、ClassInd）
  • 地區、系列、相似遊戲
  • 手把支援、存檔類型
  • 視角（第一人稱、俯視、橫版捲軸等）、維度（2D、3D）
  • 版本資訊、媒體評分和使用者評分

智能填充邏輯

  • 空欄位始終會被填充
  • 現有的使用者資料絕不會被覆蓋
  • 相似遊戲始終會被重新整理（此欄位的 AI 資料更可靠）
  • 交叉映射的分級 — 如果已知一個分級系統，其他系統中空的分級會使用成熟度等級交叉映射自動填充
  • 填充時會自動生成排序標題
  • 玩家人數欄位會規範化範圍（例如 "1-4" 變為 4）

類型規範化

AI 填充使用帶連字符名稱的規範類型形式：

  • First-Person-Shooter、Shoot-em-up、Beat-em-up
  • Hack-n-Slash、Board-Card、Real-Time Strategy

要求

必須在 設定 → 抓取 → API 密鑰 中配置至少一個 AI 提供商的 API 密鑰。最便宜的模型層級（Gemini Flash Lite、GPT-4o Mini 或 Claude Haiku）對中繼資料的效果就很好。

合集（標籤、列表、願望清單）

標籤

建立自訂顏色的標籤來整理你的遊戲。標籤的作用類似於標記 — 每款遊戲可擁有多個標籤，每個標籤也可包含多款遊戲。

  • 在標籤頁面建立帶有自訂名稱和顏色的標籤
  • 透過遊戲詳情彈窗為遊戲分配標籤
  • 點擊任意標籤即可瀏覽帶有該標籤的所有遊戲
  • 在標籤管理頁面編輯或刪除標籤

命名列表

建立可自訂排序的精選遊戲列表。列表類似於播放列表 — 你可以精確控制遊戲的順序。

  • 在列表頁面建立帶有名稱、描述和圖示的列表
  • 透過遊戲詳情彈窗或列表頁面將遊戲加入到列表
  • 拖放以重新排列列表中的遊戲
  • 按自訂順序或字母順序排序

願望清單

  • 手動加入遊戲，包含標題、系統、備註和優先級（1–5）
  • 願望清單項目可在找到時連結到現有遊戲庫中的遊戲
  • 按優先級（從高到低）排序，然後按加入日期排序
提示：標籤適用於跨類別的標記（例如「收藏」「沙發合作」「待玩清單」），而列表適用於特定的精選合集（例如「十大 SNES 遊戲」「待直播遊戲」）。

  2. 點擊「掃描獎盃」以匯入已獲得的獎盃
  3. 在 RPCS3 獎盃部分查看獎盃列表和各個獎盃詳情

RPCS3 會從你的 RPCS3 使用者目錄讀取獎盃 XML 資料，並自動將遊戲與你的遊戲庫匹配。

PSN API 獎盃

從你的 PSN 帳戶同步 PlayStation Network 獎盃資料。

  1. 獲取你的 NPSSO cookie（見下文）
  2. 在設定 → 帳戶 → PSN中輸入它
  3. 你的 PSN 獎盃庫會透過 PlayStation API 獲取
  4. 查看每款遊戲的獎盃進度，附已獲得/總計數量
  5. 各個獎盃詳情包括描述、稀有度和解鎖時間戳

PSN 身分驗證（NPSSO Cookie）

PSN 使用一種稱為 NPSSO 權杖的特殊身分驗證 cookie。獲取方法如下：

  1. 打開網頁瀏覽器並登入 store.playstation.com
  2. 登入後，導航至：https://ca.account.sony.com/api/v1/ssocookie
  3. 該頁面會顯示包含你的 NPSSO 權杖的 JSON
  4. 複製 npsso 值並貼上到設定 → 帳戶 → PSN

身分驗證完成後，RetroDB 會將存取權杖安全地快取在自己的資料庫中（按使用者），並自動重新整理它們 — 你無需在每次同步時重新貼上 NPSSO。工作階段大約在兩個月內保持有效，而且 RetroDB 現在還會在後台自動續期，因此在正常使用中你應該很少需要獲取新的 NPSSO。

獎盃詳情

  • 獎盃類型：銅杯、銀杯、金杯、白金杯
  • 獎盃圖示會被下載並快取到本地
  • 每款遊戲的完成百分比
  • 每個已獲得獎盃的解鎖時間戳

批量同步

非標準名稱檔案名不符合命名規範的 ROM。顯示當前檔案名、偵測到的問題，以及建議的更正名稱。

  • 精確雜湊（MD5） — 僅識別完全相同的檔案
  • 視覺相似度 — 感知雜湊比較，閾值可配置（1–20，數值越低匹配越嚴格）

漸進式掃描並即時顯示統計資訊，包括已掃描遊戲數、重複數量和可回收空間。結果按遊戲和系統分組。你可以在每個重複組中選擇保留哪個檔案，或使用 “選擇最大” 自動保留解析度最高的版本。

至少需要一個抓取源 API 密鑰（IGDB / TGDB / ScreenScraper）

無外部依賴（使用內建的離線 HLTB 資料集）

用於審核批量 HLTB 查詢產生的模糊匹配的隊列。每一行待處理項都會顯示源遊戲及其對應的 HLTB 候選項（標題、平台、發行年份、置信度）。可逐行批准、拒絕或選擇其他匹配。僅當至少存在一個待處理匹配時，該審核工具卡片才會出現在 ROM 工具中心。

  • 針對低置信度、備用標題和平台不匹配等匹配的 篩選標籤頁。
  • 批准 會寫入遊玩時長估算；拒絕 會丟棄該候選項並保持查詢隊列整潔。

規範化

它的作用

將類型和遊戲模式的值規範化為統一的標準形式。此過程在抓取和 AI 填充時自動進行，也可以手動應用到你現有的遊戲庫。

為何重要

不同的抓取源對同一事物使用不同的名稱。規範化可確保整個遊戲庫的一致性：

  • platform → Platformer
  • fps, first person shooter → First-Person-Shooter
  • shoot 'em up, shmup → Shoot-em-up
  • beat 'em up, brawler → Beat-em-up
  • hack and slash → Hack-n-Slash
  • rts, real time strategy → Real-Time Strategy
  • board game, card game → Board-Card

自訂規則

你可以在 設定 → 資料 → 規範化 中添加自訂規範化規則。自訂規則會覆蓋內建映射，讓你定義自己偏好的類型和模式名稱。規則儲存在資料庫中。

預覽與應用

在應用規範化之前，你可以預覽哪些遊戲會受到影響以及將做出哪些更改。這讓你可以在向遊戲庫提交更改之前進行審核。

圖片標準化

它的作用

將所有遊戲媒體標準化為統一的目標尺寸，讓整個遊戲庫保持統一的外觀。尺寸在目標值 80–120% 範圍內的圖片會被略過。

工作原理

  • 放大 — 小於目標尺寸的圖片會使用 Real-ESRGAN x4（透過 ONNX Runtime 的 AI 超解析度）進行高品質放大，然後調整為精確的目標尺寸
  • 縮小 — 大於目標尺寸的圖片會使用 Lanczos 濾波進行縮小，以獲得清晰的效果
  • 閾值區間 — 處於目標值 80–120% 範圍內的圖片會保持不變，以避免不必要的重複處理

目標尺寸

媒體類型目標方法
封面高 1080px寬度按比例縮放
3D 封面高 1080px寬度按比例縮放（保留透明度）
螢幕截圖高 1080px寬度按比例縮放
手把最長邊 1280px保留透明度（RGBA）
硬件最長邊 1280px保留透明度（RGBA）
同人圖已略過不進行標準化（保持原始尺寸）

如何執行

  1. 前往 設定 → 系統 → 維護 或 ROM 工具 → 圖片調整器
  2. 點擊 “開始” 以啟動批量標準化
  3. 任務在後台執行，透過彈出通知顯示當前檔案和統計資訊
  4. 圖片在抓取過程中也會自動標準化（新下載的內容會立即標準化）

硬件支援

Real-ESRGAN 模型會自動偵測你的硬件並使用可用的最佳提供程序：

  • CUDA — NVIDIA GPU 加速
  • ROCm — AMD GPU 加速（針對 RX 6000 系列自動覆蓋 gfx 版本）
  • CoreML — Apple Silicon 加速
  • CPU — 無 GPU 支援的系統的後備方案

ONNX 模型檔案會在首次使用時從 Hugging Face 自動下載並快取到本地。

維護

維護操作位於 設定 → 系統 → 維護 中。它們有助於保持你的遊戲庫整潔並優化性能。

遊戲庫掃描

  • 掃描遊戲庫 — 掃描你的 ROM 目錄以查找新遊戲。使用 ES-DE 的 systeminfo.txt 副檔名列表偵測系統資料夾和支援的檔案類型。也可從儀表板使用。

清理操作

  • 清理缺失的 ROM — 刪除磁碟上 ROM 檔案已不存在的遊戲的資料庫條目。在重新整理或刪除 ROM 檔案後很有用。
  • 孤立媒體清理 — 查找並刪除磁碟上沒有對應資料庫引用的圖片檔案（封面、螢幕截圖、同人圖）。刪除前可先預覽以確認。
  • 清除已抓取資料 — 刪除遊戲的所有已抓取中繼資料，同時保留 ROM 檔案條目。適合重新開始抓取。預覽會在執行前顯示受影響的遊戲。
  • 清除 CLZ 匯入 — 刪除所有 CLZ Games 匯入記錄（僅含中繼資料、無 ROM 檔案的條目）。

資料庫優化

  • 優化資料庫 — 執行 SQLite VACUUM 和 ANALYZE，從已刪除記錄中回收儲存空間並更新查詢規劃器統計資訊。建議在大量刪除或清理操作後執行。

批量圖片標準化

將所有遊戲圖片標準化為目標尺寸。詳情請參閱 圖片標準化。

伺服器管理

  • 重啟伺服器 — 優雅地重啟應用程式（清理並退出）。位於 設定 → 系統 → 故障排除。

備份與恢復

創建備份

  1. 前往 設定 → 遊戲庫 → 備份
  2. 點擊 “創建備份”
  3. 備份會以帶時間戳的檔案名儲存到 backups/ 資料夾

備份內容

備份包含整個 SQLite 資料庫（roms.db），其中含有所有遊戲中繼資料、用戶帳戶、設定、獎盃資料、成就進度、標籤、列表和心願單項目。

未備份的內容

媒體檔案（封面、螢幕截圖、同人圖、影片、說明書）不包含在資料庫備份中，因為它們可以透過抓取重新下載。如果你有自訂上傳內容，可考慮單獨備份你的 static/images/ 目錄。

恢復

  1. 在備份列表中找到該備份
  2. 點擊 “恢復”
  3. 確認該操作
警告： 恢復備份會覆蓋你當前的資料庫。在恢復較舊的備份之前，請先創建一個新備份！

更新 RetroDB

如何更新

  1. 下載新的 RetroDB 版本
  2. 備份以下檔案（它們包含你的個人資料）：
    • config.py（你的路徑和 API 密鑰）
    • data/settings.json（你的 UI 偏好設定）
    • data/scraper_settings.json（你的抓取源配置）
    • data/rom_tools_config.json（你的 ROM 工具偏好設定）
    • database/ 資料夾（你的遊戲庫資料庫，以及已儲存的 PSN/Xbox 登入令牌）
  3. 將新版本解壓覆蓋到現有安裝之上
  4. 執行 python install.py 以安裝任何新的依賴項
  5. 重啟伺服器

可安全覆蓋的檔案

所有源代碼檔案（.py、.html、.css、.js）都可以安全覆蓋。安裝程式不會覆蓋你的個人配置檔案。

需要保留的檔案

切勿刪除或覆蓋：config.py、database/roms.db、data/settings.json、data/scraper_settings.json、data/rom_tools_config.json。

資料庫遷移

RetroDB 會在啟動時自動處理資料庫結構變更。新的列和表會按需添加而不會丟失資料。你無需做任何特殊操作 — 只需啟動新版本，資料庫便會自動更新。

故障排除

常見問題

“未找到該系統的副檔名”

該系統資料夾需要一個有效的 ES-DE systeminfo.txt 檔案，用於定義支援的 ROM 檔案副檔名。請確保你的 ROM 目錄結構符合 ES-DE 標準。

“API 連接失敗”

  • 檢查你的網路連接
  • 在 設定 → 抓取 → API 密鑰 中核對 API 密鑰
  • 如遇速率限制請稍候（部分 API 有每日/每小時上限）
  • 檢查該抓取源是否已啟用（已停用的抓取源在儀表板狀態中顯示“已停用”）
  • 查看日誌檢視器以獲取詳細的錯誤資訊

“批量抓取卡住”

前往 設定 → 系統 → 故障排除 → “清除卡住的批量抓取”。這會重置任務狀態而不影響你的資料。

“RA 同步隊列卡住”

從 設定 → 系統 → 故障排除 中清除 RetroAchievements 同步隊列。

“PSN 同步卡住”

從 設定 → 系統 → 故障排除 中清除 PSN 重新整理任務。

“博物館生成卡住”

從 設定 → 系統 → 故障排除 中清除博物館生成任務。

“資料庫錯誤”

  1. 如有可能，先創建一個備份（設定 → 遊戲庫 → 備份）
  2. 嘗試 設定 → 系統 → 維護 → 優化資料庫
  3. 檢查 database/ 目錄的檔案權限
  4. 最後手段：從備份恢復，或刪除資料庫並重新掃描

“圖片未儲存”

檢查媒體目錄的寫入權限：chmod -R 755 static/images/

“頁面緩慢或無響應”

  • 大型合集可能需要時間載入 — 無限滾動以每批 100 個的方式載入
  • 嘗試重新整理頁面以清除累積的記憶體
  • 檢查瀏覽器控制台是否有 JavaScript 錯誤
  • 嘗試切換到畫布效果更輕量的主題（例如 Amber 或 Elite）
  • 畫布效果會自動偵測硬件；低端設備會以降低的幀率使用 CPU 後備方案

儀表板上的“中斷的任務”橫幅

如果 RetroDB 在任務執行時重啟，它們會出現在一個恢復橫幅中。逐個點擊 “恢復” 或點擊 “全部恢復” 以重新啟動它們。點擊 “忽略” 或 “全部忽略” 以清除它們。

“PSN 身份驗證失敗”

  • NPSSO 令牌會過期 — 請從 ca.account.sony.com/api/v1/ssocookie 生成一個新的
  • 在存取該 cookie 網址之前，請確保你已登入 store.playstation.com
  • RetroDB 會將你的 PSN 會話快取約兩個月，並且現在會在後台自動續期；如果仍然失效，只需在 設定 → 帳戶 → PSN 中貼上一個新的 NPSSO 即可

“Xbox 身份驗證失敗”

  • 在 遊戲匯入 → Xbox 標籤頁中點擊“登入”以重新驗證
  • Xbox 令牌快取在 data/xbox_tokens.json 中並會自動重新整理

“圖片放大錯誤”

  • Real-ESRGAN ONNX 模型會在首次使用時下載 — 請確保有網路存取權限
  • GPU 加速需要相容的驅動程序（NVIDIA 用 CUDA，AMD 用 ROCm）
  • 如果 GPU 失敗，系統會自動回退到 CPU 處理

性能提示

  • 保持瀏覽器為最新版本以獲得最佳性能
  • 處理超大型合集時關閉其他瀏覽器標籤頁
  • 使用系統篩選器以減少一次顯示的遊戲數量
  • 在大量操作（抓取、清理、匯入）後定期執行優化資料庫
  • 畫布主題效果會自動偵測硬件；低端設備會使用 CPU 後備方案

安全與免責聲明

安全最佳實踐

  • 更改預設密碼 — 預設的管理員密碼（admin）應在首次登入時立即更改。請使用至少 8 個字符的強密碼。
  • 使用 HTTPS 反向代理 — RetroDB 本身不提供 TLS/SSL。請將其置於反向代理（例如 Nginx、Caddy、Traefik）之後並啟用 HTTPS，以加密客戶端與伺服器之間的流量。
  • 限制網路存取 — 避免將 RetroDB 直接暴露到公共互聯網。請使用 VPN 或將存取限制在你的本地網路內。如果需要遠端存取，請使用帶身份驗證的反向代理。
  • 保持定期備份 — 使用設定中內建的備份功能定期創建資料庫備份。將備份存放在與應用程式不同的位置。
  • 保持 RetroDB 更新 — 定期檢查新版本。更新中包含安全修復和改進。
  • 保護你的 API 密鑰 — API 密鑰儲存在 data/scraper_settings.json 中。請確保該檔案不會被公開存取。切勿分享你的 config.py 或令牌檔案。

內建安全功能

  • 密碼雜湊 — 管理員密碼使用 PBKDF2 進行雜湊處理（絕不以明文儲存）
  • 登入速率限制 — 對登入端點的暴力破解防護
  • 路徑驗證 — 所有檔案操作都使用 safe_path 和 safe_filename 輔助函數以防止目錄遍歷攻擊
  • 參數化查詢 — 所有資料庫查詢都使用參數化語句以防止 SQL 注入
  • XSS 防護 — 模態對話框使用安全的 DOM 構造；用戶輸入會被轉義
  • 圖片解壓炸彈防護 — 圖片的最大像素數受到限制，以防止惡意圖片耗盡記憶體
