安裝

系統需求

  • Python 3.12+ 及 pip
  • 網頁瀏覽器（Chrome、Firefox、Safari、Edge）
  • 作業系統：Linux、Windows 10/11 或 macOS

快速安裝

  1. 將 RetroDB 的 ZIP 解壓到你選擇的目錄
  2. 在該目錄中開啟終端機／命令提示字元
  3. 執行：python install.py
  4. 啟動伺服器：
    • Linux：./start.sh
    • Windows：雙擊 start.bat
    • macOS：雙擊 start.command
  5. 在瀏覽器中開啟 http://localhost:5000

圖形介面安裝程式

在 Linux 上，你還可以執行 ./setup.sh 來啟動圖形化安裝精靈。它會自動檢查 Python／pip／tkinter，然後透過可視化的進度日誌引導你完成每一個安裝步驟。

install.py 的作用

  • 驗證 Python 3.12+ 和 pip 是否可用
  • 從 requirements.txt 安裝 Python 相依套件
  • 從範例範本建立 config.py
  • 建立所需的目錄（資料庫、日誌、媒體資料夾）
  • 建置 CSS 和 JS 套件

快速上手

首次設定

首次啟動時，RetroDB 會顯示一個設定精靈，引導你完成以下步驟：

  1. 管理員帳戶 — 建立你的使用者名稱和密碼
  2. 遊戲庫路徑 — 設定你的 ROM 目錄
  3. ES-DE 整合 — 可選地關聯 ES-DE 遊戲列表和媒體
  4. API 金鑰 — 可選地新增抓取器 API 金鑰

完成精靈後，點擊儀表板上的「掃描遊戲庫」以發現你的 ROM。

快速開始流程

  1. 掃描你的遊戲庫以匯入 ROM
  2. 按系統瀏覽，或在遊戲庫中查看所有遊戲
  3. 逐個抓取中繼資料，或使用批次抓取
  4. 使用標籤、列表和願望單進行整理
  5. 透過完成狀態和成就追蹤你的進度

ROM 遊戲庫結構

RetroDB 期望你的 ROM 在遊戲庫路徑下按系統資料夾組織：

ROM Library/
  nes/
    Super Mario Bros. (USA).nes
  snes/
    Chrono Trigger (USA).sfc
  psx/
    Final Fantasy VII (USA) (Disc 1).chd
    Final Fantasy VII (USA) (Disc 2).chd

請把 ROM 檔案直接放在系統資料夾中。子資料夾中的檔案會被略過，PS3 除外。

每個系統資料夾都應包含一個 ES-DE systeminfo.txt 檔案，用於定義支援的檔案副檔名。RetroDB 在掃描時讀取該檔案，以識別哪些檔案是每個系統的有效 ROM。

提示：如果你已經用 ES-DE 抓取過，RetroDB 可以匯入那些資料！ 在設定 → ES-DE 整合中，或在設定精靈期間配置 ES-DE 路徑。

平台說明

Linux

  • 已在 Ubuntu、Fedora、openSUSE 和 Arch Linux 上測試
  • ROM 工具需要：sudo apt install p7zip-full unrar mame-tools（Debian/Ubuntu），或你所用發行版的等效命令
  • 如果系統 Python 不允許安裝套件，安裝程式會為 RetroDB 建立專屬的 Python 資料夾（.venv），不會更動系統 Python
  • 支援 AMD GPU 的 ROCm GPU 加速（Real-ESRGAN 圖片放大）

Windows

  • 從 python.org 下載 Python（安裝時勾選 "Add to PATH"）
  • ROM 工具：安裝 7-Zip、WinRAR 和 MAME（用於 chdman）
  • 使用 start.bat 啟動，或從命令提示字元執行 python app.py

macOS

  • 可透過 Homebrew 安裝 Python 3：brew install python3
  • ROM 工具：brew install p7zip unrar rom-tools
  • 在 Finder 中雙擊 start.command 啟動
  • 支援 Apple Silicon 的 CoreML 加速（Real-ESRGAN 圖片放大）

RetroDB 提供 7 種視覺主題，每種都有獨特的配色方案和動態畫布背景效果。在 設定 → 遊戲庫 → 顯示 中更改主題。 背景會在你不使用 RetroDB 時暫停：視窗不在最前面，或一分鐘內沒有動過滑鼠或鍵盤。若要在這台電腦上讓它保持靜止，請在主題下方關閉 動態背景。

運作原理

  • 主題會覆蓋 CSS 顏色變數 — 所有 UI 元素都會自動適配
  • 畫布效果包含自動硬體等級偵測（高／中／低），在可用時使用 GPU 加速，在低端裝置上回退到 CPU
  • 當標籤頁不可見時，效果會暫停以節省資源
  • Cyberpunk 煙霧狀態在頁面導覽間保持，以實現無縫過渡
  • 細微的 CRT 風格掃描線疊加層會適配每種主題的配色方案
  • 你的主題會儲存在帳戶中，因此無論在哪個瀏覽器登入都會沿用

主題感知圖示

通知圖示、任務狀態指示器和操作圖示會自動適配當前主題。例如，成功圖示在 Cyberpunk 上可能顯示為綠色對勾，而在 Matrix 上則顯示為其他符號，以匹配黑底綠字的美學。

任務恢復

如果 RetroDB 在後台任務（批次抓取、RA 同步、圖片縮放等）運行期間重啟，被中斷的任務會出現在恢復橫幅中。選項：

  • 繼續 — 重新啟動單個被中斷的任務
  • 全部繼續 — 重新啟動所有被中斷的任務
  • 忽略 — 從恢復列表中清除單個任務
  • 全部忽略 — 清除所有被中斷的任務

API 金鑰設定指南

API 金鑰是可選的，但可啟用豐富的中繼資料抓取和額外功能。在 設定 → 抓取 → API 金鑰 中配置它們。

中繼資料抓取器

TheGamesDB

  1. 前往 api.thegamesdb.net/key.php
  2. 申請 API 金鑰（免費，人工審核）— 你將收到一個 公鑰（Public） 和一個 私鑰（Private）
  3. 在 設定 → 抓取 → API 金鑰 中，把公開金鑰填入 TheGamesDB — 主金鑰，把私密金鑰填入 TheGamesDB — 備用金鑰
  4. 先使用主金鑰；每個網路連線都有自己的額度
  5. 主金鑰用完時會使用備用金鑰；它每月大約允許 6000 次請求

IGDB（透過 Twitch）

  1. 在 twitch.tv 建立一個 Twitch 帳戶
  2. 前往 dev.twitch.tv/console
  3. 註冊一個新應用（任意名稱、任意類別，OAuth 重新導向填 http://localhost）
  4. 複製 Client ID 並生成一個 Client Secret
  5. 在 設定 → API 金鑰 → IGDB 中輸入兩者

RAWG.io

  1. 前往 rawg.io/apidocs
  2. 點擊 “Get API Key” 並建立一個帳戶
  3. 從儀表板複製你的 API 金鑰
  4. 在 設定 → API 金鑰 → RAWG 中輸入

免費額度：每月 20,000 次請求

MobyGames

  1. 前往 mobygames.com/info/api 並選擇一個 API 方案
  2. 從你的 MobyGames 帳號中複製你的 API 金鑰
  3. 在 設定 → API 金鑰 → MobyGames 中輸入

MobyGames 每小時允許幾百次請求。RetroDB 會從每次回覆中讀取額度，並等待輪到自己。因該小時額度用完而被跳過的遊戲，會在額度重設後自動再次查詢。

ScreenScraper

  1. 在 screenscraper.fr 建立一個帳戶
  2. 在 設定 → API 金鑰 → ScreenScraper 中輸入你的使用者名稱和密碼

注意：ScreenScraper 根據你的帳戶等級設有每日請求限額。為資料庫做貢獻可提高你的限額。

成就與獎盃

RetroAchievements

  1. 在 retroachievements.org 建立一個帳戶
  2. 在你的個人資料上前往 設定 → API 金鑰
  3. 複製你的 API 金鑰
  4. 在 設定 → 帳戶 → RetroAchievements 中輸入你的使用者名稱和 API 金鑰

Steam Web API

  1. 前往 steamcommunity.com/dev/apikey
  2. 註冊一個 Steam Web API 金鑰（需要 Steam 帳戶）
  3. 在設定中輸入你的 API 金鑰和 Steam ID（或個性化 URL）

用於 Steam 遊戲庫匯入和成就追蹤。

Xbox Live

Xbox 透過免費服務 OpenXBL 連線到 RetroDB。每個人使用自己的金鑰：用你的 Xbox 帳戶登入 xbl.io，複製你的 API 金鑰，然後貼到 設定 → 帳戶 → 我的資料 → Xbox 中。儲存我的資料會檢查金鑰並顯示你的玩家代號（gamertag）。免費金鑰每小時允許 150 次請求。

PlayStation Network (PSN)

PSN 使用 NPSSO cookie 認證。詳細設定說明請參見 獎盃 部分。

AI 提供商（用於 AI 填充與博物館）

AI 填充中繼資料和博物館內容生成需要一個 AI 提供商。可從以下選項中選擇：

提供商預設模型

每家提供商都提供多個模型。標有「建議」的那個對中繼資料和博物館內容表現良好；最新價格請看各提供商自己的網站。在 設定 → 抓取 → API 金鑰 中配置你偏好的提供商和 API 金鑰。

Gemini 和 OpenAI 一律上網搜尋。只有在 Claude 的模型下方開啟 允許 Claude 上網搜尋 時，Claude 才會搜尋。不搜尋時，Claude 會將需要公開數據的內容（如銷量）留空。Anthropic 按每次搜尋收費：每個遊戲最多搜尋 5 次，最多 5 美分。

設定

設定分為多個標籤頁，每個標籤頁都有子部分。管理員還會看到「模擬器」標籤頁，它會開啟獨立的頁面。

每個人只會看到自己的角色可以變更的設定。檢視者或玩家能看到「帳戶」分頁。編輯者還能看到「附贈光碟」和「手把」。其餘設定僅限管理員。

帳戶標籤頁

  • 我的資料 — 你的頭像、你自己的 RPCS3 獎盃資料夾，以及你自己的 RetroAchievements、PlayStation Network、Xbox 和 Steam 帳戶。填寫 RetroAchievements 使用者名稱和網頁 API 金鑰後，就能顯示你的成就；用密碼登入後，玩遊戲時才能解鎖成就。一個儲存我的資料按鈕就能儲存整張卡片，並檢查新的 PlayStation 權杖或 Xbox 金鑰。更改密碼需要把新密碼輸入兩次，至少 12 個字元。
  • 主題和語言 — 你的主題、你的語言和動態背景
  • 通知 — 每種訊息在畫面上停留多久，只對你自己有效
  • 時區 — 設定你的時區，用於整個應用中的日期顯示
  • 使用者 — 使用者管理：新增、編輯、刪除使用者並分配角色（僅限管理員）

遊戲庫標籤頁

  • 路徑 — ROM 遊戲庫資料夾、ES-DE 的遊戲清單和媒體資料夾，以及全家共用的 RPCS3 獎盃資料夾，共用一個儲存按鈕
  • 顯示 — 封面樣式（2D/3D）和偏好的年齡分級系統，對所有人生效
  • ROM 命名 — 冠詞位置（前置／後置的 “The”）、地區選項列表、預設地區、命名規範
  • 附贈光碟 — 尋找附贈光碟，並把它們連結到對應的遊戲
  • 備份 — 建立和恢復資料庫備份

抓取標籤頁

  • 抓取器 — 開啟或關閉抓取器，並拖曳它們來調整嘗試的順序。批次抓取比對篩選決定結果要多接近才會被採用：嚴格只接受完全相同的標題，普通（建議）（預設）接受同一系統上相近的標題，寬鬆連部分相符的標題也接受。你在舊版本中做的設定會顯示為自訂，直到你另選一項。
  • API 金鑰 — 所有抓取器憑證（TheGamesDB、IGDB、RAWG、ScreenScraper）、AI 提供商選擇和模型選擇（Gemini、OpenAI、Claude），以及全家共用的 RetroAchievements 和 Steam 金鑰。優先使用「我的資料」裡你自己的 RetroAchievements 金鑰，沒有金鑰的人才會用全家共用的。全家共用的 Steam 金鑰只供沒有自己金鑰的管理員使用。

資料標籤頁

  • 下拉選單 — 自訂類型、視角和存檔類型等清單中提供的值
  • 標準化 — 類型和模式的標準化規則 — 新增自訂映射以統一抓取器輸出

自訂標籤頁

  • 手把 — 開啟手把頁面會進入手把頁面。你可以在那裡設定每個系統的預設手把、新增自己的手把，並編輯手把庫。預設手把會在取得中繼資料時覆寫抓取/AI 的值。
  • 標誌 — 重新整理系統徽標會從你的 ES-DE 資料夾複製新的徽標，然後顯示哪些系統還沒有徽標

系統標籤頁

  • 維護 — 清理遺失的 ROM、清除 CLZ 匯入或已抓取的資料、刪除沒有遊戲使用的媒體檔案、清除指向已不存在媒體檔案的連結、最佳化資料庫，以及計算檔案大小
  • 更新 — 檢查、下載並安裝新版本
  • 伺服器 — 重新啟動或關閉 RetroDB、它使用的連接埠（重新啟動後位址會改變），以及資料庫的位置
  • 日誌 — 各類別的日誌層級設定，以及日誌檔案

模擬器與遊玩

管理員在 設定 → 模擬器 中設定模擬器。把存放模擬器的資料夾加入模擬器資料夾。RetroDB 會在其中找到每個模擬器（AppImage、可攜式指令碼或已安裝的 Flatpak），並將其與它能執行的系統關聯起來。對應表會把每個系統顯示一次，附帶一個用於選擇其模擬器的清單，並顯示該模擬器是否可用，以及其 BIOS 檔案是否就位。RetroDB 只讀取 BIOS 檔案，絕不會複製或下載它們。

模擬器可用的遊戲，會在遊戲頁面、資料庫卡片和系統頁面上顯示遊玩按鈕。

還沒有模擬器？在同一頁面的在 RetroDB 中遊玩下按取得 RetroArch。RetroDB 會從 libretro 下載官方 RetroArch，檢查下載內容，並將其設定為 RetroArch (RetroDB)，擁有自己的設定和存檔，與你已在使用的任何 RetroArch 分開。之後，在你第一次遊玩時，它會為每個系統下載最合適的核心。對於多光碟遊戲，下一張光碟無需任何設定即可使用。在這類遊戲執行時（在 Windows 和 macOS 上則是任何遊戲執行時），RetroArch 會在一個網路連接埠上監聽 RetroDB 的指令。

對於 DuckStation、PCSX2 和 RPCS3，RetroDB 還會在模擬器自己的單遊戲設定檔中，為每個遊戲設定解析度縮放和長寬比，以及遊戲是否全螢幕啟動。要修改整個系統的值，請使用對應表中的設定按鈕；要修改單一遊戲，請使用其遊戲頁面上的模擬器設定面板。這些值會在你按下遊玩時寫入。你在模擬器內部修改的設定一律優先：此後 RetroDB 不再改動它。請在遊玩前先執行一次每個模擬器，讓它建立自己的設定資料夾。

金手指

在同一頁的金手指下，按下載取得免費的公開金手指包，或匯入你已有的金手指資料夾。RetroDB 會複製檔案，絕不改動你的資料夾；再次匯入即可取得新檔案。之後，在 RetroArch (RetroDB)、DuckStation 或 PCSX2 中遊玩的遊戲，其遊戲頁面會顯示金手指面板，每個金手指都有開／關切換。對於 RetroArch (RetroDB)，你開啟的金手指會在你下次按下遊玩時生效，而你在遊玩時於 RetroArch 自己的選單中切換的開關會被保留。對於 DuckStation 和 PCSX2，開關會直接儲存到模擬器中該遊戲的設定裡，所以在模擬器內所做的變更也會顯示在面板中。RetroDB 絕不覆寫模擬器已有的金手指檔案。開啟金手指會暫停 RetroAchievements 硬核模式；DuckStation 和 PCSX2 在硬核模式下會忽略金手指。

對於在 MAME 中遊玩的街機遊戲，請在瀏覽器中從 mamecheat.co.uk 下載「MAME XML Cheats Collection」，然後匯入存放它的資料夾。RetroDB 會依其自述檔的要求保持其壓縮狀態，並從中一次性讀取每個遊戲的金手指名稱，為此會從網際網路取得 7-Zip 工具。之後，遊戲頁面會列出該遊戲的金手指，每個普通的開/關金手指都有一個開關，MAME 啟動時會啟用已打開的金手指。需要輸入數值或只生效一次的金手指沒有開關：遊玩時依序按 Tab、Plugin Options、Cheat 來設定。你在那裡更改的開關，會在結束 MAME 後顯示在遊戲頁面上。匯入較新的合集會取代舊的。

帶有 RetroAchievements 的街機遊戲會改在使用 FinalBurn Neo 核心的 RetroArch (RetroDB) 中遊玩，因為 RetroAchievements 不支援 MAME；其餘遊戲仍在 MAME 中遊玩。在同一頁面按 FinalBurn Neo 街機金手指旁的下載，這樣的每個遊戲的頁面就會列出它的金手指。FinalBurn Neo 每次啟動遊戲都會關閉所有金手指，所以清單中沒有開關：遊玩時按 F1 開啟 RetroArch 的選單，然後依序選擇 Core Options、Cheat。遊戲執行時，RetroDB 會把它的金手指檔案放進 RetroArch 的系統資料夾，除非那裡已有同名檔案，並在遊戲停止時將其刪除。要在 MAME 中遊玩這類遊戲，請在其編輯視窗的啟動下的模擬器覆蓋中選擇 MAME。

單個遊戲抓取

  1. 打開任意遊戲的詳情彈窗（點擊遊戲卡片）
  2. 點擊 "抓取"
  3. 如有需要，修改搜尋標題
  4. 從匹配結果中選擇正確的條目
  5. 點擊 "套用"

抓取來源

混合抓取

RetroDB 會自動合併來自多個來源的資料，以最大化中繼資料的覆蓋範圍：

  • 文字中繼資料來自優先級最高的可用來源
  • 當主來源沒有圖片和媒體時，從次要來源獲取
  • 跨抓取器自動補全空缺，以獲得最大覆蓋
  • 抓取過程中會根據遊戲標題自動生成排序標題
  • 只有當某個來源列出了該遊戲的系統時才會搜尋它，並且只在該系統中搜尋：RAWG 沒有 Intellivision，因此不會在 RAWG 上查找 Intellivision 遊戲，否則只會比對到其他平台的遊戲
  • 開啟 AI 時，它還會給出遊戲在其 ROM 所屬地區發行時的官方標題，遊戲會被重新命名為該標題，單一遊戲抓取和批次抓取中都是如此（參見AI 填充）

媒體處理

  • 媒體欄位（封面、3D 封面、盒子背面、螢幕截圖、同人圖、標誌、影片、說明書）在正常抓取時絕不會被取代 — 只在為空時填充
  • 螢幕截圖始終是追加，絕不替換
  • 若要重新下載媒體，請先在編輯彈窗中清除現有圖片，然後重新抓取
  • 完整重新抓取模式會覆蓋此規則並替換所有內容
  • 失效的媒體引用（檔案已刪除但檔案名仍在資料庫中）會在抓取前自動清除，以便下載新的媒體
  • 下載的圖片會自動標準化為目標尺寸（參見圖片標準化）

保留標題

當你在編輯視窗中輸入新標題並儲存後，抓取就不會再更改它，完整重新抓取也一樣。編輯視窗中的抓取時保留此標題核取方塊會顯示標題是否被保留；取消勾選即可讓抓取器再次重新命名該遊戲。遊戲頁面上的重置也會讓抓取器重新命名它，而維護中的清除抓取資料會讓保留的標題保持不變。

抓取器優先級

在 設定 → 抓取 → 抓取器 中配置哪些抓取器優先運行以及哪些啟用/停用。拖放可重新排序優先級。停用的抓取器在抓取時不會被嘗試，也不會在儀表板上觸發 API 狀態警告。

速率限制

RetroDB 會自行錯開對每個服務的請求，不需要設定。當某個服務表示已達到上限時，RetroDB 會在該服務給出的時間之前停止向它發出請求，並給出提示（見疑難排解）。

批次抓取

開始批次抓取

  1. 前往任意系統或遊戲庫頁面
  2. 點擊 "選擇" 進入選擇模式。選擇工具會出現在視窗底部的一個列中。
  3. 逐個選擇遊戲，或使用快速選擇：
    • 全選 — 所有可見的遊戲
    • 選擇未抓取的 — 僅無中繼資料的遊戲
  4. 選擇模式：填充缺失項 或 完整重新抓取
  5. 點擊 "抓取所選"
  6. 點擊 "完成" 離開選擇模式

控制

  • 暫停 / 繼續 — 暫停或繼續抓取
  • 取消 — 徹底停止
  • 後台 — 最小化並在抓取運行時繼續瀏覽

提示通知

在後台運行時，會有一個常駐提示在所有頁面上顯示進度：

  • 當前遊戲名稱、進度計數和結果統計（成功、失敗、已略過）
  • 可從任意頁面使用暫停/取消控制
  • 點擊提示可返回抓取彈窗

佇列系統

多個批次抓取會自動排隊：

  • 在一個抓取運行時啟動新的抓取 — 它會進入佇列
  • 佇列會在提示中顯示待處理任務的數量
  • 任務會按順序自動處理
  • 使用佇列管理器可查看、重新排序或取消排隊的任務

抓取選項

  • 僅填充缺失 — 只填充空的中繼資料欄位，保留現有資料
  • 完整重新抓取 — 替換所有欄位，包括媒體（下載新的圖片和影片）
  • 保留現有媒體 — 使用完整重新抓取時，保留磁碟上已有的圖片、影片和手冊，而不是重新下載。仍會加入新的截圖。
  • 檢查 RetroAchievements — 抓取時也檢查 RetroAchievements 成就集

任務恢復

AI 填充

它的作用

AI 填充使用大語言模型（Gemini、OpenAI 或 Claude）智能地填充缺失或不完整的遊戲中繼資料。它比常規抓取更聰明，因為它利用關於遊戲的上下文知識來提供抓取器可能沒有的準確資料。

如何使用

  1. 打開遊戲的詳情彈窗（或完整詳情頁）
  2. 點擊 "AI 填充"（需要在設定中配置 AI API 金鑰）
  3. AI 分析遊戲標題和系統，然後填充缺失的欄位
  4. 查看結果 — 更改會自動儲存

一次處理多個遊戲

要填充整個系統，請開啟ROM 工具 → 批量 AI 填充，使用用 AI 填充空白欄位卡片。開啟你想填充的欄位；只統計其中任一欄位為空的遊戲，欄位越少，費用越低。選擇一個系統或「所有系統」，然後點擊用 AI 填充。它會對每個遊戲執行 AI 填充，並將結果直接儲存到遊戲中。卡片上的進度列和 AI 填充通知會顯示進度，執行期間你可以離開此頁面。已做過 AI 填充的遊戲會被略過，因此第二次執行只處理剩下的遊戲；開啟包含 AI 填充已處理過的遊戲，也可為它們填充某個欄位，例如銷量。如果 AI 停止回應，例如金鑰被拒絕或帳戶沒有餘額，工作會自動停止。你的 AI 服務商按每個遊戲收費。

AI 填充可提供的內容

  • 類型、簡介、開發商、發行商、發行日期
  • 玩家人數、遊玩模式（單人、多人、合作等）
  • 戰役資訊和遊戲結構
  • 全部分級系統（ESRB、PEGI、CERO、USK、ACB、FPB、GRAC、ClassInd、CADPA）
  • 地區、系列、相似遊戲
  • 手把支援、存檔類型
  • 視角（第一人稱、俯視、橫版捲軸等）、維度（2D、3D）
  • 版本資訊、媒體評分和使用者評分

智能填充邏輯

  • 空欄位始終會被填充
  • 現有的使用者資料絕不會被覆蓋
  • 相似遊戲始終會被重新整理（此欄位的 AI 資料更可靠）
  • 交叉映射的分級 — 如果已知一個分級系統，其他系統中空的分級會使用成熟度等級交叉映射自動填充
  • 填充時會自動生成排序標題
  • 官方標題 — AI 還會給出遊戲在其 ROM 所屬地區發行時的官方標題，遊戲會被重新命名為該標題，在 AI 填充中以及抓取時 AI 填補空缺時都是如此。舊名稱會保留為備用標題。你自己輸入的標題，或用抓取時保留此標題保留的標題，絕不會被重新命名
  • 玩家人數欄位會標準化範圍（例如 "1-4" 變為 4）

類型標準化

AI 填充使用帶連字符名稱的規範類型形式：

  • First-Person-Shooter、Shoot-em-up、Beat-em-up
  • Hack-n-Slash、Board-Card、Real-Time Strategy

要求

必須在 設定 → 抓取 → API 金鑰 中配置至少一個 AI 提供商的 API 金鑰。最便宜的模型層級（Gemini Flash Lite、GPT-4o Mini 或 Claude Haiku）對中繼資料的效果就很好。

篩選與搜尋

搜尋

搜尋按標題（和排序標題）篩選遊戲。按 / 可聚焦搜尋框。結果實時更新，帶 300 毫秒防抖。

來源篩選

按匯入來源篩選遊戲：

  • ROM 檔案 — 來自你的 ROM 遊戲庫的遊戲
  • CLZ 匯入 — 從 CLZ 匯入的實體遊戲
  • Steam 匯入 — 從 Steam 匯入的遊戲
  • Xbox 匯入 — 從 Xbox 匯入的遊戲
  • PSN 匯入 — 從 PlayStation Network 匯入的遊戲

篩選按鈕

每個篩選器都會打開一個彈窗，顯示你遊戲庫中所有的唯一值及其數量。篩選器支援兩種模式：

  • 包含（IS） — 只顯示匹配所選值的遊戲
  • 排除（IS NOT） — 隱藏匹配所選值的遊戲

使用篩選彈窗中的開關在包含和排除模式之間切換。

在類型、系列、發行商、開發商、遊玩模式、視角和維度篩選器中，可勾選任意數量的值，然後按套用。遊戲只要具有任一勾選的值就會顯示；在排除模式下，遊戲只要具有其中任一值就會被隱藏。每個值在遊戲上方都有自己的標籤，點擊其 × 只會移除該值。分級和來源篩選器只取一個值，點擊後立即生效。

排序選項

在遊戲數量旁邊的排序方式中選擇順序：

  • 名稱 — 按排序標題字母順序（不區分大小寫）
  • 最新發行 / 最早發行 — 按發行日期
  • 媒體評分 / 使用者評分 — 最高的在前
  • 最近新增 — 最後加入遊戲庫的遊戲排在最前

沒有日期或評分的遊戲排在最後。清除會保留你選擇的排序。

字母導航

跳轉到以特定字母開頭的遊戲。沒有匹配遊戲的字母會顯示為灰色。數字和符號歸入 # 之下。按名稱排序時可使用字母列，按其他方式排序時它會顯示為灰色。

無限滾動

遊戲會在你滾動時以每批 100 個的方式載入。當你接近底部時會自動載入新頁面。更改篩選器或搜尋會立即重置並重新載入結果。

狀態保持

你當前的篩選器、搜尋詞、排序和滾動位置會儲存在會話存儲中。當你返回該頁面或重新整理時會被恢復。

遊戲詳情

遊戲詳情彈窗

點擊任意遊戲卡片會打開一個帶緩存快速視圖的詳情彈窗。該彈窗顯示：

  • 封面（2D 和 3D）、同人圖背景
  • 簡介和發行資訊
  • 開發商、發行商、類型徽章
  • 玩家人數、遊玩模式、遊戲結構
  • 年齡分級圖片（來自你偏好的系統，帶交叉映射回退）
  • 帶鍵盤導航的螢幕截圖畫廊（← →）
  • 預告影片（若有）
  • HLTB 遊玩時長估算（主線、主線 + 額外內容、完美通關）
  • RetroAchievements 狀態和進度
  • 相似遊戲（可點擊的連結）
  • 手把支援詳情
  • 分配給遊戲的標籤
  • 檔案大小和 ROM 路徑

完整遊戲詳情頁

點擊遊戲標題連結或從麵包屑導航進入，即可查看完整遊戲詳情頁。完整頁面上的附加功能包括：

  • 同人圖背景頁頭，帶麵包屑導航
  • 遊戲標誌 — 遊戲的標誌顯示在標題上方，標題仍以文字顯示。沒有封面的遊戲會在封面的位置顯示其標誌。抓取會從 ES-DE、ScreenScraper、TheGamesDB、IGDB 和 Steam 填充標誌；使用填充缺失項的批次抓取會為之前抓取過的遊戲填充標誌
  • 盒子背面 — 當遊戲有盒子背面時，封面上會有一個背面按鈕。按下它可查看背面，按正面可返回。點擊背面可放大。每次抓取遊戲時，都會從 ES-DE、ScreenScraper 和 TheGamesDB 填充背面
  • 平台匯入徽章 — 適用時顯示 CLZ 匯入、Steam 匯入、Xbox 匯入或 PSN 匯入，並帶平台標誌
  • 附贈光碟指示 — 顯示徽章和帶縮圖的 "所屬：" 連結，指向父遊戲
  • 刪除按鈕 — 從資料庫中移除該遊戲（需確認）
  • 清除按鈕 — 清除所有抓取的中繼資料，同時保留 ROM 條目

編輯彈窗

點擊 編輯（或按 e）打開編輯彈窗，其分為以下幾個部分：

  • 身分 — 標題、排序標題（自動生成但可編輯）、系列、版本
  • 發行資訊 — 發行日期、地區（來自可配置的下拉選單）
  • 玩法 — 類型（多選標籤）、模式、遊戲結構、玩家人數、開發商、發行商
  • 技術資訊 — 手把（多選）、存檔類型、視角（多值）、維度（多值）
  • 年齡分級 — 全部分級系統，帶官方分級圖片和自動交叉映射。更改一個分級會自動填充其他系統中空的分級。
  • 評分 — 媒體評分、使用者評分
  • 簡介 — 遊戲簡介文字
  • 自訂圖片 — 上傳自訂封面（2D）、3D 封面、盒子背面、同人圖和標誌。清除現有圖片以允許重新抓取。
  • 匯入 3D 包裝盒 — 也在「自訂圖片」中。無需按「儲存變更」，會立即儲存。選擇 Slipcase 儲存的 .box.json 檔案以及它的圖片（選擇整個資料夾也可以）。Slipcase 1.4.0 或更新版本會在每張匯出的圖片旁儲存此檔案。RetroDB 會為這個遊戲保存包裝盒的各面；之後點擊封面就會以 3D 顯示包裝盒，可以拖曳或用方向鍵轉動。你的 3D 封面圖片不會被改動。已經有各面圖片的遊戲會在取代前先詢問，移除會刪除它們。
  • 影片 / 預告片 — 上傳或連結影片預告

對比遊戲

功能說明

在表格檢視中並排比較兩款遊戲的中繼資料。可用於檢查中繼資料品質、發現重複項，或比較同一遊戲在不同系統上的版本。

  2. 搜尋並選擇第一款遊戲
  3. 搜尋並選擇第二款遊戲
  4. 查看比較表格 — 差異會被醒目標示

比較的欄位

系統、開發商、發行商、發行日期、類型、系列、地區、玩家人數、模式、視角、維度、全部年齡分級、使用者評分、媒體評分、遊玩時長估算、手把支援、存檔類型、檔案大小、相似遊戲、簡介等。

合集（標籤、列表、願望單）

標籤

建立自訂顏色的標籤來整理你的遊戲。標籤的作用類似於標記 — 每款遊戲可擁有多個標籤，每個標籤也可包含多款遊戲。

  • 在標籤頁面建立帶有自訂名稱和顏色的標籤
  • 透過遊戲詳情彈窗為遊戲分配標籤
  • 點擊任意標籤即可瀏覽帶有該標籤的所有遊戲
  • 在標籤管理頁面編輯或刪除標籤

命名列表

建立可自訂排序的精選遊戲列表。列表類似於播放列表 — 你可以精確控制遊戲的順序。

  • 在列表頁面建立帶有名稱、描述和圖示的列表
  • 透過遊戲詳情彈窗或列表頁面將遊戲加入到列表
  • 拖放以重新排列列表中的遊戲
  • 按自訂順序或字母順序排序

願望單

追蹤你想要獲取的遊戲，無論是實體版還是數位版。

  • 手動加入遊戲，包含標題、系統、備註和優先級（1–5）
  • 願望單項目可在找到時連結到現有遊戲庫中的遊戲
  • 按優先級（從高到低）排序，然後按加入日期排序
提示：標籤適用於跨類別的標記（例如「收藏」「沙發合作」「待玩清單」），而列表適用於特定的精選合集（例如「十大 SNES 遊戲」「待直播遊戲」）。

遊戲匯入

從外部來源匯入遊戲合集。透過側邊欄中的遊戲匯入存取。所有匯入類型都整合到一個帶標籤頁的頁面中。

CLZ Games 匯入

從 CLZ Games 匯入你的實體遊戲收藏。

  1. 將你的 CLZ Games 收藏匯出為 PDF
  2. 進入遊戲匯入 → CLZ 標籤頁
  3. 上傳 PDF 檔案
  4. 查看解析出的遊戲
  5. 選擇要匯入的遊戲

CLZ 匯入與 ROM 遊戲分開追蹤（使用 clz_import/ 前綴），讓你可以同時編目實體和數位收藏。CLZ 匯入可從設定 → 系統 → 維護中完全清除。

Steam 匯入

匯入你的 Steam 遊戲庫並追蹤成就。

  1. 在設定中配置你的 Steam Web API 金鑰和 Steam ID
  2. 進入遊戲匯入 → Steam 標籤頁
  3. 點擊「取得遊戲庫」以檢索你的 Steam 遊戲
  4. 選擇要匯入的遊戲。已在你的 Windows 清單中、名稱相同的遊戲會連結到 Steam，而不會重複新增
  5. 匯入的遊戲會標記其 Steam App ID 以便追蹤成就
  6. 每個遊戲會在背景從其 Steam 商店頁面填充空白的詳細資訊，你的成就和遊玩時間也會隨之同步。遊戲頁面會顯示你的遊玩時間。請抓取該遊戲以取得其類型和發行日期：Steam 的類型過於寬泛，日期則是遊戲登上 Steam 的日期

Xbox 匯入

使用你自己的 OpenXBL 金鑰，匯入你玩過的 Xbox 遊戲。

  1. 在 設定 → 我的資料 → Xbox 中儲存你的 OpenXBL 金鑰（見上文「API 金鑰」）
  2. 進入遊戲匯入 → Xbox 標籤頁，點擊取得遊戲庫
  3. 選擇要匯入的遊戲，並偵測重複項。應用程式和僅限手機的遊戲會被排除。
  4. 匯入的遊戲會標記其 Xbox Title ID 以便追蹤成就

PSN 匯入

匯入你的 PlayStation Network 遊戲庫。

  1. 進入遊戲匯入 → PSN 標籤頁
  2. 輸入你的 NPSSO cookie（獲取方法請參閱 獎盃 → PSN 身分驗證）
  3. 點擊「取得遊戲庫」以檢索你的 PSN 遊戲
  4. 選擇要匯入的遊戲

匯入之後

  • 匯入的遊戲會帶著平台專屬的徽章出現在你的遊戲庫中
  • 使用批次抓取為匯入的遊戲獲取中繼資料
  • 成就/獎盃追蹤會自動連結到來源平台
  • 在遊戲庫中可使用來源篩選器篩選匯入的遊戲
提示：從任意平台匯入遊戲後，你可以像 ROM 遊戲一樣使用批次抓取為它們抓取中繼資料。匯入的遊戲也可以追蹤各自平台的成就。

RetroAchievements

設定

  1. 在 retroachievements.org 建立帳戶
  2. 在你的個人資料設定中產生 API 金鑰
  3. 在設定 → 帳戶 → RetroAchievements 中輸入你的使用者名稱和 API 金鑰

要在 RetroDB 的 RetroArch、DuckStation 或 PCSX2 中遊玩時贏取成就，請在同一頁面的在 RetroArch、DuckStation 和 PCSX2 中贏取成就下輸入一次你的 RetroAchievements 密碼。密碼只傳送給 RetroAchievements，不會被保留；RetroDB 儲存其傳回的登入權杖，每個 RetroDB 使用者一個。如有需要，可在此勾選硬核模式。如果成就無法再登入（例如你在 RetroAchievements 網站上重設了密鑰之後），請登出後重新登入。當你在 DuckStation 或 PCSX2 中按下「遊玩」時，RetroDB 會把你的登入資訊寫入該模擬器自己的設定檔，並一直保留到你登出或其他 RetroDB 使用者開始遊玩。你在模擬器自身選單中完成的登入不會被改動。RetroDB 無法在 Mac 上讓 DuckStation 登入。

成就頁面

  • 系統標籤頁 — 按平台瀏覽成就（會記住你上次查看的標籤頁）

  3. 在成就的RPCS3分頁中檢視獎盃清單與各個獎盃的詳細資訊

RPCS3 會從你的 RPCS3 使用者目錄讀取獎盃 XML 資料，並自動將遊戲與你的遊戲庫匹配。

PSN API 獎盃

從你的 PSN 帳戶同步 PlayStation Network 獎盃資料。

  1. 獲取你的 NPSSO cookie（見下文）
  2. 在設定 → 帳戶 → PSN中輸入它
  3. 你的 PSN 獎盃庫會透過 PlayStation API 獲取
  4. 查看每款遊戲的獎盃進度，附已獲得/總計數量
  5. 各個獎盃詳情包括描述、稀有度和解鎖時間戳

PSN 身分驗證（NPSSO Cookie）

PSN 使用一種稱為 NPSSO 權杖的特殊身分驗證 cookie。獲取方法如下：

  1. 打開網頁瀏覽器並登入 store.playstation.com
  2. 登入後，導航至：https://ca.account.sony.com/api/v1/ssocookie
  3. 該頁面會顯示包含你的 NPSSO 權杖的 JSON
  4. 複製 npsso 值並貼上到設定 → 帳戶 → PSN

身分驗證完成後，RetroDB 會將存取權杖安全地快取在自己的資料庫中（按使用者），並自動重新整理它們 — 你無需在每次同步時重新貼上 NPSSO。當 Sony 的工作階段結束時，RetroDB 會使用你儲存的 NPSSO 自動重新登入。只有當 Sony 拒絕已儲存的 NPSSO 時，你才需要新的 NPSSO；屆時 設定 → 帳戶 和儀表板會提示你。

獎盃詳情

  • 獎盃類型：銅杯、銀杯、金杯、白金杯

  • 每款遊戲的完成百分比
  • 每個已獲得獎盃的解鎖時間戳

ROM 報告

功能說明

根據標準命名規範驗證 ROM 檔案名並識別潛在問題。從側邊欄的ROM 工具開啟，然後選擇ROM 報告分頁。

報告類型

標籤頁檢查內容
非標準名稱檔案名不符合命名規範的 ROM。顯示當前檔案名、偵測到的問題，以及建議的更正名稱。
名稱不符檔案名與抓取的中繼資料標題不匹配的 ROM。顯示當前檔案名與抓取的標題、地區、年份和開發商。

  • 缺失的年份標籤
  • 檔案名與資料庫標題不匹配

ROM 工具

從側邊欄進入 ROM 工具中心。每個工具都作為後台任務執行，支援即時進度更新、暫停/恢復以及日誌記錄。

壓縮檔掃描器

解壓 ROM 壓縮包（ZIP、7Z、RAR），可選項包括：

  • 遞迴掃描子資料夾
  • 解壓後刪除不需要的檔案
  • 為多光碟遊戲自動生成 M3U 播放列表

需要：7z 或 unzip

將光碟鏡像（ISO、BIN/CUE、GDI）轉換為壓縮的 CHD 格式。在保持與模擬器完全相容的同時大幅節省儲存空間。

需要：chdman（來自 mame-tools）

CHD 校驗

透過雜湊驗證檢查 CHD 檔案的完整性。識別損壞或不完整的轉換結果。

需要：chdman

重複查找器

按雜湊或檔案名查找重複的 ROM，並可選擇按地區標籤設定優先級。 在檔名模式下，同一遊戲已連結的地區版本不會被回報為重複項；在雜湊模式下，相同的檔案一律會被回報。

無外部依賴

地區版本

僅限編輯者。RetroDB 會推薦看起來是同一遊戲不同地區版本的遊戲：同一個 IGDB 或 ScreenScraper 遊戲、僅地區標籤不同的同名遊戲，或相符的地區名稱。取消勾選不屬於該組的遊戲，然後點擊 「連結已勾選的遊戲」；或點擊 「非版本」，該組將不再被推薦。在你確認之前，不會連結任何內容。請先在維護中執行 回填別名標題：它會填入推薦所用的 IGDB 和 ScreenScraper ID。

無外部依賴

MAME 命名

僅限管理員。MAME 透過精確的檔名尋找遊戲，所以請保留短名稱，例如 dyger.zip。選擇 MAME 的清單（與你的 ROM 相符的 DAT，或 mame -listxml 的輸出），然後按「為 MAME 遊戲命名」。每個遊戲都會獲得其真實名稱、年份和廠商，檔案則保持不變。你自己更改過的標題會被保留。加入 catver.ini 可依類別篩選清單。BIOS 集會在清單中隱藏，但仍保留在磁碟上，因為其他遊戲需要它們。之後請進行抓取，以便抓取器能找到每個遊戲。

需要：一個 MAME 清單檔案

僅限編輯者。對整個系統執行 AI 填充，填充你開啟的欄位（參見 AI 填充 → 一次處理多個遊戲）。

需要：設定 → 抓取 中的 AI 提供者

多光碟整理器

在你的遊戲庫中查找並刪除重複的螢幕截圖，以釋放儲存空間。

  • 精確雜湊（MD5） — 僅識別完全相同的檔案
  • 視覺相似度 — 感知雜湊比較，閾值可配置（1–20，數值越低匹配越嚴格）

漸進式掃描並即時顯示統計資訊，包括已掃描遊戲數、重複數量和可回收空間。結果按遊戲和系統分組。你可以在每個重複組中選擇保留哪個檔案，或使用 “保留最大的” 自動保留解析度最高的版本。如果你在掃描期間或掃描後離開此頁面，返回時結果仍會保留，直到掃描結束後 30 分鐘為止，除非 RetroDB 重新啟動。其他會掃描或轉換的 ROM 工具頁面也是如此。

圖片尺寸調整

無外部依賴（基於 Python 的 AI 放大）

回填別名標題

遍歷每個已抓取的遊戲，從 IGDB / TGDB / ScreenScraper 取得其備用標題，並標註每個名稱所屬的地區。你已有的名稱也會獲得其地區。在匯入大型目錄，或從另一款不儲存地區/日文/副標題的工具遷移後特別有用。在後台執行，進度顯示在工具卡片上。

至少需要一個抓取源 API 金鑰（IGDB / TGDB / ScreenScraper）

修復包裝盒與說明書地區

舊版 ScreenScraper 抓取會從按字母排序的地區清單中取第一個包裝盒、3D 包裝盒和說明書，因此美國版遊戲可能顯示歐洲版包裝盒，或帶有葡萄牙語說明書。此工具會重新查詢每個這類遊戲。如果其他地區更適合該遊戲，它會下載該檔案並刪除舊檔案。來自其他地區的包裝盒和說明書不會被改動，檔案已經合適的遊戲也一樣。點擊卡片會開啟此工具的頁面。在該頁面中，暫停、繼續和停止可控制執行，而What changed會列出每個已替換檔案的遊戲，並顯示其目前的包裝盒以及每個新檔案來自的地區。之後再次執行時會繼續處理其餘部分。

需要 ScreenScraper 帳號。會消耗你的 ScreenScraper 每日額度

依檔名修復地區

ROM 的檔名說明了它是哪個版本，因此 (USA) 這樣的標記現在會決定其地區，不再詢問 AI。舊版抓取讓 AI 先猜測，因此 (USA) 檔案可能被標為日本。此工具會把這些遊戲的地區改為檔名中的地區。它只更改由 AI 填寫的地區，包括你之後手動修正、與檔名不同的地區。

整理類型、視角與模式

各來源對同一事物的叫法不同，因此一個類型可能同時顯示為 RPG 和 Role Playing Game，篩選器就會漏掉遊戲。現在抓取使用同一套名稱，即篩選清單中的名稱。此工具會轉換舊版抓取儲存的內容。在這些清單中沒有位置的詞（如 Arcade 或 Indie）會被刪除。屬於其他欄位的詞（如 FPV）會在該欄位為空時移到那裡。與遊戲模式矛盾的玩家人數會被修正，來自 RAWG 的舊玩家人數 1 會被清除，以便填入真實人數。你自己加入下拉選單中的值會保留。之後請使用填充缺失項執行一次批次抓取，以填充仍為空的內容。

標準化

它的作用

將類型和遊戲模式的值標準化為統一的標準形式。此過程在抓取和 AI 填充時自動進行，也可以手動應用到你現有的遊戲庫。

為何重要

不同的抓取源對同一事物使用不同的名稱。標準化可確保整個遊戲庫的一致性：

  • platform → Platformer
  • fps, first person shooter → First-Person-Shooter
  • shoot 'em up, shmup → Shoot-em-up
  • beat 'em up, brawler → Beat-em-up
  • hack and slash → Hack-n-Slash
  • rts, real time strategy → Real-Time Strategy
  • board game, card game → Board-Card

自訂規則

你可以在 設定 → 資料 → 標準化 中添加自訂標準化規則。自訂規則會覆蓋內建映射，讓你定義自己偏好的類型和模式名稱。規則儲存在資料庫中。

預覽與應用

在應用標準化之前，你可以預覽哪些遊戲會受到影響以及將做出哪些更改。這讓你可以在向遊戲庫提交更改之前進行審核。

名稱的兩種寫法

系列、發行商和開發商按鈕會列出大小寫不同的名稱，例如 Doom 和 DOOM。系統會選用遊戲最多的寫法；如果你喜歡別的，可以另選，然後按套用。之後的抓取或 AI 填充若帶來大小寫不同的名稱，會採用你遊戲庫中的寫法。

在發行商和開發商下，可能是同一家公司的名稱會列出 Eidos 和 Eidos Interactive 這樣的名稱。預設不勾選任何項目，因為相似的名稱可能是不同的公司：Atari Games 和 Atari, Inc. 就是兩家。在某一列中，選出要保留的名稱，勾選屬於同一家公司的名稱，然後按合併。被勾選的名稱在發行商和開發商中都會改為保留的那個，之後的抓取或 AI 填充若帶來已合併的名稱，會採用保留的那個。

圖片標準化

它的作用

將所有遊戲媒體標準化為統一的目標尺寸，讓整個遊戲庫保持統一的外觀。尺寸在目標值 80–120% 範圍內的圖片會被略過。

工作原理

  • 放大 — 小於目標尺寸的圖片會使用 Real-ESRGAN x4（透過 ONNX Runtime 的 AI 超解析度）進行高品質放大，然後調整為精確的目標尺寸
  • 縮小 — 大於目標尺寸的圖片會使用 Lanczos 濾波進行縮小，以獲得清晰的效果
  • 閾值區間 — 處於目標值 80–120% 範圍內的圖片會保持不變，以避免不必要的重複處理

目標尺寸

媒體類型目標方法
封面高 1080px寬度按比例縮放
3D 封面高 1080px寬度按比例縮放（保留透明度）
螢幕截圖高 1080px寬度按比例縮放
手把最長邊 1280px保留透明度（RGBA）
硬件最長邊 1280px保留透明度（RGBA）
同人圖已略過不進行標準化（保持原始尺寸）
標誌已略過保持原始尺寸；保留其透明背景（格式為 JPEG 時儲存為 PNG）

如何執行

  1. 前往 設定 → 系統 → 維護 或 ROM 工具 → 圖片尺寸調整
  2. 點擊 “開始” 以啟動批量標準化
  3. 任務在後台執行，透過彈出通知顯示當前檔案和統計資訊
  4. 圖片在抓取過程中也會自動標準化（新下載的內容會立即標準化）

硬件支援

Real-ESRGAN 模型會自動偵測你的硬件並使用可用的最佳提供程序：

  • CUDA — NVIDIA GPU 加速
  • ROCm — AMD GPU 加速（針對 RX 6000 系列自動覆蓋 gfx 版本）
  • CoreML — Apple Silicon 加速
  • CPU — 無 GPU 支援的系統的後備方案

ONNX 模型檔案會在首次使用時從 Hugging Face 自動下載並快取到本地。

掃描沒有找到新遊戲，或缺少某個系統

  • 每個系統資料夾都需要一個 ES-DE 的 systeminfo.txt，其中列出該系統的副檔名。沒有它的資料夾會被略過；日誌檢視器會為它顯示 No extensions found。PS3 資料夾不需要它。

抓取

"No results found. Try a different search term."

  • 在搜尋框中縮短標題，或試試英文名稱。
  • 確認資料來源已開啟，並在 設定 → 抓取 → 抓取器 中顯示線上。
  • 已達到上限的資料來源在它給出的時間之前不會回傳任何結果（見下文）。

資料或圖片屬於另一個遊戲

  • 批次抓取是依 ROM 的檔名搜尋，所以命名不當的檔案會找到錯誤的遊戲。請重新命名檔案，或在該遊戲自己的頁面用更好的搜尋標題抓取，並選擇正確的結果。

抓取只會填入空白的圖片，螢幕截圖只會新增。請先在「編輯遊戲」視窗中刪除該圖片，再重新抓取。批次完整重新抓取會取代圖片，除非勾選了保留現有媒體。你刪除過的螢幕截圖不會再次被加入。

「… 表示已達到使用上限」或「… 拒絕了 API 金鑰」

RetroDB 會在訊息中給出的時間之前停止向該服務發出請求。如果金鑰被拒絕：請在 設定 → 抓取 → API 金鑰 中更正，然後按下儲存 API 金鑰；儲存也會立即解除所有這類暫停。重新啟動同樣會解除。

資料來源顯示的是原因，而不是「線上」

原因會指出問題，例如 "No API key" 或 "Invalid API key"。在 設定 → 抓取 → API 金鑰（僅限管理員）中輸入或更正金鑰，然後按下儲存 API 金鑰。已儲存的金鑰會顯示為星號；不要動輸入框就能保留它，或者清空後輸入新金鑰。

批次抓取

批次抓取卡住

在「批次抓取」視窗中按下取消；點選進度通知即可開啟該視窗。正在抓取的遊戲會先完成。如果仍在執行，請見任務似乎卡住了。

大多數遊戲顯示「已略過」

  • 填充缺失項會略過最近 24 小時內已由批次抓取完成的遊戲。
  • 抓取後沒有發現任何新內容的遊戲也算作已略過。
  • 若要立即重新抓取它們，請使用完整重新抓取；勾選保留現有媒體可保留你的圖片。

很多遊戲顯示「失敗」

「失敗」通常表示沒有夠接近的結果可以儲存。請在 設定 → 抓取 → 抓取器 → 批次抓取比對篩選 中選擇寬鬆，並檢查檔名。日誌檢視器會列出每個沒有找到比對結果的遊戲。

「… 的抓取已在執行」

該系統已在以相同模式抓取。請等它完成，或取消它。另一個系統的抓取會排隊等待，並自動開始。

AI 填充

「AI 未返回任何資料。請檢查您的 API 金鑰和供應商設定。」

在 設定 → 抓取 → API 金鑰 中選擇AI 中繼資料供應商，輸入它的金鑰，按下儲存 API 金鑰，然後按下測試已儲存的 AI 金鑰。如果 AI 服務拒絕了請求，訊息會改為說明原因，例如額度用完。

「AI 找不到需要填充的缺漏欄位」

這不是錯誤：這個遊戲沒有空白欄位可供 AI 填充。

批次 AI 填充自行停止了

連續三個遊戲都沒有得到回答時它就會停止。請用測試已儲存的 AI 金鑰檢查金鑰，然後再執行一次。已經填充的遊戲會保留得到的內容。

圖片

抓取後圖片遺失

下載失敗的圖片會被默默略過；日誌檢視器會說明原因。請確認 RetroDB 可以寫入它的媒體資料夾（除非你移動過，否則是 static/images/）。在 Linux 或 macOS 上，chmod -R u+rwX static/images/ 會給你的帳戶寫入權限，同時不會把圖片標示為程式。

放大似乎沒有作用

  • 第一次放大會下載 Real-ESRGAN 模型，所以需要連上網路。
  • GPU 需要可用的驅動程式（NVIDIA 用 CUDA，AMD 用 ROCm）。如果 GPU 失敗，放大會改用 CPU。
  • 如果放大器完全無法執行，RetroDB 會改用一般方式（Lanczos）放大圖片。logs/upscale_worker.log 會說明原因。

玩遊戲

遊戲在另一台電腦上開啟

遊玩會在執行 RetroDB 的電腦上啟動模擬器，而不是在你按下按鈕的裝置上。

「在 PATH 中找不到模擬器程式」

在「模擬器」頁面的已登錄的模擬器下，編輯該模擬器，並在程式位置中填入程式所在的位置。或者把存放它的資料夾加到模擬器資料夾。對於 RetroArch，請在 RetroArch 卡片上按下自動偵測，然後按下儲存空間。

「系統 … 未設定模擬器」或「模擬器 … 已關閉」

在「模擬器」頁面的各系統對應下為該系統選擇模擬器，或在已登錄的模擬器下開啟該模擬器。如果某個遊戲指定的模擬器已不存在：請在它的「編輯遊戲」視窗中清除該選擇。

「… 沒有為它設定 RetroArch 核心」或「找不到 RetroArch 核心」

在「模擬器」頁面檢查 RetroArch 卡片是否指向存放你的核心的資料夾（自動偵測會自動填入），然後按下儲存。用 RetroArch 內建的核心下載器安裝缺少的核心。或者在各系統對應下為該系統選擇另一個模擬器。

「未找到 ROM 檔案」或「ROM 路徑在已設定的掃描資料夾之外」

該檔案在上次掃描後被移動或刪除了，或者位於你的 ROM 資料夾之外。請把它放回系統資料夾，然後再次掃描遊戲庫。

「該遊戲已在執行中」

關閉模擬器視窗，或接受關閉它並重新開始的提示。

「無法下載 … 核心」

在 RetroDB 中第一次遊玩時會下載缺少的核心，除非在「模擬器」頁面關閉了按下「遊玩」時下載缺少的核心。請檢查網路連線後再按一次「遊玩」，或在「模擬器」頁面按下為我的系統安裝核心。

金手指

「找不到這個遊戲的金手指。」

在「模擬器」頁面的「金手指」卡片中下載該模擬器的金手指包，或在那裡匯入你自己的金手指資料夾。金手指可用於播放器、DuckStation、PCSX2 和 MAME。對於 MAME，請從 mamecheat.co.uk 匯入金手指合集。

已開啟的金手指沒有任何效果

金手指會在你下次按下「遊玩」時生效。開啟的金手指會在你遊玩期間關閉 RetroAchievements 硬核模式。

「請先執行一次 … 以產生其設定，然後再次遊玩。」

DuckStation 或 PCSX2 還沒有建立它的設定資料夾。請單獨啟動一次該模擬器，然後再按一次「遊玩」。

成就與獎盃

RetroAchievements 同步卡住或在等待

RetroAchievements 同一時間只執行一個任務；其餘的在進度通知中排隊等待。通知上的停止按鈕會結束正在執行的任務，每個等待中的任務都有一個從佇列移除按鈕。

「未配置 RetroAchievements」

在 設定 → 帳戶 → 我的資料 → RetroAchievements 設定 中儲存你的 RetroAchievements 使用者名稱和網頁 API 金鑰。

「RetroAchievements 未能讓你登入」

為了遊玩而登入需要你的 RetroAchievements 密碼，而不是 API 金鑰。它會在你下次按下「遊玩」時生效。

「未找到遊戲。請檢查您的 Steam 個人資料和遊戲詳情是否設定為公開。」

在 Steam 網站上，把你的個人資料及其遊戲詳情設為公開。你的 Steam 金鑰和 17 位數的 Steam ID 填在 設定 → 帳戶 → 我的資料 → Steam 中。

「OpenXBL 不接受此金鑰」

  • 從 xbl.io 重新複製金鑰，並貼到 設定 → 帳戶 → 我的資料 → Xbox 中。
  • 「已達到 OpenXBL 每小時的請求上限」表示該金鑰已用完這個小時的 150 次請求。請稍後再同步；會先從尚未同步的遊戲開始。

「PSN 驗證失敗」

  • Sony 不再接受你儲存的 NPSSO 權杖。請依 設定 → 帳戶 → 我的資料 → PlayStation Network 中的步驟取得新的，然後按下儲存我的資料。
  • 只要 Sony 接受權杖，RetroDB 會自行維持登入。若要更換仍然有效的權杖，請先登出 PlayStation。

PSN 獎盃同步卡住

PSN 重新整理在進度通知中有停止按鈕。完整的獎盃同步沒有；重新啟動 RetroDB 會結束它。

收藏家獎盃全部顯示為未獲得

在「收藏家獎盃」頁面按下重新整理進度。開啟頁面本身不會進行統計。

「未找到 … 的 HLTB 匹配結果」

在搜尋框中輸入 HowLongToBeat 使用的標題，再查詢一次。如果 HowLongToBeat 提示請求過多，RetroDB 會等 15 分鐘再詢問，在此之前查詢不會找到任何結果。

博物館與 ROM 工具

「未配置 AI 提供方」

博物館使用 設定 → 抓取 → API 金鑰 中設定的 AI 供應商來撰寫頁面。請先設定一個，然後再次產生。

博物館產生卡住

按下「博物館」頁面進度條下方的取消。

「未找到 chdman。請安裝 MAME 工具。」

請安裝 MAME 工具（其中包含 chdman），或在 ROM 工具 → 設定 中設定它的位置。

「這些掃描結果已過期。請重新掃描後再刪除。」

重新執行掃描，然後從新的結果中刪除。

帳戶與登入

「登入嘗試次數過多，請稍後再試。」

五分鐘內輸錯五次密碼後，請等五分鐘再試。

忘記密碼

無法透過電子郵件重設。管理員可在 設定 → 帳戶 → 使用者管理 中設定新密碼。如果唯一的管理員忘了密碼，請還原一份在知道密碼時做的備份。

"你沒有執行此操作的權限"

你的角色不包含該功能。管理員可以在 設定 → 帳戶 → 使用者管理 中更改你的角色。

資料庫、備份與更新

資料庫錯誤

  1. 如果可能，先建立備份（設定 → 遊戲庫 → 備份）
  2. 試試 設定 → 系統 → 維護 → 最佳化資料庫。任務正在寫入時它可能失敗；請等任務完成後再試。
  3. 檢查 database/ 目錄的檔案權限
  4. 最後手段：從備份還原

「有背景任務正在執行。請等待其完成後再還原。」

讓任務完成，或在它的進度通知中停止它，然後再還原。還原之後，請重新啟動 RetroDB。

「這份 RetroDB 是 git 簽出副本。請用 git pull 更新。」

更新程式只能安裝到下載的發行版本上。用 git 取得的副本請用 git pull 更新。

更新失敗

下載失敗不會安裝任何東西；請再按一次下載更新。安裝失敗會自動還原舊版本，並說明原因。詳細資訊在 logs/update.log 中。

頁面與速度

頁面緩慢或沒有回應

  • 大型合集可能需要時間載入 — 無限滾動以每批 100 個的方式載入
  • 試著重新整理頁面以清除累積的記憶體
  • 檢查瀏覽器控制台是否有 JavaScript 錯誤
  • 試著切換到畫布效果更輕量的主題（例如 Amber 或 Elite）
  • 畫布效果會自動偵測硬體；低端設備會以降低的幀率使用 CPU 備援方案

效能提示

  • 保持瀏覽器為最新版本以獲得最佳效能
  • 處理超大型合集時關閉其他瀏覽器標籤頁
  • 使用系統篩選器以減少一次顯示的遊戲數量
  • 在大量操作（抓取、清理、匯入）後定期執行最佳化資料庫

安全與免責聲明

安全最佳實踐

  • 更改預設密碼 — 預設的管理員密碼（admin）應在首次登入時立即更改。請使用至少 12 個字符的強密碼。
  • 使用 HTTPS 反向代理 — RetroDB 本身不提供 TLS/SSL。請將其置於反向代理（例如 Nginx、Caddy、Traefik）之後並啟用 HTTPS，以加密客戶端與伺服器之間的流量。
  • 限制網路存取 — 避免將 RetroDB 直接暴露到公共互聯網。請使用 VPN 或將存取限制在你的本地網路內。如果需要遠端存取，請使用帶身份驗證的反向代理。
  • 保持定期備份 — 使用設定中內建的備份功能定期創建資料庫備份。將備份存放在與應用程式不同的位置。
  • 保持 RetroDB 更新 — 定期檢查新版本。更新中包含安全修復和改進。
  • 保護你的 API 金鑰 — API 金鑰儲存在 data/scraper_settings.json 中。請確保該檔案不會被公開存取。切勿分享你的 config.py 或令牌檔案。

內建安全功能

  • 密碼雜湊 — 密碼使用 PBKDF2 進行雜湊處理（絕不以明文儲存）
  • 登入速率限制 — 對登入端點的暴力破解防護
  • 路徑驗證 — 所有檔案操作都使用 safe_path 和 safe_filename 輔助函數以防止目錄遍歷攻擊
  • 參數化查詢 — 所有資料庫查詢都使用參數化語句以防止 SQL 注入
  • XSS 防護 — 模態對話框使用安全的 DOM 構造；使用者輸入會被轉義
  • 圖片解壓炸彈防護 — 圖片的最大像素數受到限制，以防止惡意圖片耗盡記憶體
