インストール

システム要件

  • Python 3.8 以上（pip 付き）
  • Web ブラウザ（Chrome、Firefox、Safari、Edge）
  • オペレーティングシステム: Linux、Windows 10/11、または macOS

クイックインストール

  1. RetroDB の ZIP を任意のディレクトリに展開します
  2. そのディレクトリでターミナル／コマンドプロンプトを開きます
  3. 次を実行します: python install.py
  4. サーバーを起動します:
    • Linux: ./start.sh
    • Windows: start.bat をダブルクリック
    • macOS: start.command をダブルクリック
  5. ブラウザで http://localhost:5000 を開きます

GUI インストーラー

Linux では ./setup.sh を実行してグラフィカルなインストールウィザードを起動することもできます。Python／pip／tkinter の有無を自動でチェックし、視覚的な進捗ログとともに各セットアップ手順をガイドします。

install.py が行う処理

  • Python 3.8 以上と pip が利用可能か確認します
  • requirements.txt から Python の依存関係をインストールします
  • サンプルテンプレートから config.py を作成します
  • 必要なディレクトリ（データベース、ログ、メディアフォルダー）を作成します
  • CSS と JS のバンドルをビルドします

はじめに

初回セットアップ

初回起動時、RetroDB は次の手順をガイドするセットアップウィザードを表示します:

  1. 管理者アカウント — ユーザー名とパスワードを作成します
  2. ライブラリパス — ROM ディレクトリを設定します
  3. ES-DE 連携 — 任意で ES-DE のゲームリストとメディアをリンクします
  4. API キー — 任意でスクレイパーの API キーを追加します

ウィザードを完了したら、ダッシュボードで「ライブラリをスキャン」をクリックして ROM を検出します。

クイックスタートの流れ

  1. ライブラリをスキャンして ROM をインポートします
  2. システムごとにブラウズするか、ライブラリですべてのゲームを表示します
  3. メタデータを個別に、または一括スクレイプでスクレイプします
  4. タグ、リスト、ウィッシュリストで整理します
  5. クリア状況や実績で進捗をトラッキングします

ROM ライブラリの構造

RetroDB はライブラリパス内のシステムフォルダーに ROM が整理されていることを前提とします:

ROM Library/
  nes/
    Super Mario Bros. (USA).nes
  snes/
    Chrono Trigger (USA).sfc
  psx/
    Final Fantasy VII (USA)/
      Final Fantasy VII (USA) (Disc 1).chd
      Final Fantasy VII (USA) (Disc 2).chd

各システムフォルダーには、サポートするファイル拡張子を定義した ES-DE の systeminfo.txt ファイルが必要です。RetroDB はスキャン時にこれを読み込み、各システムでどのファイルが有効な ROM かを判別します。

ヒント: すでに ES-DE でスクレイプ済みの場合、RetroDB はそのデータをインポートできます！ ES-DE のパスは「設定 → ES-DE 連携」で、またはセットアップウィザード中に設定します。

プラットフォーム別の注意

Linux

  • Ubuntu、Fedora、openSUSE、Arch Linux でテスト済みです
  • ROM ツールには次が必要です: sudo apt install p7zip-full unrar mame-tools（Debian/Ubuntu）またはお使いのディストリビューションの同等品
  • システム Python を使用する場合、インストーラーが --break-system-packages を自動で処理します
  • AMD GPU 向けに ROCm による GPU アクセラレーションをサポートします（Real-ESRGAN による画像アップスケーリング）

Windows

  • python.org から Python をダウンロードします（インストール時に「Add to PATH」をチェック）
  • ROM ツール: 7-Zip、WinRAR、MAME（chdman 用）をインストールします
  • start.bat で起動するか、コマンドプロンプトから python app.py を実行します

macOS

  • Python 3 は Homebrew でインストールできます: brew install python3
  • ROM ツール: brew install p7zip unrar rom-tools
  • Finder で start.command をダブルクリックして起動します
  • Apple Silicon 向けに CoreML アクセラレーションをサポートします（Real-ESRGAN による画像アップスケーリング）

仕組み

  • テーマは CSS のカラー変数を上書きし、すべての UI 要素が自動的に適応します
  • キャンバスエフェクトはハードウェアの性能ティア（高／中／低）を自動検出し、利用可能なときは GPU アクセラレーションを、低スペックデバイスでは CPU フォールバックを使用します
  • タブが非表示のときはエフェクトを一時停止してリソースを節約します
  • Cyberpunk の煙の状態はページ遷移をまたいで保持され、シームレスな遷移を実現します
  • 控えめな CRT 風スキャンライン（走査線）のオーバーレイは各テーマのカラーパレットに適応します
  • テーマの設定はブラウザに保存され、セッションをまたいで維持されます

テーマ対応アイコン

通知アイコン、ジョブ状態インジケーター、アクションアイコンは現在のテーマに自動的に適応します。たとえば成功アイコンは Cyberpunk では緑のチェックマークを表示し、Matrix では緑と黒の美学に合わせて別のシンボルを表示することがあります。

ダッシュボード

コレクション健全性スコア

円形のプログレスリングが、コレクション全体の健全性をパーセンテージで表示し、品質に応じて色分けします:

  • 緑（80% 以上）— メタデータの網羅性が優秀
  • シアン（60–79%）— おおむね良好だが一部に抜けあり
  • オレンジ（40–59%）— 網羅性は中程度、一括スクレイピングを検討
  • 赤（40% 未満）— メタデータに大きな抜けあり

下に並ぶ内訳のミニリングは、ボックスアート、説明文、実績の網羅状況を示します。

統計概要

ひと目で分かるカードで次を表示します:

  • 総システム数 — ライブラリ内のプラットフォーム数
  • 総ゲーム数 — 合計ゲーム数（ボーナスディスクを除く）
  • メタデータなし — まだスクレイプしていないゲーム
  • 完了 — メタデータをスクレイプ済みのゲーム

最近のアクティビティセクション

最近のアクティビティを表示するスクロール可能なセクション（該当するゲームがある場合のみ表示）:

  • 現在プレイ中 — 「進行中」とマークされたゲーム
  • 最近追加 — ライブラリに最近追加されたゲーム
  • 最近表示 — 最近開いたゲーム
  • 最近スクレイプ — 最近メタデータを取得したゲーム

クイックアクション

  • ライブラリをスキャン — 新しいゲームを探して ROM ディレクトリをスキャン
  • ランダムゲーム — ライブラリからランダムにゲームを選択

API ステータス

設定済みのすべてのスクレイパーと API の接続状態を表示します。オフラインまたは設定不備の API は、設定へのリンク付きの警告バナーを表示します。

ジョブの復旧

バックグラウンドジョブ（一括スクレイプ、RA 同期、画像リサイズなど）の実行中に RetroDB が再起動した場合、中断されたジョブが復旧バナーに表示されます。オプション:

  • 再開 — 中断された個別のジョブを再開
  • すべて再開 — 中断されたすべてのジョブを再開
  • 破棄 — 復旧リストから個別のジョブを消去
  • すべて破棄 — 中断されたすべてのジョブを消去

システムブラウザー

システムグリッド

システムページは、ライブラリ内のすべてのプラットフォームをレスポンシブなメイソンリーグリッドのカードとして表示します。各カードには次が表示されます:

  • システムロゴ（「設定 → カスタマイズ → ロゴ」でカスタマイズ可能）
  • ROM 数と未スクレイプ数
  • システム種別バッジ — 据置機、携帯機、コンピューター、アーケード、またはエンジン
  • 機能バッジ — RetroAchievements 対応、ローカルトロフィー（RPCS3）

システムスペックモーダル

任意のシステムカードの情報ボタンをクリックすると、詳細なハードウェア仕様を表示します:

  • ハードウェア画像（本体／システムの写真）
  • メーカーと発売日
  • CPU、GPU、RAM、VRAM
  • 解像度、色深度、サウンドチップ
  • メディア種別（カートリッジ、ディスクなど）

フィルタリングと検索

  • テキスト検索 — システム名またはフォルダー名で絞り込み
  • 種別フィルター — 据置機、携帯機、コンピューター、アーケード、エンジン
  • 機能フィルター — RetroAchievements 対応、ローカルトロフィー
  • フィルター結果バーに 「X / Y システム」を表示
  • フィルターはセッションストレージによりページ再読み込みをまたいで保持されます

システムごとのゲーム一覧

任意のシステムカードをクリックすると、そのゲームを表示します。システムごとのゲーム一覧は、ライブラリページ全体と同じ機能（無限スクロール、検索、すべてのフィルターオプション、一括選択、並べ替え）を備えています。システムヘッダーにはシステム名、ゲーム数、システム種別バッジが表示されます。

API キー設定ガイド

API キーは任意ですが、リッチなメタデータのスクレイピングや追加機能を有効にします。「設定 → スクレイピング → API キー」で設定します。

  1. api.thegamesdb.net/key.php にアクセスします

  3. 両方のキーを「設定 → API キー → TheGamesDB」に入力します
  4. Public キー（IP ごとのレート制限）がスクレイピングの主キーとして使われます

  4. Client ID をコピーし、Client Secret を生成します
  5. 両方を「設定 → API キー → IGDB」に入力します

RAWG.io

  2. 「Get API Key」をクリックしてアカウントを作成します
  3. ダッシュボードから API キーをコピーします
  4. それを「設定 → API キー → RAWG」に入力します

RetroAchievements

  1. retroachievements.org でアカウントを作成します

  4. ユーザー名と API キーを「設定 → アカウント → RetroAchievements」に入力します

Steam Web API

  1. steamcommunity.com/dev/apikey にアクセスします
  2. Steam Web API キーを登録します（Steam アカウントが必要）
  3. API キーと Steam ID（またはバニティ URL）を設定に入力します

PlayStation Network（PSN）

PSN は NPSSO クッキー認証を使用します。詳細な設定手順はトロフィーセクションを参照してください。

設定

設定は 6 つのタブに整理されており、それぞれ複数のサブセクションを持ちます。

アカウントタブ

  • マイプロフィール — アバターのアップロード／削除、表示名、ロール情報、パスワード変更
  • RetroAchievements — RA 連携用のユーザー名と API キー
  • PSN — PlayStation Network トロフィー同期用の NPSSO クッキー
  • タイムゾーン — アプリ全体の日付表示に使うタイムゾーンを設定
  • ユーザー — ユーザー管理: ユーザーの追加、編集、削除、ロールの割り当て（管理者のみ）

ライブラリタブ

  • パス — ROM ライブラリのパス、データベースの場所
  • 表示 — テーマ選択、ボックスアートのスタイル（2D/3D）、優先する年齢レーティングシステム、1 ページあたりの件数
  • ROM 命名 — 冠詞の配置（先頭／末尾の「The」）、地域オプション一覧、デフォルト地域、命名規則
  • バックアップ — データベースバックアップの作成と復元

スクレイピングタブ

  • ES-DE — ローカルデータインポート用の ES-DE ゲームリストとメディアのパス
  • スクレイパー — 各スクレイパーの有効化／無効化、ドラッグ＆ドロップによる優先順位付け、スクレイパーごとのレート制限設定
  • API キー — すべてのスクレイパー資格情報（TGDB、IGDB、RAWG、ScreenScraper）、AI プロバイダーの選択とモデルの選択（Gemini、OpenAI、Claude）

データタブ

  • 統計 — ライブラリ統計の概要（総ゲーム数、システム数、ストレージ使用量）
  • トロフィー — ローカル PS3 トロフィースキャン用の RPCS3 トロフィーパス設定
  • ドロップダウン — 地域オプションやアプリ全体で使われるその他のドロップダウン値をカスタマイズ
  • 正規化 — ジャンルとモードの正規化ルール — カスタムマッピングを追加してスクレイパー出力を標準化

カスタマイズタブ

  • 通知 — 通知のタイムアウト設定（成功、情報、警告、エラー — それぞれ独立して設定可能）
  • コントローラー — コントローラーライブラリの管理、システムごとのデフォルトコントローラー設定、カスタムコントローラーの追加。デフォルトコントローラーはメタデータ取得時にスクレイプ／AI 値を上書きします。
  • ロゴ — システムロゴのカスタマイズ — システムロゴのインポートまたはデフォルトからの更新

システムタブ

  • メンテナンス — データベース最適化（VACUUM/ANALYZE）、孤立メディアのクリーンアップ、欠落 ROM のクリーン、スクレイプデータのクリア、CLZ インポートのクリア、画像の一括標準化
  • サーバー — サーバー構成（ホスト、ポート、デバッグモード）
  • ロギング — カテゴリーごとのログレベル設定
  • トラブルシューティング — 停止した一括スクレイプのクリア、RA 同期キューのクリア、PSN 更新のクリア、ミュージアム生成のクリア、サーバーの再起動
ヒント: 無効化されたスクレイパーはダッシュボードで「API オフライン」警告を出しません。使わないスクレイパーは API キーを削除するのではなく、「設定 → スクレイピング → スクレイパー」で無効化してください。

メタデータのスクレイピング

単一ゲームのスクレイピング

  1. 任意のゲームの詳細モーダルを開きます（ゲームカードをクリック）
  2. 「スクレイプ」をクリックします
  3. 必要に応じて検索タイトルを修正します
  4. 候補から正しい結果を選択します
  5. 「適用」をクリックします

ハイブリッドスクレイピング

RetroDB は複数のソースのデータを自動的に組み合わせて、メタデータの網羅性を最大化します:

  • テキストメタデータは利用可能な最も優先度の高いソースから取得
  • 画像とメディアは、主ソースに無い場合は副ソースから取得
  • スクレイパーをまたいだ自動的な抜け埋めで網羅性を最大化
  • ソートタイトルはスクレイピング中にゲームタイトルから自動生成

メディアの扱い

  • メディアフィールド（ボックスアート、3D ボックスアート、スクリーンショット、ファンアート、動画、マニュアル）は通常のスクレイピング中に置き換えられることはなく、空のときのみ埋められます
  • スクリーンショットは常に追加され、置き換えられることはありません
  • メディアを再ダウンロードするには、まず編集モーダルで既存の画像をクリアしてから再スクレイプします
  • 完全再スクレイプモードはこれを上書きし、すべてを置き換えます
  • 古いメディア参照（ファイルは削除されたがファイル名は DB に残っている）はスクレイピング前に自動でクリアされ、新しいメディアをダウンロードできるようにします
  • ダウンロードした画像は目標サイズに自動的に標準化されます（画像標準化を参照）

スクレイパーの優先順位

どのスクレイパーを先に実行するか、どれを有効／無効にするかは「設定 → スクレイピング → スクレイパー」で設定します。ドラッグ＆ドロップで優先順位を並べ替えます。無効化されたスクレイパーはスクレイピング中に試行されず、ダッシュボードで API ステータス警告も出しません。

レート制限

各スクレイパーには API スロットリングを防ぐための設定可能なレート制限があります。デフォルトの遅延は控えめに設定されています。遅延を減らすのは自己責任で行ってください — API のレート制限を超えると、該当サービスから一時的に BAN される可能性があります。

一括スクレイピング

一括スクレイプの開始

  1. 任意のシステムまたはライブラリページに移動します
  2. 「選択」をクリックして選択モードに入ります
  3. ゲームを個別に選択するか、クイック選択を使います:
    • すべて選択 — 表示中のすべてのゲーム
    • 未スクレイプを選択 — メタデータのないゲームのみ
  4. モードを選びます: 不足分を埋める または 完全再スクレイプ
  5. 「選択をスクレイプ」をクリックします

操作

  • 一時停止／再開 — スクレイピングの一時停止または続行
  • キャンセル — 完全に停止
  • バックグラウンド — 最小化し、スクレイプ実行中もブラウジングを続行

トースト通知

バックグラウンドで実行中は、すべてのページに進捗を示す常駐トーストが表示されます:

  • 現在のゲーム名、進捗カウント、結果の統計（成功、失敗、スキップ）
  • どのページからも利用できる一時停止／キャンセル操作
  • トーストをクリックするとスクレイプモーダルに戻ります

キューシステム

複数の一括スクレイプは自動的にキューに入ります:

  • 1 つが実行中に新しいスクレイプを開始すると — キューに入ります
  • キューは保留中ジョブ数とともにトーストに表示されます
  • ジョブは順番に自動処理されます
  • キューマネージャーを使ってキュー内ジョブの表示、並べ替え、キャンセルができます

スクレイプオプション

  • 不足分のみ埋める — 空のメタデータフィールドのみを埋め、既存データを保持
  • 完全再スクレイプ — メディアを含むすべてのフィールドを置き換え（新しい画像と動画をダウンロード）
  • RetroAchievements をチェック — スクレイピング中に RetroAchievements の実績セットも確認

ジョブの復旧

ジョブの実行中に RetroDB が再起動された場合、中断されたジョブはダッシュボードの復旧バナーに表示されます。個別のジョブで「再開」をクリックするか、「すべて再開」で再開します。再開後すぐに進捗トーストが表示されます。

AI フィル

機能の概要

AI フィルは大規模言語モデル（Gemini、OpenAI、または Claude）を使って、不足または不完全なゲームメタデータを賢く埋めます。ゲームに関する文脈的な知識を活用し、スクレイパーが持っていない正確なデータを提供できるため、通常のスクレイピングより賢いと言えます。

使い方

  1. ゲームの詳細モーダル（または詳細ページ）を開きます
  2. 「AI フィル」をクリックします（設定で AI API キーが必要）
  3. AI がゲームタイトルとシステムを分析し、不足フィールドを埋めます
  4. 結果を確認します — 変更は自動的に保存されます

AI フィルが提供できる情報

  • ジャンル、説明文、開発元、発売元、発売日
  • プレイ人数、プレイモード（シングルプレイ、マルチプレイ、協力プレイなど）
  • キャンペーン情報とゲーム構造
  • 8 つすべての年齢レーティングシステム（ESRB、PEGI、CERO、USK、ACB、FPB、GRAC、ClassInd）
  • 地域、フランチャイズ、類似ゲーム
  • コントローラー対応、セーブ方式
  • 視点（一人称、トップダウン、横スクロールなど）、次元（2D、3D）
  • エディション情報、批評家スコアとユーザースコア

スマートフィルのロジック

  • 空のフィールドは常に埋められます
  • 既存のユーザーデータは決して上書きされません
  • 類似ゲームは常に更新されます（このフィールドでは AI データのほうが信頼できるため）
  • クロスマッピングされたレーティング — あるレーティングシステムが分かっている場合、他システムの空のレーティングは成熟度ティアのクロスマッピングを使って自動的に埋められます
  • ソートタイトルは埋められる際に自動生成されます
  • プレイ人数フィールドは範囲を正規化します（例: 「1-4」は 4 になります）

ジャンルの正規化

AI フィルはハイフン付きの名称による正規ジャンル形式を使用します:

  • First-Person-Shooter、Shoot-em-up、Beat-em-up
  • Hack-n-Slash、Board-Card、Real-Time Strategy

要件

「設定 → スクレイピング → API キー」で少なくとも 1 つの AI プロバイダー API キーを設定する必要があります。最も安価なモデルティア（Gemini Flash Lite、GPT-4o Mini、または Claude Haiku）でもメタデータには十分機能します。

フィルタリングと検索

検索

検索はタイトル（およびソートタイトル）でゲームを絞り込みます。/ を押すと検索ボックスにフォーカスします。結果は 300ms のデバウンスでリアルタイムに更新されます。

ソースフィルター

インポート元でゲームを絞り込みます:

  • ROM ファイル — ROM ライブラリのゲーム
  • CLZ インポート — CLZ からインポートした実物ゲーム
  • Steam インポート — Steam からインポートしたゲーム
  • Xbox インポート — Xbox からインポートしたゲーム
  • PSN インポート — PlayStation Network からインポートしたゲーム

フィルターボタン

各フィルターは、ライブラリ内のすべての固有値を件数とともに表示するモーダルを開きます。フィルターは 2 つのモードをサポートします:

  • 含める（IS） — 選択した値に一致するゲームのみを表示
  • 除外する（IS NOT） — 選択した値に一致するゲームを非表示

フィルターモーダル内のスイッチで含める／除外するモードを切り替えます。

  • タイトル — ソートタイトルのアルファベット順（大文字小文字を区別しない）
  • 発売日 — 時系列順（古いものから）
  • プラットフォーム — システム名でグループ化

アルファベットナビゲーション

特定の文字で始まるゲームへジャンプします。一致するゲームのない文字はグレーアウトされます。数字と記号は # の下にまとめられます。

無限スクロール

ゲームはスクロールに合わせて 100 件ずつのバッチで読み込まれます。下端に近づくと新しいページが自動で読み込まれます。フィルターや検索を変更すると、結果は即座にリセットされ再読み込みされます。

状態の保持

現在のフィルター、検索語、スクロール位置はセッションストレージに保存されます。ページに戻ったり更新したりすると復元されます。

ゲーム詳細

ゲーム詳細モーダル

任意のゲームカードをクリックすると、キャッシュされたクイックビューを備えた詳細モーダルが開きます。モーダルには次が表示されます:

  • ボックスアート（2D と 3D）、ファンアート背景
  • 説明文と発売情報
  • 開発元、発売元、ジャンルバッジ
  • プレイ人数、プレイモード、ゲーム構造
  • 年齢レーティング画像（優先するシステムから、クロスマッピングのフォールバック付き）
  • キーボードナビゲーション付きのスクリーンショットギャラリー（← →）
  • 予告編動画（利用可能な場合）
  • HLTB プレイ時間の見積もり（メインストーリー、メイン＋エクストラ、コンプリート）
  • RetroAchievements の状態と進捗
  • 類似ゲーム（クリック可能なリンク）
  • コントローラー対応の詳細
  • ゲームに割り当てられたタグ
  • ファイルサイズと ROM パス

ゲーム詳細ページ全体

ゲームタイトルのリンクをクリックするか、パンくずリストから移動するとゲーム詳細ページ全体を表示します。全体ページの追加機能には次が含まれます:

  • ファンアート背景ヘッダー（パンくずナビゲーション付き）
  • プラットフォームインポートバッジ — 該当する場合、CLZ インポート、Steam インポート、Xbox インポート、PSN インポートをプラットフォームロゴ付きで表示
  • ボーナスディスクのインジケーター — バッジと、サムネイル付きで親ゲームへの「一部:」リンクを表示
  • 削除ボタン — データベースからゲームを削除（確認あり）
  • クリアボタン — ROM エントリを保持したまま、スクレイプ済みメタデータをすべてクリア

編集モーダル

編集をクリック（または e を押す）すると、次のセクションに整理された編集モーダルが開きます:

  • 識別情報 — タイトル、ソートタイトル（自動生成だが編集可能）、フランチャイズ、エディション
  • 発売情報 — 発売日、地域（設定可能なドロップダウンから）
  • ゲームプレイ — ジャンル（複数選択タグ）、モード、ゲーム構造、プレイ人数、開発元、発売元
  • 技術情報 — コントローラー（複数選択）、セーブ方式、視点（複数値）、次元（複数値）
  • 年齢レーティング — 公式レーティング画像と自動クロスマッピングを備えた 8 つすべてのレーティングシステム。1 つのレーティングを変更すると、他システムの空のレーティングが自動で埋められます。
  • スコア — 批評家スコア、ユーザースコア
  • 説明 — ゲームの説明文
  • カスタム画像 — カスタムのボックスアート（2D）、3D ボックスアート、ファンアートをアップロード。既存画像をクリアすると再スクレイプが可能になります。
  • 動画／予告編 — 動画予告編をアップロードまたはリンク

クイックアクション

  • 編集 — 編集モーダルを開く（e）
  • スクレイプ — スクレイパーソースからメタデータを取得（s）
  • AI フィル — 不足フィールドを AI で埋める（AI API キーが必要）
  • RA をチェック — RetroAchievements の実績セットを検索
  • HLTB ルックアップ — HowLongToBeat からプレイ時間の見積もりを検索

クリア状況

次のステータスで進捗をトラッキングします（ゲームカードにバッジとして表示）:

  • 未開始 — まだプレイしていない
  • 進行中 — 現在プレイ中
  • プレイ済み — プレイしたが未クリア
  • クリア — メインゲームをクリア
  • 100% — すべてをコンプリート

ゲームの比較

機能の概要

2 つのゲームのメタデータをテーブル形式で並べて比較します。メタデータの品質確認、重複の発見、システムをまたいだ同一ゲームのバージョン比較に便利です。

使い方

  2. 1 つ目のゲームを検索して選択します
  3. 2 つ目のゲームを検索して選択します
  4. 比較テーブルを確認します — 相違点がハイライトされます

比較されるフィールド

システム、開発元、発売元、発売日、ジャンル、フランチャイズ、地域、プレイ人数、モード、視点、次元、8 つすべての年齢レーティング、ユーザーレーティング、批評家スコア、プレイ時間の見積もり、コントローラー対応、セーブ方式、ファイルサイズ、類似ゲーム、説明文など。

コレクション（タグ、リスト、ウィッシュリスト）

タグ

ゲームを整理するために、色分けされたカスタムタグを作成します。タグはラベルのように機能します — 各ゲームは複数のタグを持つことができ、各タグは複数のゲームを含むことができます。

  • タグページからカスタム名と色でタグを作成します
  • ゲーム詳細モーダルからゲームにタグを割り当てます
  • 任意のタグをクリックすると、そのタグの付いたすべてのゲームをブラウズできます
  • タグ管理ページからタグを編集または削除します

名前付きリスト

カスタムの並び順でキュレーション済みのゲームリストを作成します。リストはプレイリストのようなもので — ゲームの正確な順序を自分で制御できます。

  • リストページから名前、説明、アイコンを付けてリストを作成します
  • ゲーム詳細モーダルまたはリストページからリストにゲームを追加します
  • ドラッグ＆ドロップでリスト内のゲームを並べ替えます
  • カスタム順またはアルファベット順で並べ替えます

ウィッシュリスト

実物・デジタルを問わず、入手したいゲームをトラッキングします。

  • タイトル、システム、メモ、優先度（1–5）を付けて手動でゲームを追加します
  • ウィッシュリストのアイテムは、見つかれば既存のライブラリゲームにリンクできます
  • 優先度順（高い順）に、次に追加日順で並びます
ヒント: 横断的なラベルにはタグを（例: 「お気に入り」「カウチ協力プレイ」「積みゲー」）、特定のキュレーション済みコレクションにはリストを（例: 「SNES ベスト 10」「配信するゲーム」）使いましょう。

ゲームインポート

外部ソースからゲームコレクションをインポートします。サイドバーのゲームインポートからアクセスします。すべてのインポート種別が 1 つのタブ付きページにまとめられています。

CLZ Games インポート

CLZ Games から実物のゲームコレクションをインポートします。

  1. CLZ Games のコレクションを PDF としてエクスポートします
  2. ゲームインポート → CLZ タブに移動します
  3. PDF ファイルをアップロードします
  4. 解析されたゲームを確認します
  5. インポートするゲームを選択します

CLZ インポートは ROM ゲームとは別に管理され（clz_import/ プレフィックスを使用）、実物とデジタルの両方のコレクションをカタログ化できます。CLZ インポートは「設定 → システム → メンテナンス」からまとめてクリアできます。

Steam インポート

Steam のゲームライブラリをインポートし、実績をトラッキングします。

  1. 設定で Steam Web API キーと Steam ID を設定します
  2. ゲームインポート → Steam タブに移動します
  3. 「ライブラリを取得」をクリックして Steam ゲームを取得します
  4. インポートするゲームを選択します（重複は自動検出されます）
  5. インポートしたゲームは実績トラッキング用に Steam App ID でタグ付けされます

Xbox インポート

Microsoft アカウント経由で Xbox のゲームライブラリをインポートします。

  1. ゲームインポート → Xbox タブに移動します
  2. 「サインイン」をクリックして Microsoft アカウントで認証します（OAuth2 フロー）
  3. Xbox のタイトル履歴が自動的に取得されます
  4. 重複検出付きでインポートするゲームを選択します
  5. インポートしたゲームは実績トラッキング用に Xbox Title ID でタグ付けされます

Xbox トークンは data/xbox_tokens.json にキャッシュされ、自動的に更新されます。

PSN インポート

PlayStation Network のゲームライブラリをインポートします。

  1. ゲームインポート → PSN タブに移動します
  2. NPSSO クッキーを入力します（取得方法はトロフィー → PSN 認証を参照）
  3. 「ライブラリを取得」をクリックして PSN ゲームを取得します
  4. インポートするゲームを選択します

インポート後

  • インポートしたゲームは、プラットフォーム固有のバッジ付きでライブラリに表示されます
  • 一括スクレイプを使ってインポートしたゲームのメタデータを取得できます
  • 実績／トロフィーのトラッキングは元のプラットフォームに自動的にリンクされます
  • インポートしたゲームはライブラリでソースフィルターを使って絞り込めます
ヒント: どのプラットフォームからゲームをインポートした後でも、ROM ゲームと同じように一括スクレイプでメタデータをスクレイプできます。インポートしたゲームは、それぞれのプラットフォームから実績をトラッキングすることもできます。

RetroAchievements

セットアップ

  1. retroachievements.org でアカウントを作成します
  2. プロフィール設定で API キーを生成します
  3. ユーザー名と API キーを「設定 → アカウント → RetroAchievements」に入力します

実績ページ

  • システムタブ — プラットフォーム別に実績をブラウズ（最後に表示したタブを記憶）
  • アルファベットナビゲーション — 各システムタブ内で頭文字によりゲームへジャンプ
  • 進捗を更新 — RetroAchievements から実績の進捗を同期
  • 全体統計 — すべてのシステムにわたる獲得実績とポイント
  • ゲームごとの進捗 — プログレスバーで各ゲームのクリア率を表示

同期キュー

複数のシステム同期をキューに入れられます:

  • 任意のシステムで「進捗を更新」をクリックして同期を開始またはキューに追加します
  • すでに同期が実行中の場合、新しいリクエストは自動的にキューに入ります
  • 現在の同期が完了するとキューが自動的に処理されます
  • トースト通知に現在の進捗とキュー数を表示します

実績のあるゲームを探す

  • ライブラリフィルター — 「RA あり」フィルターを使って実績のあるゲームのみを表示
  • RA をチェック — ゲーム詳細モーダルでクリックして実績セットを検索
  • 一括スクレイプ — 「RA をチェック」オプションを有効にしてスクレイピング中に実績を検出
  • RA 更新ジョブ — システム内のすべてのゲームをスキャンして RA 対応のものを特定

ゲーム単位の詳細

実績ページで任意のゲームをクリックすると、個々の実績名、説明、ポイント値、獲得状況を含む、ゲームごとの詳細な実績情報を表示します。

注: 「進捗を更新」は、すでに RetroAchievements がリンクされているゲームの進捗を同期します。 新しい実績セットを見つけるには、ゲーム詳細モーダルで「RA をチェック」を使うか、一括スクレイピング中に有効にしてください。

Steam 実績

セットアップ

  1. ゲームインポート → Steam から Steam ゲームをインポートします
  2. Steam Web API キーが設定で構成されていることを確認します

実績ランディングページ

  • 全体統計 — Steam ゲーム総数、獲得実績数、クリア率
  • ゲームごとの進捗 — 各ゲームのクリア率バー

ゲームごとの実績詳細

  • 実績アイコン、名前、説明
  • 解除済みと未解除の状態、解除タイムスタンプ付き
  • 各実績の全プレイヤー解除率

同期

  • 詳細ページから単一ゲームの実績を同期します
  • 実績ランディングページからすべての Steam ゲームを一括同期します
  • 同期はトースト通知の進捗付きでバックグラウンドジョブとして実行されます

Xbox 実績

セットアップ

  1. ゲームインポート → Xbox から Xbox ゲームをインポートします
  2. 認証はインポート中に Xbox OAuth 経由で処理されます

実績ランディングページ

  • 全体統計 — Xbox ゲーム総数、獲得実績数、獲得／合計ゲーマースコア、クリア率
  • ゲームごとの進捗 — プログレスバー付きでゲームごとに獲得したゲーマースコア

ゲームごとの実績詳細

任意の Xbox ゲームをクリックすると、個々の実績を表示します:

  • 個々のゲーマースコア値付きの実績アイコン
  • 解除済みと未解除の状態、解除タイムスタンプ付き
  • 各実績のゲーマースコアバッジ

同期

  • 単一ゲームの同期またはすべての Xbox ゲームの一括同期
  • トースト通知付きでバックグラウンドジョブとして実行されます
  • 各同期後にゲーマースコアの合計が自動的に更新されます

How Long to Beat

使い方

  1. 任意のゲームの詳細モーダルを開きます
  2. 「HLTB ルックアップ」をクリックします
  3. 結果から正しい一致を選択します
  4. プレイ時間の見積もりがゲームに保存されます

時間カテゴリー

  • メインストーリー — コアのクリア時間
  • メイン＋エクストラ — サイドコンテンツを含む
  • コンプリート — すべてを 100%

HLTB データが表示される場所

  • ゲーム詳細モーダル — ゲーム情報内にプレイ時間の見積もりを表示
  • ゲーム詳細ページ全体 — 同じプレイ時間情報
  • 分析 → プレイ時間タブ — コレクション全体のプレイ時間分析
  • ゲームの比較 — プレイ時間の並列比較

PS3 / PSN トロフィー

RPCS3 ローカルトロフィー

RPCS3 エミュレーターで PS3 ゲームで獲得したトロフィーをトラッキングします。

  1. 「設定 → データ → トロフィー」で RPCS3 トロフィーパスを設定します
  2. 「トロフィーをスキャン」をクリックして獲得済みトロフィーをインポートします
  3. RPCS3 トロフィーセクションでトロフィー一覧と個々のトロフィー詳細を表示します

RPCS3 は RPCS3 ユーザーディレクトリからトロフィーの XML データを読み込み、ゲームをライブラリに自動的に一致させます。

PSN API トロフィー

PSN アカウントから PlayStation Network のトロフィーデータを同期します。

  1. NPSSO クッキーを取得します（下記参照）
  2. 「設定 → アカウント → PSN」に入力します
  3. PlayStation API 経由で PSN トロフィーライブラリが取得されます
  4. 獲得／合計数とともにゲームごとのトロフィー進捗を表示します
  5. 個々のトロフィー詳細には説明、レア度、解除タイムスタンプが含まれます

PSN 認証（NPSSO クッキー）

PSN は NPSSO トークンと呼ばれる特別な認証クッキーを使用します。取得方法:

  1. Web ブラウザを開き、store.playstation.com にログインします
  2. ログインしたら、次に移動します: https://ca.account.sony.com/api/v1/ssocookie
  3. ページに NPSSO トークンを含む JSON が表示されます
  4. npsso の値をコピーし、設定 → アカウント → PSN に貼り付けます

認証されると、トークンは data/psn_tokens.json にローカルでキャッシュされ、自動的に更新されます。キャッシュされたトークンは約 2 か月間有効です。

トロフィー詳細

  • トロフィー種別: ブロンズ、シルバー、ゴールド、プラチナ
  • トロフィーアイコンはダウンロードされてローカルにキャッシュされます
  • ゲームごとのクリア率
  • 獲得した各トロフィーの解除タイムスタンプ

一括同期

バックグラウンドジョブで PSN の全ゲームトロフィーを一度に同期します。進捗はトースト通知に表示されます。レート制限（リクエスト間 2.5 秒）により PSN API のスロットリングを防ぎます。

概要

コレクションのマイルストーンに基づいてトロフィーを授与するゲーミフィケーションシステムです。ゲームを追加し、メタデータをスクレイプし、ゲームをクリアするにつれて、トロフィーが自動的に解除されます。

  • コレクタートロフィーページにアクセスして、各トロフィーへの進捗を確認します
  • 変更後は「更新」をクリックして進捗を更新します
  • 獲得したトロフィーは解除日とともに表示されます
  • プログレスバーで次のマイルストーンまでの近さを表示します

ミュージアム

概要

世代別に整理されたゲームシステムのインタラクティブな百科事典です。コレクション内の各プラットフォームの歴史、仕様、注目すべきゲームについて学べます。

ランディングページ

ミュージアムのランディングページは、世代別（第 1–9 世代、携帯機、アーケード、コンピューター）にグループ化されたゲームシステムのタイムラインを表示します。各システムカードにはハードウェア画像とライブラリ内のゲーム数が表示されます。

システム詳細ページ

任意のシステムをクリックすると、次を含むミュージアムページを表示します:

  • ハードウェア画像 — 本体／システムの写真
  • 技術仕様 — CPU、GPU、RAM、解像度、メディア種別
  • 歴史 — システムの開発、ローンチ、レガシーに関する AI 生成のナラティブ
  • トップ 10 ゲーム — システムの最も注目すべきタイトル（批評家スコアと AI の提案から）
  • コントローラーギャラリー — 説明付きのシステムコントローラー画像

AI コンテンツ生成

ミュージアムのコンテンツは AI（Gemini、OpenAI、または Claude）を使って生成されます。次のコンテンツを生成できます:

  • 単一システム — 任意のシステムのミュージアムページで「生成」をクリック
  • 一括生成 — ランディングページからすべてのシステムのコンテンツを一度に生成（トースト進捗付きのバックグラウンドジョブとして実行）

コントローラー画像

コントローラー画像は次の方法で追加できます:

  • 画像検索 — Bing 画像検索を使ってコントローラーの写真を検索。結果は関連度（コントローラー名＋メーカー＋システムのバリエーション）でランク付けされます。
  • 手動アップロード — 自分のコントローラー画像をアップロード
  • 背景除去 — ローカル AI（rembg ライブラリ）を使って背景を自動除去し、どんな背景でも使える透過コントローラー画像を作成
  • 画像の伝播 — コントローラー画像が見つかると、他システムの同じコントローラー（兄弟コントローラー）に自動的に共有されます
  • 一括取得 — システム内のすべてのコントローラーの画像を一度に取得

すべてのコントローラー画像は目標サイズに標準化され、WebP 形式で保存されます。

ヒント: コンテンツ生成には AI API キーが必要です。ミュージアムは「設定 → スクレイピング → API キー」で設定された AI プロバイダーと同じものを使用します。

分析

分析は 12 タブにわたる包括的な統計と可視化を提供します。すべてのチャートはインタラクティブで、PNG としてエクスポート、クリップボードにコピー、または CSV としてダウンロードできます。

ROM レポート

機能の概要

標準的な命名規則に対して ROM ファイル名を検証し、潜在的な問題を特定します。サイドバーの ROM レポートからアクセスします。

レポート種別

タブチェック内容
非標準名命名規則に一致しないファイル名の ROM。現在のファイル名、検出された問題、提案される修正名を表示します。
名前の不一致ファイル名がスクレイプ済みのメタデータタイトルと一致しない ROM。現在のファイル名とスクレイプ済みタイトル、地域、年、開発元を表示します。

チェックされる内容

  • ファイル名中の無効な文字（: ? * / " < > | \）
  • 地域タグの欠落または誤り（例: (USA)、(Europe)）
  • 年タグの欠落
  • ファイル名とデータベースタイトルの不一致

レポートはシステム、ファイル名、問題種別で並べ替えられます。これらを使って ROM ライブラリを整理し、一貫した命名を保ちましょう。

ROM ツール

サイドバーから ROM ツールハブにアクセスします。各ツールはリアルタイムの進捗更新、一時停止／再開対応、ロギングを備えたバックグラウンドジョブとして実行されます。

アーカイブスキャナー

次のオプション付きで ROM アーカイブ（ZIP、7Z、RAR）を展開します:

  • サブディレクトリの再帰スキャン
  • 展開後の不要ファイルの削除
  • マルチディスクゲーム用の M3U プレイリストの自動生成

必要: 7z または unzip

CHD コンバーター

ディスクイメージ（ISO、BIN/CUE、GDI）を圧縮 CHD 形式に変換します。エミュレーターとの完全な互換性を保ちながら、ストレージを大幅に節約します。

必要: chdman（mame-tools から）

CHD 検証

ハッシュ検証で CHD ファイルの整合性を検証します。破損または不完全な変換を特定します。

必要: chdman

重複ファインダー

ハッシュまたはファイル名で重複した ROM を見つけ、地域タグで優先順位を付けるオプションがあります。

外部依存なし

マルチディスク整理

マルチディスクゲームをサブディレクトリに整理し、対応エミュレーター向けに M3U プレイリストを生成します。PlayStation や Saturn のようなシステムに便利です。

外部依存なし

スクリーンショット重複除去

ゲームライブラリ全体で重複したスクリーンショットを見つけて削除し、ストレージ容量を解放します。

  • 完全ハッシュ（MD5） — 完全に同一のファイルのみを特定
  • 視覚的類似度 — 設定可能なしきい値（1–20、低いほど一致が厳密）による知覚ハッシュ比較

スキャンしたゲーム数、重複数、回収可能な容量を示すライブ統計とともに段階的にスキャンします。結果はゲームとシステムごとにグループ化されます。各重複グループで保持するファイルを選択できるほか、「最大を選択」を使って最高解像度のバージョンを自動的に保持できます。

外部依存なし

画像リサイザー

ゲームメディアを一貫した目標サイズに標準化します。詳細は画像標準化を参照してください。

外部依存なし（Python ベースの AI アップスケーリング）

別名タイトルのバックフィル

別名タイトルフィールドが空のゲームをライブラリから探し、IGDB／TGDB／ScreenScraper から埋めます。大規模なカタログをインポートした後や、地域名／日本語／サブタイトルを保存していなかった別のツールから移行した後に便利です。バックグラウンドで実行され、進捗はツールカードに表示されます。

少なくとも 1 つのスクレイパー API キーが必要（IGDB／TGDB／ScreenScraper）

HLTB 一括ルックアップ

プレイ時間の見積もりが欠けているすべてのゲームに対して HowLongToBeat のルックアップを実行します。各一致はタイトル＋プラットフォーム＋発売年でスコア付けされ、高信頼度の一致は自動的に保存されます。信頼度しきい値を下回るもの（またはプラットフォームが矛盾するもの）は人によるレビュー用に保留されます。

外部依存なし（同梱のオフライン HLTB データセットを使用）

HLTB 保留レビュー

HLTB 一括ルックアップで浮かび上がった曖昧な一致のレビューキューです。各保留行は、元のゲームを HLTB 候補（タイトル、プラットフォーム、発売年、信頼度）とともに表示します。行ごとに承認、却下、または別の一致の選択ができます。レビューツールカードは、保留中の一致が少なくとも 1 件あるときだけ ROM ツールハブに表示されます。

  • 低信頼度、別名タイトル、プラットフォーム不一致の一致向けのフィルタータブ。
  • 承認はプレイ時間の見積もりを書き込み、却下は候補を破棄してルックアップキューをクリーンに保ちます。

ツール設定

すべての ROM ツールで共有されるパス、ツールの場所、アーカイブ種別、設定を構成します。

ヒント: すべての ROM ツールは一時停止／再開に対応し、バックグラウンドで実行されます。進捗と結果はログに記録され、ログビューアーで確認できます。ツールの状態（利用可能 vs 要インストール）は各ツールカードに表示されます。

正規化

機能の概要

ジャンルとプレイモードの値を一貫した正規形式に正規化します。これはスクレイピングと AI フィル中に自動的に行われ、既存のライブラリに手動で適用することもできます。

なぜ重要か

異なるスクレイパーは同じものに異なる名称を使います。正規化はライブラリ全体で一貫性を保ちます:

  • platform → Platformer
  • fps、first person shooter → First-Person-Shooter
  • shoot 'em up、shmup → Shoot-em-up
  • beat 'em up、brawler → Beat-em-up
  • hack and slash → Hack-n-Slash
  • rts、real time strategy → Real-Time Strategy
  • board game、card game → Board-Card

カスタムルール

「設定 → データ → 正規化」でカスタム正規化ルールを追加できます。カスタムルールは組み込みのマッピングを上書きし、好みのジャンルやモードの名称を自分で定義できます。ルールはデータベースに保存されます。

プレビューと適用

正規化を適用する前に、どのゲームが影響を受け、どのような変更が行われるかをプレビューできます。これにより、ライブラリへの変更を確定する前に確認できます。

画像標準化

機能の概要

すべてのゲームメディアを一貫した目標サイズに標準化し、ライブラリ全体で統一された見た目にします。目標サイズの 80–120% 以内の画像はスキップされます。

仕組み

  • アップスケーリング — 目標サイズより小さい画像は Real-ESRGAN x4（ONNX Runtime による AI 超解像）で高品質に拡大され、その後ちょうど目標サイズにリサイズされます
  • ダウンスケーリング — 目標サイズより大きい画像は Lanczos フィルタリングで縮小され、シャープな結果になります
  • しきい値帯 — 目標サイズの 80–120% 以内の画像は不要な再処理を避けるためそのまま残されます

目標サイズ

メディア種別目標方式
ボックスアート高さ 1080px幅は比例的に拡大縮小
3D ボックスアート高さ 1080px幅は比例的に拡大縮小（透過を保持）
スクリーンショット高さ 1080px幅は比例的に拡大縮小
コントローラー最長辺 1280px透過を保持（RGBA）
ハードウェア最長辺 1280px透過を保持（RGBA）
ファンアートスキップ標準化しない（元のサイズのまま）

実行方法

  1. 「設定 → システム → メンテナンス」または 「ROM ツール → 画像リサイザー」に移動します
  2. 「開始」をクリックして一括標準化を始めます
  3. ジョブは、現在のファイルと統計を示すトースト進捗付きでバックグラウンドで実行されます
  4. 画像はスクレイピング中にも自動標準化されます（新しいダウンロードは即座に標準化されます）

ハードウェアサポート

Real-ESRGAN モデルはお使いのハードウェアを自動検出し、利用可能な最良のプロバイダーを使用します:

  • CUDA — NVIDIA GPU アクセラレーション
  • ROCm — AMD GPU アクセラレーション（RX 6000 シリーズ向けの gfx バージョン自動オーバーライド付き）
  • CoreML — Apple Silicon アクセラレーション
  • CPU — GPU 非対応システム向けのフォールバック

ONNX モデルファイルは初回使用時に Hugging Face から自動的にダウンロードされ、ローカルにキャッシュされます。

ログビューアー

機能の概要

すべてのアプリケーションログ向けの統合ビューアーです。サイドバーのログビューアーからアクセスします。

機能

  • カテゴリーで絞り込むか、すべてのログをまとめて表示
  • ファイル一覧に作成日とファイルサイズを表示
  • 任意のログファイルをクリックして全内容を表示
  • 個別のログファイルをダウンロード
  • 素早い概観のためにカテゴリー数を上部に表示
  • ログレベルは「設定 → システム → ロギング」で設定可能

メンテナンス

メンテナンス操作は「設定 → システム → メンテナンス」で利用できます。これらはライブラリをクリーンで最適な状態に保つのに役立ちます。

ライブラリのスキャン

  • ライブラリをスキャン — 新しいゲームを探して ROM ディレクトリをスキャンします。ES-DE の systeminfo.txt 拡張子一覧を使ってシステムフォルダーと対応ファイル種別を検出します。ダッシュボードからも利用できます。

クリーンアップ操作

  • 欠落 ROM のクリーン — ROM ファイルがディスク上に存在しなくなったゲームのデータベースエントリを削除します。ROM ファイルを再整理または削除した後に便利です。
  • 孤立メディアのクリーンアップ — 対応するデータベース参照のないディスク上の画像ファイル（ボックスアート、スクリーンショット、ファンアート）を見つけて削除します。削除前にプレビューで確認できます。
  • スクレイプデータのクリア — ROM ファイルエントリを保持したまま、ゲームからすべてのスクレイプ済みメタデータを削除します。スクレイピングをやり直すときに便利です。実行前にプレビューで影響を受けるゲームを表示します。
  • CLZ インポートのクリア — すべての CLZ Games インポート記録（ROM ファイルのないメタデータのみのエントリ）を削除します。

データベース最適化

  • データベースを最適化 — SQLite の VACUUM と ANALYZE を実行し、削除された記録からストレージを回収してクエリプランナーの統計を更新します。大量削除やクリーンアップ操作の後に推奨されます。

画像の一括標準化

すべてのゲーム画像を目標サイズに標準化します。詳細は画像標準化を参照してください。

サーバー管理

  • サーバーを再起動 — アプリケーションの正常な再起動（クリーンアップして終了）。「設定 → システム → トラブルシューティング」で利用できます。

バックアップと復元

バックアップの作成

  1. 「設定 → ライブラリ → バックアップ」に移動します
  2. 「バックアップを作成」をクリックします
  3. バックアップはタイムスタンプ付きのファイル名で backups/ フォルダーに保存されます

バックアップされる内容

バックアップには SQLite データベース全体（roms.db）が含まれ、すべてのゲームメタデータ、ユーザーアカウント、設定、トロフィーデータ、実績進捗、タグ、リスト、ウィッシュリストアイテムが含まれます。

バックアップされない内容

メディアファイル（ボックスアート、スクリーンショット、ファンアート、動画、マニュアル）は、スクレイピングで再ダウンロードできるため、データベースバックアップには含まれません。カスタムアップロードがある場合は、static/images/ ディレクトリを別途バックアップすることを検討してください。

復元

  1. バックアップ一覧でバックアップを見つけます
  2. 「復元」をクリックします
  3. 操作を確認します
警告: バックアップを復元すると現在のデータベースが上書きされます。古いものを復元する前に、新しいバックアップを作成してください！

RetroDB のアップデート

アップデート方法

  1. 新しい RetroDB リリースをダウンロードします
  2. これらのファイルをバックアップします（個人データが含まれます）:
    • config.py（パスと API キー）
    • data/settings.json（UI の設定）
    • data/scraper_settings.json（スクレイパーの構成）
    • data/rom_tools_config.json（ROM ツールの設定）
    • data/psn_tokens.json（PSN 認証トークン）
    • data/xbox_tokens.json（Xbox 認証トークン）
    • database/ フォルダー（ゲームライブラリのデータベース）
  3. 既存のインストールに上書きして新しいバージョンを展開します
  4. python install.py を実行して新しい依存関係をインストールします
  5. サーバーを再起動します

上書きしても安全なファイル

すべてのソースコードファイル（.py、.html、.css、.js）は安全に上書きできます。インストーラーは個人の設定ファイルを上書きしません。

保持すべきファイル

決して削除または上書きしないでください: config.py、database/roms.db、data/settings.json、data/scraper_settings.json、data/rom_tools_config.json。

データベースマイグレーション

RetroDB は起動時にデータベーススキーマの変更を自動的に処理します。新しいカラムやテーブルはデータを失うことなく必要に応じて追加されます。特別なことをする必要はありません — 新しいバージョンを起動するだけで、データベースが自動的に更新されます。

トラブルシューティング

よくある問題

「システムの拡張子が見つかりません」

システムフォルダーには、対応する ROM ファイル拡張子を定義した有効な ES-DE systeminfo.txt ファイルが必要です。ROM ディレクトリ構造が ES-DE 標準に一致していることを確認してください。

「API 接続に失敗しました」

  • インターネット接続を確認してください
  • 「設定 → スクレイピング → API キー」で API キーを確認してください
  • レート制限されている場合は待ってください（一部の API には日次／時間ごとの上限があります）
  • スクレイパーが有効か確認してください（無効化されたスクレイパーはダッシュボードのステータスに「無効」と表示されます）
  • 詳細なエラーメッセージはログビューアーで確認してください

「一括スクレイプが停止しています」

「設定 → システム → トラブルシューティング → 「停止した一括スクレイプをクリア」」に移動します。これはデータに影響を与えずにジョブの状態をリセットします。

「RA 同期キューが停止しています」

「設定 → システム → トラブルシューティング」から RetroAchievements 同期キューをクリアします。

「PSN 同期が停止しています」

「設定 → システム → トラブルシューティング」から PSN 更新ジョブをクリアします。

「ミュージアム生成が停止しています」

「設定 → システム → トラブルシューティング」からミュージアム生成ジョブをクリアします。

「データベースエラー」

  1. 可能であればバックアップを作成します（設定 → ライブラリ → バックアップ）
  2. 「設定 → システム → メンテナンス → データベースを最適化」を試します
  3. database/ ディレクトリのファイル権限を確認します
  4. 最終手段: バックアップから復元するか、データベースを削除して再スキャンします

「画像が保存されない」

メディアディレクトリの書き込み権限を確認してください: chmod -R 755 static/images/

「ページが遅い、または応答しない」

  • 大規模なコレクションは読み込みに時間がかかることがあります — 無限スクロールは 100 件ずつのバッチで読み込みます
  • 蓄積されたメモリをクリアするためにページを更新してみてください
  • ブラウザのコンソールで JavaScript エラーを確認してください
  • より軽量なキャンバスエフェクトのテーマ（例: Amber や Elite）に切り替えてみてください
  • キャンバスエフェクトはハードウェアを自動検出します。低スペックデバイスは CPU フォールバックを使用します

ダッシュボードの「中断されたジョブ」バナー

ジョブの実行中に RetroDB が再起動すると、復旧バナーに表示されます。個別に「再開」をクリックするか、「すべて再開」で再開します。「破棄」または「すべて破棄」をクリックして消去します。

「PSN 認証に失敗しました」

  • NPSSO トークンは期限切れになります — ca.account.sony.com/api/v1/ssocookie から新しいものを生成してください
  • クッキー URL にアクセスする前に store.playstation.com にログインしていることを確認してください
  • data/psn_tokens.json のキャッシュ済みトークンは約 2 か月持続します

「Xbox 認証に失敗しました」

  • ゲームインポート → Xbox タブで「サインイン」をクリックして再認証してください
  • Xbox トークンは data/xbox_tokens.json にキャッシュされ、自動的に更新されます

「画像アップスケーリングのエラー」

  • Real-ESRGAN ONNX モデルは初回使用時にダウンロードされます — インターネットアクセスを確認してください
  • GPU アクセラレーションには互換性のあるドライバーが必要です（NVIDIA は CUDA、AMD は ROCm）
  • GPU が失敗した場合、システムは自動的に CPU 処理にフォールバックします

パフォーマンスのヒント

  • 最高のパフォーマンスのためにブラウザを最新の状態に保ってください
  • 非常に大規模なコレクションを扱うときは他のブラウザタブを閉じてください
  • システムフィルターを使って一度に表示するゲーム数を減らしてください
  • 大量の操作（スクレイピング、クリーンアップ、インポート）の後は定期的にデータベースを最適化してください
  • キャンバステーマのエフェクトはハードウェアを自動検出します。低スペックデバイスは CPU フォールバックを使用します

セキュリティと免責事項

セキュリティのベストプラクティス

  • デフォルトパスワードを変更する — デフォルトの管理者パスワード（admin）は初回ログイン時にすぐ変更すべきです。少なくとも 8 文字の強力なパスワードを使ってください。
  • HTTPS リバースプロキシを使う — RetroDB は単体では TLS/SSL を提供しません。HTTPS を有効にしたリバースプロキシ（例: Nginx、Caddy、Traefik）の背後に配置し、クライアントとサーバー間の通信を暗号化してください。
  • ネットワークアクセスを制限する — RetroDB を公開インターネットに直接公開するのは避けてください。VPN を使うか、アクセスをローカルネットワークに制限してください。リモートアクセスが必要な場合は、認証付きのリバースプロキシを使ってください。
  • 定期的にバックアップを取る — 設定の組み込みバックアップ機能を使って定期的なデータベースバックアップを作成してください。バックアップはアプリケーションとは別の場所に保管してください。
  • RetroDB を最新に保つ — 新しいリリースを定期的に確認してください。セキュリティ修正と改善はアップデートに含まれます。
  • API キーを保護する — API キーは data/scraper_settings.json に保存されます。このファイルが公開アクセス可能でないことを確認してください。config.py やトークンファイルを決して共有しないでください。

組み込みのセキュリティ機能

  • パスワードハッシュ化 — 管理者パスワードは PBKDF2 でハッシュ化されます（平文で保存されることはありません）
  • ログインのレート制限 — ログインエンドポイントでのブルートフォース対策
  • パス検証 — すべてのファイル操作は safe_path と safe_filename ヘルパーを使い、ディレクトリトラバーサル攻撃を防止します
  • パラメーター化クエリ — すべてのデータベースクエリはパラメーター化されたステートメントを使い、SQL インジェクションを防止します
  • XSS 対策 — モーダルダイアログは安全な DOM 構築を使い、ユーザー入力はエスケープされます
  • 画像解凍爆弾対策 — 悪意ある画像によるメモリ枯渇を防ぐため、最大画像ピクセル数が制限されています
