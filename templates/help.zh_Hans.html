安装

系统要求

  • Python 3.8+ 及 pip
  • 网页浏览器（Chrome、Firefox、Safari、Edge）
  • 操作系统：Linux、Windows 10/11 或 macOS

快速安装

  1. 将 RetroDB 的 ZIP 解压到你选择的目录
  2. 在该目录中打开终端／命令提示符
  3. 运行：python install.py
  4. 启动服务器：
    • Linux：./start.sh
    • Windows：双击 start.bat
    • macOS：双击 start.command
  5. 在浏览器中打开 http://localhost:5000

图形界面安装程序

在 Linux 上，你还可以运行 ./setup.sh 来启动图形化安装向导。它会自动检查 Python／pip／tkinter，然后通过可视化的进度日志引导你完成每一个安装步骤。

install.py 的作用

  • 验证 Python 3.8+ 和 pip 是否可用
  • 从 requirements.txt 安装 Python 依赖项
  • 从示例模板创建 config.py
  • 创建所需的目录（数据库、日志、媒体文件夹）
  • 构建 CSS 和 JS 包

快速上手

首次设置

首次启动时，RetroDB 会显示一个设置向导，引导你完成以下步骤：

  1. 管理员账户 — 创建你的用户名和密码
  2. 游戏库路径 — 设置你的 ROM 目录
  3. ES-DE 集成 — 可选地关联 ES-DE 游戏列表和媒体
  4. API 密钥 — 可选地添加抓取器 API 密钥

完成向导后，点击仪表盘上的"扫描游戏库"以发现你的 ROM。

快速开始流程

  1. 扫描你的游戏库以导入 ROM
  2. 按系统浏览，或在游戏库中查看所有游戏
  3. 逐个抓取元数据，或使用批量抓取
  4. 使用标签、列表和愿望单进行整理
  5. 通过完成状态和成就追踪你的进度

ROM 游戏库结构

RetroDB 期望你的 ROM 在游戏库路径下按系统文件夹组织：

ROM Library/
  nes/
    Super Mario Bros. (USA).nes
  snes/
    Chrono Trigger (USA).sfc
  psx/
    Final Fantasy VII (USA)/
      Final Fantasy VII (USA) (Disc 1).chd
      Final Fantasy VII (USA) (Disc 2).chd

每个系统文件夹都应包含一个 ES-DE systeminfo.txt 文件，用于定义支持的文件扩展名。RetroDB 在扫描时读取该文件，以识别哪些文件是每个系统的有效 ROM。

提示：如果你已经用 ES-DE 抓取过，RetroDB 可以导入那些数据！ 在设置 → ES-DE 集成中，或在设置向导期间配置 ES-DE 路径。

平台说明

Linux

  • 已在 Ubuntu、Fedora、openSUSE 和 Arch Linux 上测试
  • ROM 工具需要：sudo apt install p7zip-full unrar mame-tools（Debian/Ubuntu），或你所用发行版的等效命令
  • 如果使用系统 Python，安装程序会自动处理 --break-system-packages
  • 支持 AMD GPU 的 ROCm GPU 加速（Real-ESRGAN 图片放大）

Windows

  • 从 python.org 下载 Python（安装时勾选 "Add to PATH"）
  • ROM 工具：安装 7-Zip、WinRAR 和 MAME（用于 chdman）
  • 使用 start.bat 启动，或从命令提示符运行 python app.py

macOS

  • 可通过 Homebrew 安装 Python 3：brew install python3
  • ROM 工具：brew install p7zip unrar rom-tools
  • 在 Finder 中双击 start.command 启动
  • 支持 Apple Silicon 的 CoreML 加速（Real-ESRGAN 图片放大）

工作原理

  • 主题会覆盖 CSS 颜色变量 — 所有 UI 元素都会自动适配
  • 画布效果包含自动硬件等级检测（高／中／低），在可用时使用 GPU 加速，在低端设备上回退到 CPU
  • 当标签页不可见时，效果会暂停以节省资源
  • Cyberpunk 烟雾状态在页面导航间保持，以实现无缝过渡
  • 细微的 CRT 风格扫描线叠加层会适配每种主题的配色方案
  • 你的主题偏好会保存在浏览器中，并在多次会话间保留

主题感知图标

通知图标、任务状态指示器和操作图标会自动适配当前主题。例如，成功图标在 Cyberpunk 上可能显示为绿色对勾，而在 Matrix 上则显示为其他符号，以匹配黑底绿字的美学。

API 密钥设置指南

API 密钥是可选的，但可启用丰富的元数据抓取和额外功能。在 设置 → 抓取 → API 密钥 中配置它们。

元数据抓取器

TheGamesDB

  1. 前往 api.thegamesdb.net/key.php
  2. 申请 API 密钥（免费，人工审核）— 你将收到一个 公钥（Public） 和一个 私钥（Private）
  3. 在 设置 → API 密钥 → TheGamesDB 中输入这两个密钥
  4. 公钥（按 IP 限速）用作抓取的主密钥
  5. 私钥（共享月度额度池）在公钥失败时用作后备

IGDB（通过 Twitch）

  1. 在 twitch.tv 创建一个 Twitch 账户
  2. 前往 dev.twitch.tv/console
  3. 注册一个新应用（任意名称、任意类别，OAuth 重定向填 http://localhost）
  4. 复制 Client ID 并生成一个 Client Secret
  5. 在 设置 → API 密钥 → IGDB 中输入两者

RAWG.io

  1. 前往 rawg.io/apidocs
  2. 点击 “Get API Key” 并创建一个账户
  3. 从仪表盘复制你的 API 密钥
  4. 在 设置 → API 密钥 → RAWG 中输入

免费额度：每月 20,000 次请求

ScreenScraper

  1. 在 screenscraper.fr 创建一个账户
  2. 在 设置 → API 密钥 → ScreenScraper 中输入你的用户名和密码

注意：ScreenScraper 根据你的账户等级设有每日请求限额。为数据库做贡献可提高你的限额。

成就与奖杯

RetroAchievements

  1. 在 retroachievements.org 创建一个账户
  2. 在你的个人资料上前往 设置 → API 密钥
  3. 复制你的 API 密钥
  4. 在 设置 → 账户 → RetroAchievements 中输入你的用户名和 API 密钥

Steam Web API

  1. 前往 steamcommunity.com/dev/apikey
  2. 注册一个 Steam Web API 密钥（需要 Steam 账户）
  3. 在设置中输入你的 API 密钥和 Steam ID（或个性化 URL）

用于 Steam 游戏库导入和成就追踪。

Xbox Live

Xbox 认证使用 OAuth2 — 无需 API 密钥。直接从 游戏导入 → Xbox 标签页用你的 Microsoft 账户登录。令牌会自动缓存并按需刷新。

设置

设置分为 6 个标签页，每个标签页都有多个子部分。

账户标签页

  • 我的资料 — 头像上传／移除、显示名称、角色信息、修改密码
  • RetroAchievements — 用于 RA 集成的用户名和 API 密钥
  • PSN — 用于 PlayStation Network 奖杯同步的 NPSSO cookie
  • 时区 — 设置你的时区，用于整个应用中的日期显示
  • 用户 — 用户管理：添加、编辑、删除用户并分配角色（仅限管理员）

游戏库标签页

  • 路径 — ROM 游戏库路径、数据库位置
  • 显示 — 主题选择、封面样式（2D/3D）、偏好的年龄分级系统、每页项目数
  • ROM 命名 — 冠词位置（前置／后置的 “The”）、地区选项列表、默认地区、命名规范
  • 备份 — 创建和恢复数据库备份

抓取标签页

  • ES-DE — 用于本地数据导入的 ES-DE 游戏列表和媒体路径
  • 抓取器 — 启用／禁用单个抓取器、拖放优先级排序、每个抓取器的限速设置
  • API 密钥 — 所有抓取器凭据（TGDB、IGDB、RAWG、ScreenScraper）、AI 提供商选择和模型选择（Gemini、OpenAI、Claude）

数据标签页

  • 统计 — 游戏库统计概览（游戏总数、系统数、存储占用）
  • 奖杯 — 用于本地 PS3 奖杯扫描的 RPCS3 奖杯路径配置
  • 下拉选项 — 自定义地区选项和整个应用中使用的其他下拉值
  • 规范化 — 类型和模式的规范化规则 — 添加自定义映射以统一抓取器输出

自定义标签页

  • 通知 — 通知超时偏好（成功、信息、警告、错误 — 每种均可独立配置）
  • 手柄 — 管理手柄库、为每个系统设置默认手柄、添加自定义手柄。在元数据获取期间，默认手柄会覆盖抓取／AI 的值。
  • 徽标 — 系统徽标自定义 — 导入系统徽标或从默认恢复

系统标签页

  • 维护 — 数据库优化（VACUUM/ANALYZE）、孤立媒体清理、清理缺失的 ROM、清除抓取数据、清除 CLZ 导入、批量图片标准化
  • 服务器 — 服务器配置（主机、端口、调试模式）
  • 日志 — 不同类别的日志级别设置
  • 故障排除 — 清除卡住的批量抓取、清除 RA 同步队列、清除 PSN 刷新、清除博物馆生成、重启服务器
提示：已禁用的抓取器不会在仪表盘上触发 “API 离线” 警告。如果你不使用某个抓取器，请在 设置 → 抓取 → 抓取器 中将其禁用，而不是删除 API 密钥。

抓取元数据

单个游戏抓取

  1. 打开任意游戏的详情弹窗（点击游戏卡片）
  2. 点击 "抓取"
  3. 如有需要，修改搜索标题
  4. 从匹配结果中选择正确的条目
  5. 点击 "应用"

混合抓取

RetroDB 会自动合并来自多个来源的数据，以最大化元数据的覆盖范围：

  • 文本元数据来自优先级最高的可用来源
  • 当主来源没有图片和媒体时，从次要来源获取
  • 跨抓取器自动补全空缺，以获得最大覆盖
  • 抓取过程中会根据游戏标题自动生成排序标题

媒体处理

  • 媒体字段（封面、3D 封面、截图、同人图、视频、说明书）在正常抓取时绝不会被替换 — 只在为空时填充
  • 截图始终是追加，绝不替换
  • 若要重新下载媒体，请先在编辑弹窗中清除现有图片，然后重新抓取
  • 完全重新抓取模式会覆盖此规则并替换所有内容
  • 失效的媒体引用（文件已删除但文件名仍在数据库中）会在抓取前自动清除，以便下载新的媒体
  • 下载的图片会自动标准化为目标尺寸（参见图片标准化）

抓取器优先级

在 设置 → 抓取 → 抓取器 中配置哪些抓取器优先运行以及哪些启用/禁用。拖放可重新排序优先级。禁用的抓取器在抓取时不会被尝试，也不会在仪表盘上触发 API 状态警告。

速率限制

每个抓取器都有可配置的速率限制，以防止 API 被限流。默认延迟设置得较为保守。降低延迟需自行承担风险 — 超出 API 速率限制可能导致相应服务对你临时封禁。

批量抓取

开始批量抓取

  1. 前往任意系统或游戏库页面
  2. 点击 "选择" 进入选择模式
  3. 逐个选择游戏，或使用快速选择：
    • 全选 — 所有可见的游戏
    • 选择未抓取 — 仅无元数据的游戏
  4. 选择模式：填充缺失 或 完全重新抓取
  5. 点击 "抓取所选"

控制

  • 暂停 / 继续 — 暂停或继续抓取
  • 取消 — 彻底停止
  • 后台 — 最小化并在抓取运行时继续浏览

提示通知

在后台运行时，会有一个常驻提示在所有页面上显示进度：

  • 当前游戏名称、进度计数和结果统计（成功、失败、已跳过）
  • 可从任意页面使用暂停/取消控制
  • 点击提示可返回抓取弹窗

队列系统

多个批量抓取会自动排队：

  • 在一个抓取运行时启动新的抓取 — 它会进入队列
  • 队列会在提示中显示待处理任务的数量
  • 任务会按顺序自动处理
  • 使用队列管理器可查看、重新排序或取消排队的任务

抓取选项

  • 仅填充缺失 — 只填充空的元数据字段，保留现有数据
  • 完全重新抓取 — 替换所有字段，包括媒体（下载新的图片和视频）
  • 检查 RetroAchievements — 抓取时也检查 RetroAchievements 成就集

任务恢复

如果 RetroDB 在任务运行期间被重启，被中断的任务会出现在仪表盘的恢复横幅中。点击单个任务上的 "继续" 或 "全部继续" 来重新启动它们。恢复后进度提示会立即出现。

AI 填充

它的作用

AI 填充使用大语言模型（Gemini、OpenAI 或 Claude）智能地填充缺失或不完整的游戏元数据。它比常规抓取更聪明，因为它利用关于游戏的上下文知识来提供抓取器可能没有的准确数据。

如何使用

  1. 打开游戏的详情弹窗（或完整详情页）
  2. 点击 "AI 填充"（需要在设置中配置 AI API 密钥）
  3. AI 分析游戏标题和系统，然后填充缺失的字段
  4. 查看结果 — 更改会自动保存

AI 填充可提供的内容

  • 类型、简介、开发商、发行商、发行日期
  • 玩家人数、游玩模式（单人、多人、合作等）
  • 战役信息和游戏结构
  • 全部 8 个分级系统（ESRB、PEGI、CERO、USK、ACB、FPB、GRAC、ClassInd）
  • 地区、系列、相似游戏
  • 手柄支持、存档类型
  • 视角（第一人称、俯视、横版卷轴等）、维度（2D、3D）
  • 版本信息、媒体评分和用户评分

智能填充逻辑

  • 空字段始终会被填充
  • 现有的用户数据绝不会被覆盖
  • 相似游戏始终会被刷新（此字段的 AI 数据更可靠）
  • 交叉映射的分级 — 如果已知一个分级系统，其他系统中空的分级会使用成熟度等级交叉映射自动填充
  • 填充时会自动生成排序标题
  • 玩家人数字段会规范化范围（例如 "1-4" 变为 4）

类型规范化

AI 填充使用带连字符名称的规范类型形式：

  • First-Person-Shooter、Shoot-em-up、Beat-em-up
  • Hack-n-Slash、Board-Card、Real-Time Strategy

要求

必须在 设置 → 抓取 → API 密钥 中配置至少一个 AI 提供商的 API 密钥。最便宜的模型层级（Gemini Flash Lite、GPT-4o Mini 或 Claude Haiku）对元数据的效果就很好。

搜索

游戏会在你滚动时以每批 100 个的方式加载。当你接近底部时会自动加载新页面。更改筛选器或搜索会立即重置并重新加载结果。

比较游戏

合集（标签、列表、愿望清单）

标签

创建自定义颜色的标签来整理你的游戏。标签的作用类似于标记 — 每款游戏可拥有多个标签，每个标签也可包含多款游戏。

  • 在标签页面创建带有自定义名称和颜色的标签
  • 通过游戏详情弹窗为游戏分配标签
  • 点击任意标签即可浏览带有该标签的所有游戏
  • 在标签管理页面编辑或删除标签

命名列表

创建可自定义排序的精选游戏列表。列表类似于播放列表 — 你可以精确控制游戏的顺序。

  • 在列表页面创建带有名称、描述和图标的列表
  • 通过游戏详情弹窗或列表页面将游戏添加到列表
  • 拖放以重新排列列表中的游戏
  • 按自定义顺序或字母顺序排序

愿望清单

追踪你想要获取的游戏，无论是实体版还是数字版。

  • 手动添加游戏，包含标题、系统、备注和优先级（1–5）
  • 愿望清单项目可在找到时链接到现有游戏库中的游戏
  • 按优先级（从高到低）排序，然后按添加日期排序
提示：标签适用于跨类别的标记（例如“收藏”“沙发合作”“待玩清单”），而列表适用于特定的精选合集（例如“十大 SNES 游戏”“待直播游戏”）。

游戏导入

从外部来源导入游戏合集。通过侧边栏中的游戏导入访问。所有导入类型都整合到一个带标签页的页面中。

CLZ Games 导入

从 CLZ Games 导入你的实体游戏收藏。

  1. 将你的 CLZ Games 收藏导出为 PDF
  2. 进入游戏导入 → CLZ 标签页
  3. 上传 PDF 文件
  4. 查看解析出的游戏
  5. 选择要导入的游戏

CLZ 导入与 ROM 游戏分开追踪（使用 clz_import/ 前缀），让你可以同时编目实体和数字收藏。CLZ 导入可从设置 → 系统 → 维护中完全清除。

Steam 导入

导入你的 Steam 游戏库并追踪成就。

  1. 在设置中配置你的 Steam Web API 密钥和 Steam ID
  2. 进入游戏导入 → Steam 标签页
  3. 点击“获取游戏库”以检索你的 Steam 游戏
  4. 选择要导入的游戏（会自动检测重复项）
  5. 导入的游戏会标记其 Steam App ID 以便追踪成就

Xbox 导入

通过 Microsoft 账户导入你的 Xbox 游戏库。

  1. 进入游戏导入 → Xbox 标签页
  2. 点击“登录”以使用你的 Microsoft 账户进行身份验证（OAuth2 流程）
  3. 系统会自动获取你的 Xbox 游戏历史记录
  4. 选择要导入的游戏，并检测重复项
  5. 导入的游戏会标记其 Xbox Title ID 以便追踪成就

Xbox 令牌缓存在 data/xbox_tokens.json 中并会自动刷新。

PSN 导入

导入你的 PlayStation Network 游戏库。

  1. 进入游戏导入 → PSN 标签页
  2. 输入你的 NPSSO cookie（获取方法请参阅 奖杯 → PSN 身份验证）
  3. 点击“获取游戏库”以检索你的 PSN 游戏
  4. 选择要导入的游戏

导入之后

  • 导入的游戏会带着平台专属的徽章出现在你的游戏库中
  • 使用批量抓取为导入的游戏获取元数据
  • 成就/奖杯追踪会自动链接到来源平台
  • 在游戏库中可使用来源筛选器筛选导入的游戏
提示：从任意平台导入游戏后，你可以像 ROM 游戏一样使用批量抓取为它们抓取元数据。导入的游戏也可以追踪各自平台的成就。

RetroAchievements

设置

  1. 在 retroachievements.org 创建账户
  2. 在你的个人资料设置中生成 API 密钥
  3. 在设置 → 账户 → RetroAchievements 中输入你的用户名和 API 密钥

成就页面

  • 系统标签页 — 按平台浏览成就（会记住你上次查看的标签页）
  • 字母导航 — 在每个系统标签页内按首字母跳转到游戏
  • 刷新进度 — 从 RetroAchievements 同步你的成就进度
  • 总体统计 — 所有系统中已获得的成就和点数
  • 单游戏进度 — 通过进度条查看每款游戏的完成百分比

同步队列

可以将多个系统的同步加入队列：

  • 点击任意系统的“刷新进度”以开始或排队同步
  • 如果已有同步正在运行，新请求会自动加入队列
  • 当前同步完成后，队列会自动处理
  • Toast 通知会显示当前进度和队列数量

PS3 / PSN 奖杯

  1. 在设置 → 数据 → 奖杯中设置你的 RPCS3 奖杯路径
  2. 点击“扫描奖杯”以导入已获得的奖杯
  3. 在 RPCS3 奖杯部分查看奖杯列表和各个奖杯详情

RPCS3 会从你的 RPCS3 用户目录读取奖杯 XML 数据，并自动将游戏与你的游戏库匹配。

PSN API 奖杯

从你的 PSN 账户同步 PlayStation Network 奖杯数据。

  1. 获取你的 NPSSO cookie（见下文）
  2. 在设置 → 账户 → PSN中输入它
  3. 你的 PSN 奖杯库会通过 PlayStation API 获取
  4. 查看每款游戏的奖杯进度，附已获得/总计数量
  5. 各个奖杯详情包括描述、稀有度和解锁时间戳

PSN 身份验证（NPSSO Cookie）

PSN 使用一种称为 NPSSO 令牌的特殊身份验证 cookie。获取方法如下：

  1. 打开网页浏览器并登录 store.playstation.com
  2. 登录后，导航至：https://ca.account.sony.com/api/v1/ssocookie
  3. 该页面会显示包含你的 NPSSO 令牌的 JSON
  4. 复制 npsso 值并粘贴到设置 → 账户 → PSN

身份验证完成后，RetroDB 会将访问令牌安全地缓存在自己的数据库中（按用户），并自动刷新它们 — 你无需在每次同步时重新粘贴 NPSSO。会话大约在两个月内保持有效，而且 RetroDB 现在还会在后台自动续期，因此在正常使用中你应该很少需要获取新的 NPSSO。

奖杯详情

  • 奖杯类型：铜杯、银杯、金杯、白金杯
  • 奖杯图标会被下载并缓存到本地
  • 每款游戏的完成百分比
  • 每个已获得奖杯的解锁时间戳

批量同步

通过后台任务一次性同步所有 PSN 游戏奖杯。进度会显示在 toast 通知中。速率限制（请求之间间隔 2.5 秒）可防止 PSN API 限流。

规范化

它的作用

将类型和游戏模式的值规范化为统一的标准形式。此过程在抓取和 AI 填充时自动进行，也可以手动应用到你现有的游戏库。

为何重要

不同的抓取源对同一事物使用不同的名称。规范化可确保整个游戏库的一致性：

  • platform → Platformer
  • fps, first person shooter → First-Person-Shooter
  • shoot 'em up, shmup → Shoot-em-up
  • beat 'em up, brawler → Beat-em-up
  • hack and slash → Hack-n-Slash
  • rts, real time strategy → Real-Time Strategy
  • board game, card game → Board-Card

自定义规则

你可以在 设置 → 数据 → 规范化 中添加自定义规范化规则。自定义规则会覆盖内置映射，让你定义自己偏好的类型和模式名称。规则存储在数据库中。

预览与应用

在应用规范化之前，你可以预览哪些游戏会受到影响以及将做出哪些更改。这让你可以在向游戏库提交更改之前进行审核。

图片标准化

它的作用

将所有游戏媒体标准化为统一的目标尺寸，让整个游戏库保持统一的外观。尺寸在目标值 80–120% 范围内的图片会被跳过。

工作原理

  • 放大 — 小于目标尺寸的图片会使用 Real-ESRGAN x4（通过 ONNX Runtime 的 AI 超分辨率）进行高质量放大，然后调整为精确的目标尺寸
  • 缩小 — 大于目标尺寸的图片会使用 Lanczos 滤波进行缩小，以获得清晰的效果
  • 阈值区间 — 处于目标值 80–120% 范围内的图片会保持不变，以避免不必要的重复处理

目标尺寸

媒体类型目标方法
封面高 1080px宽度按比例缩放
3D 封面高 1080px宽度按比例缩放（保留透明度）
截图高 1080px宽度按比例缩放
手柄最长边 1280px保留透明度（RGBA）
硬件最长边 1280px保留透明度（RGBA）
同人图已跳过不进行标准化（保持原始尺寸）

如何运行

  1. 前往 设置 → 系统 → 维护 或 ROM 工具 → 图片调整器
  2. 点击 “开始” 以启动批量标准化
  3. 任务在后台运行，通过弹出通知显示当前文件和统计信息
  4. 图片在抓取过程中也会自动标准化（新下载的内容会立即标准化）

硬件支持

Real-ESRGAN 模型会自动检测你的硬件并使用可用的最佳提供程序：

  • CUDA — NVIDIA GPU 加速
  • ROCm — AMD GPU 加速（针对 RX 6000 系列自动覆盖 gfx 版本）
  • CoreML — Apple Silicon 加速
  • CPU — 无 GPU 支持的系统的后备方案

ONNX 模型文件会在首次使用时从 Hugging Face 自动下载并缓存到本地。

  • 孤立媒体清理 — 查找并删除磁盘上没有对应数据库引用的图片文件（封面、截图、同人图）。删除前可先预览以确认。

  • 清除 CLZ 导入 — 删除所有 CLZ Games 导入记录（仅含元数据、无 ROM 文件的条目）。

数据库优化

  • 优化数据库 — 运行 SQLite VACUUM 和 ANALYZE，从已删除记录中回收存储空间并更新查询规划器统计信息。建议在大量删除或清理操作后运行。

批量图片标准化

将所有游戏图片标准化为目标尺寸。详情请参阅 图片标准化。

服务器管理

  • 重启服务器 — 优雅地重启应用程序（清理并退出）。位于 设置 → 系统 → 故障排除。

更新 RetroDB

如何更新

  1. 下载新的 RetroDB 版本
  2. 备份以下文件（它们包含你的个人数据）：
    • config.py（你的路径和 API 密钥）
    • data/settings.json（你的 UI 偏好设置）
    • data/scraper_settings.json（你的抓取源配置）
    • data/rom_tools_config.json（你的 ROM 工具偏好设置）
    • database/ 文件夹（你的游戏库数据库，以及已保存的 PSN/Xbox 登录令牌）
  3. 将新版本解压覆盖到现有安装之上
  4. 运行 python install.py 以安装任何新的依赖项
  5. 重启服务器

可安全覆盖的文件

需要保留的文件

数据库迁移

故障排除

常见问题

“未找到该系统的扩展名”

该系统文件夹需要一个有效的 ES-DE systeminfo.txt 文件，用于定义支持的 ROM 文件扩展名。请确保你的 ROM 目录结构符合 ES-DE 标准。

“API 连接失败”

  • 检查你的网络连接
  • 在 设置 → 抓取 → API 密钥 中核对 API 密钥
  • 如遇速率限制请稍候（部分 API 有每日/每小时上限）
  • 检查该抓取源是否已启用（已禁用的抓取源在仪表盘状态中显示“已禁用”）
  • 查看日志查看器以获取详细的错误信息

“批量抓取卡住”

前往 设置 → 系统 → 故障排除 → “清除卡住的批量抓取”。这会重置任务状态而不影响你的数据。

“RA 同步队列卡住”

从 设置 → 系统 → 故障排除 中清除 RetroAchievements 同步队列。

“PSN 同步卡住”

从 设置 → 系统 → 故障排除 中清除 PSN 刷新任务。

“博物馆生成卡住”

从 设置 → 系统 → 故障排除 中清除博物馆生成任务。

“数据库错误”

  1. 如有可能，先创建一个备份（设置 → 游戏库 → 备份）
  2. 尝试 设置 → 系统 → 维护 → 优化数据库
  3. 检查 database/ 目录的文件权限
  4. 最后手段：从备份恢复，或删除数据库并重新扫描

“图片未保存”

检查媒体目录的写入权限：chmod -R 755 static/images/

“页面缓慢或无响应”

  • 大型合集可能需要时间加载 — 无限滚动以每批 100 个的方式加载
  • 尝试刷新页面以清除累积的内存
  • 检查浏览器控制台是否有 JavaScript 错误
  • 尝试切换到画布效果更轻量的主题（例如 Amber 或 Elite）
  • 画布效果会自动检测硬件；低端设备会以降低的帧率使用 CPU 后备方案

仪表盘上的“中断的任务”横幅

如果 RetroDB 在任务运行时重启，它们会出现在一个恢复横幅中。逐个点击 “恢复” 或点击 “全部恢复” 以重新启动它们。点击 “忽略” 或 “全部忽略” 以清除它们。

“PSN 身份验证失败”

  • NPSSO 令牌会过期 — 请从 ca.account.sony.com/api/v1/ssocookie 生成一个新的
  • 在访问该 cookie 网址之前，请确保你已登录 store.playstation.com
  • RetroDB 会将你的 PSN 会话缓存约两个月，并且现在会在后台自动续期；如果仍然失效，只需在 设置 → 账户 → PSN 中粘贴一个新的 NPSSO 即可

“Xbox 身份验证失败”

  • 在 游戏导入 → Xbox 标签页中点击“登录”以重新验证
  • Xbox 令牌缓存在 data/xbox_tokens.json 中并会自动刷新

“图片放大错误”

  • Real-ESRGAN ONNX 模型会在首次使用时下载 — 请确保有网络访问权限
  • GPU 加速需要兼容的驱动程序（NVIDIA 用 CUDA，AMD 用 ROCm）
  • 如果 GPU 失败，系统会自动回退到 CPU 处理

性能提示

  • 保持浏览器为最新版本以获得最佳性能
  • 处理超大型合集时关闭其他浏览器标签页
  • 使用系统筛选器以减少一次显示的游戏数量
  • 在大量操作（抓取、清理、导入）后定期运行优化数据库
  • 画布主题效果会自动检测硬件；低端设备会使用 CPU 后备方案

安全与免责声明

安全最佳实践

  • 更改默认密码 — 默认的管理员密码（admin）应在首次登录时立即更改。请使用至少 8 个字符的强密码。
  • 使用 HTTPS 反向代理 — RetroDB 本身不提供 TLS/SSL。请将其置于反向代理（例如 Nginx、Caddy、Traefik）之后并启用 HTTPS，以加密客户端与服务器之间的流量。
  • 限制网络访问 — 避免将 RetroDB 直接暴露到公共互联网。请使用 VPN 或将访问限制在你的本地网络内。如果需要远程访问，请使用带身份验证的反向代理。
  • 保持定期备份 — 使用设置中内置的备份功能定期创建数据库备份。将备份存放在与应用程序不同的位置。
  • 保持 RetroDB 更新 — 定期检查新版本。更新中包含安全修复和改进。
  • 保护你的 API 密钥 — API 密钥存储在 data/scraper_settings.json 中。请确保该文件不会被公开访问。切勿分享你的 config.py 或令牌文件。

内置安全功能

  • 密码哈希 — 管理员密码使用 PBKDF2 进行哈希处理（绝不以明文存储）
  • 登录速率限制 — 对登录端点的暴力破解防护
  • 路径验证 — 所有文件操作都使用 safe_path 和 safe_filename 辅助函数以防止目录遍历攻击
  • 参数化查询 — 所有数据库查询都使用参数化语句以防止 SQL 注入
  • XSS 防护 — 模态对话框使用安全的 DOM 构造；用户输入会被转义
