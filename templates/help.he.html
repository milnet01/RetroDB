התקנה

דרישות מערכת

  • Python 3.8+ עם pip
  • דפדפן אינטרנט (Chrome, Firefox, Safari, Edge)
  • מערכת הפעלה: Linux, Windows 10/11, או macOS

התקנה מהירה

  1. חלצו את קובץ ה-ZIP של RetroDB לתיקייה לבחירתכם
  2. פתחו טרמינל/שורת פקודה בתיקייה זו
  3. הריצו: python install.py
  4. הפעילו את השרת:
    • Linux: ./start.sh
    • Windows: לחיצה כפולה על start.bat
    • macOS: לחיצה כפולה על start.command
  5. פתחו את http://localhost:5000 בדפדפן שלכם

מתקין גרפי

ב-Linux, ניתן גם להריץ ./setup.sh כדי להפעיל אשף התקנה גרפי. הוא בודק אוטומטית את קיומם של Python/pip/tkinter, ולאחר מכן מלווה אתכם בכל שלב בהתקנה עם יומן התקדמות חזותי.

מה install.py עושה

  • מוודא ש-Python 3.8+ ו-pip זמינים
  • מתקין תלויות Python מתוך requirements.txt
  • יוצר את config.py מתבנית הדוגמה
  • יוצר את התיקיות הנדרשות (בסיס נתונים, יומנים, תיקיות מדיה)
  • בונה את חבילות ה-CSS וה-JS

תחילת העבודה

הגדרה ראשונית

בהפעלה הראשונה, RetroDB מציג אשף הגדרה שמדריך אתכם דרך:

  1. חשבון מנהל — יצירת שם המשתמש והסיסמה שלכם
  2. נתיב הספרייה — הגדרת תיקיית ה-ROM שלכם
  3. שילוב ES-DE — קישור אופציונלי של רשימות משחקים ומדיה של ES-DE
  4. מפתחות API — הוספה אופציונלית של מפתחות API לגירוד נתונים

לאחר השלמת האשף, לחצו על "סרוק ספרייה" בלוח הבקרה כדי לגלות את ה-ROMs שלכם.

תהליך התחלה מהירה

  1. סרקו את הספרייה שלכם כדי לייבא ROMs
  2. עיינו לפי מערכת או צפו בכל המשחקים בספרייה
  3. גרדו מטא-נתונים בנפרד או השתמשו בגירוד קבוצתי
  4. ארגנו באמצעות תגיות, רשימות ורשימת משאלות
  5. עקבו אחר ההתקדמות שלכם עם סטטוס השלמה והישגים

מבנה ספריית ה-ROM

RetroDB מצפה שה-ROMs שלכם יהיו מאורגנים בתיקיות מערכת בתוך נתיב הספרייה שלכם:

ROM Library/
  nes/
    Super Mario Bros. (USA).nes
  snes/
    Chrono Trigger (USA).sfc
  psx/
    Final Fantasy VII (USA)/
      Final Fantasy VII (USA) (Disc 1).chd
      Final Fantasy VII (USA) (Disc 2).chd

כל תיקיית מערכת צריכה להכיל קובץ systeminfo.txt של ES-DE שמגדיר את סיומות הקבצים הנתמכות. RetroDB קורא אותו במהלך הסריקה כדי לזהות אילו קבצים הם ROMs תקינים עבור כל מערכת.

טיפ: אם כבר גרדתם נתונים עם ES-DE, RetroDB יכול לייבא את הנתונים האלה! הגדירו נתיבי ES-DE ב-הגדרות → שילוב ES-DE, או במהלך אשף ההגדרה.

הערות פלטפורמה

Linux

  • נבדק על Ubuntu, Fedora, openSUSE ו-Arch Linux
  • כלי ROM דורשים: sudo apt install p7zip-full unrar mame-tools (Debian/Ubuntu) או המקבילה עבור ההפצה שלכם
  • אם משתמשים ב-Python של המערכת, המתקין מטפל ב---break-system-packages אוטומטית
  • האצת GPU של ROCm נתמכת עבור מעבדי גרפיקה של AMD (הגדלת תמונות Real-ESRGAN)

Windows

  • הורידו את Python מ-python.org (סמנו "Add to PATH" במהלך ההתקנה)
  • כלי ROM: התקינו את 7-Zip, WinRAR, ו-MAME (עבור chdman)
  • השתמשו ב-start.bat כדי להפעיל, או הריצו python app.py משורת הפקודה

macOS

  • ניתן להתקין את Python 3 באמצעות Homebrew: brew install python3
  • כלי ROM: brew install p7zip unrar rom-tools
  • לחיצה כפולה על start.command ב-Finder כדי להפעיל
  • האצת CoreML נתמכת עבור Apple Silicon (הגדלת תמונות Real-ESRGAN)

לוח בקרה

ציון בריאות האוסף

טבעת התקדמות מעגלית מציגה את בריאות האוסף הכוללת שלכם כאחוז, מקודדת בצבע לפי איכות:

  • ירוק (80%+) — כיסוי מטא-דאטה מצוין
  • ציאן (60–79%) — כיסוי טוב עם מעט פערים
  • כתום (40–59%) — כיסוי בינוני, שקלו גירוד המוני
  • אדום (<40%) — פערי מטא-דאטה משמעותיים

מיני-טבעות פירוט למטה מציגות את שלמות תמונות הקופסה, שלמות התיאורים וכיסוי ההישגים.

סקירת סטטיסטיקות

כרטיסים למבט חטוף המציגים:

  • סך המערכות — מספר הפלטפורמות בספרייה שלכם
  • סך המשחקים — ספירת המשחקים הכוללת (לא כולל דיסקי בונוס)
  • מטא-דאטה חסרה — משחקים שטרם נגרדו
  • הושלם — משחקים עם מטא-דאטה גרודה

מקטעי פעילות אחרונה

מקטעים ניתנים לגלילה המציגים את הפעילות האחרונה שלכם (כל אחד מופיע רק כאשר יש משחקים רלוונטיים):

  • משחקים כעת — משחקים המסומנים כ"בתהליך"
  • נוספו לאחרונה — המשחקים האחרונים שנוספו לספרייה שלכם
  • נצפו לאחרונה — משחקים שפתחתם לאחרונה
  • נגרדו לאחרונה — משחקים עם מטא-דאטה שאוחזרה לאחרונה

פעולות מהירות

  • סריקת ספרייה — סרקו את תיקיות ה-ROM שלכם לאיתור משחקים חדשים
  • משחק אקראי — בחרו משחק אקראי מהספרייה שלכם

סטטוס API

מציג את סטטוס החיבור של כל הגרדים וממשקי ה-API המוגדרים. ממשקי API לא מקוונים או לא מוגדרים כראוי מציגים באנר אזהרה עם קישור להגדרות.

שחזור עבודות

אם RetroDB מופעלת מחדש בזמן שעבודות רקע פועלות (גירוד המוני, סנכרון RA, שינוי גודל תמונות וכו'), עבודות שהופרעו מופיעות בבאנר שחזור. אפשרויות:

  • המשך — הפעלה מחדש של עבודה בודדת שהופרעה
  • המשך הכל — הפעלה מחדש של כל העבודות שהופרעו
  • ביטול — הסרת עבודה בודדת מרשימת השחזור
  • ביטול הכל — הסרת כל העבודות שהופרעו

דפדפן מערכות

רשת המערכות

דף המערכות מציג את כל הפלטפורמות בספרייה שלכם ככרטיסים בפריסת רשת בנייה רספונסיבית. כל כרטיס מציג:

  • לוגו מערכת (ניתן להתאמה אישית בהגדרות → התאמה אישית → לוגואים)
  • ספירת ROM וספירת לא-גרודים
  • תג סוג מערכת — קונסולה, נייד, מחשב, ארקייד או מנוע
  • תגי תכונות — תמיכת RetroAchievements, גביעים מקומיים (RPCS3)

חלון מפרטי מערכת

לחצו על כפתור המידע בכל כרטיס מערכת כדי לצפות במפרטי חומרה מפורטים:

  • תמונת חומרה (תצלום קונסולה/מערכת)
  • יצרן ותאריך שחרור
  • CPU, GPU, RAM, VRAM
  • רזולוציה, עומק צבע, שבב קול
  • סוג מדיה (מחסנית, דיסק וכו')

  • סרגל תוצאות הסינון מציג "X מתוך Y מערכות"
  • הסינונים נשמרים בין טעינות דף מחדש באמצעות אחסון הפעלה

רשימת משחקים לכל מערכת

לחצו על כל כרטיס מערכת כדי לצפות במשחקים שלה. רשימת המשחקים לכל מערכת כוללת את אותן תכונות כמו דף הספרייה המלא — גלילה אינסופית, חיפוש, כל אפשרויות הסינון, בחירה המונית ומיון. כותרת מערכת מציגה את שם המערכת, ספירת המשחקים ותג סוג המערכת.

מדריך הגדרת מפתחות API

מפתחות API הם אופציונליים אך מאפשרים גירוד מטא-דאטה עשיר ותכונות נוספות. הגדירו אותם בהגדרות → גירוד → מפתחות API.

גרדי מטא-דאטה

TheGamesDB

  1. עברו אל api.thegamesdb.net/key.php
  2. בקשו מפתחות API (חינמי, מאושר ידנית) — תקבלו מפתח ציבורי ומפתח פרטי
  3. הזינו את שני המפתחות בהגדרות → מפתחות API → TheGamesDB
  4. המפתח הציבורי (מגבלת קצב לכל IP) משמש כמפתח הראשי לגירוד
  5. המפתח הפרטי (מאגר חודשי משותף) משמש כגיבוי אם המפתח הציבורי נכשל

IGDB (דרך Twitch)

  1. צרו חשבון Twitch בtwitch.tv
  2. עברו אל dev.twitch.tv/console
  3. רשמו אפליקציה חדשה (כל שם, כל קטגוריה, http://localhost כהפניית OAuth)
  4. העתיקו את הClient ID וצרו Client Secret
  5. הזינו את שניהם בהגדרות → מפתחות API → IGDB

RAWG.io

  1. עברו אל rawg.io/apidocs
  2. לחצו על "Get API Key" וצרו חשבון
  3. העתיקו את מפתח ה-API שלכם מלוח הבקרה
  4. הזינו אותו בהגדרות → מפתחות API → RAWG

שכבה חינמית: 20,000 בקשות לחודש

ScreenScraper

  1. צרו חשבון בscreenscraper.fr
  2. הזינו את שם המשתמש והסיסמה שלכם בהגדרות → מפתחות API → ScreenScraper

הערה: ל-ScreenScraper יש מגבלות בקשות יומיות בהתבסס על רמת החשבון שלכם. תרומה למסד הנתונים מגדילה את המגבלות שלכם.

הגדרות

ההגדרות מאורגנות ב-6 לשוניות, כל אחת עם מספר תת-מקטעים.

לשונית חשבון

  • הפרופיל שלי — העלאת/הסרת אווטאר, שם תצוגה, מידע על תפקיד, שינוי סיסמה
  • RetroAchievements — שם משתמש ומפתח API לשילוב RA
  • PSN — עוגיית NPSSO לסנכרון גביעי PlayStation Network
  • אזור זמן — הגדירו את אזור הזמן שלכם לתצוגת תאריכים בכל האפליקציה
  • משתמשים — ניהול משתמשים: הוספה, עריכה, מחיקת משתמשים והקצאת תפקידים (מנהל בלבד)

לשונית ספרייה

  • נתיבים — נתיב ספריית ה-ROM, מיקום מסד הנתונים
  • תצוגה — בחירת ערכת נושא, סגנון תמונת קופסה (2D/3D), מערכת דירוג גיל מועדפת, פריטים לכל דף
  • מתן שמות ל-ROM — מיקום תווית ("The" מוביל/נגרר), רשימת אפשרויות אזור, אזור ברירת מחדל, מוסכמות מתן שמות
  • גיבוי — יצירה ושחזור של גיבויי מסד הנתונים

לשונית גירוד

  • ES-DE — נתיבי gamelist ומדיה של ES-DE לייבוא נתונים מקומי
  • גרד — הפעלה/השבתה של גרדים בודדים, סידור עדיפויות בגרירה ושחרור, הגדרות מגבלת קצב לכל גרד
  • מפתחות API — כל אישורי הגרדים (TGDB, IGDB, RAWG, ScreenScraper), בחירת ספק AI ובחירת מודל (Gemini, OpenAI, Claude)

לשונית נתונים

  • סטטיסטיקות — סקירת סטטיסטיקות הספרייה (סך משחקים, מערכות, שימוש באחסון)
  • גביעים — הגדרת נתיב גביעי RPCS3 לסריקת גביעי PS3 מקומיים
  • תפריטים נפתחים — התאמה אישית של אפשרויות אזור וערכי תפריטים נפתחים אחרים בשימוש ברחבי האפליקציה
  • נרמול — כללי נרמול ז'אנר ומצבים — הוסיפו מיפויים מותאמים אישית כדי לתקנן את פלט הגרד

לשונית התאמה אישית

  • התראות — העדפות פסק זמן להתראות (הצלחה, מידע, אזהרה, שגיאה — כל אחת ניתנת להגדרה בנפרד)
  • בקרים — ניהול ספריית הבקרים, הגדרת בקרי ברירת מחדל לכל מערכת, הוספת בקרים מותאמים אישית. בקרי ברירת מחדל דורסים ערכי גירוד/AI במהלך אחזור מטא-דאטה.
  • לוגואים — התאמה אישית של לוגו מערכת — ייבוא לוגואי מערכת או רענון מברירות המחדל

לשונית מערכת

  • תחזוקה — אופטימיזציית מסד נתונים (VACUUM/ANALYZE), ניקוי מדיה יתומה, ניקוי ROM חסרים, ניקוי נתונים גרודים, ניקוי ייבוא CLZ, תקנון תמונות המוני
  • שרת — הגדרת שרת (מארח, פורט, מצב ניפוי באגים)
  • רישום — הגדרות רמת רישום לקטגוריות שונות
  • פתרון תקלות — ניקוי גירוד המוני תקוע, ניקוי תור סנכרון RA, ניקוי רענון PSN, ניקוי יצירת מוזיאון, הפעלה מחדש של השרת
טיפ: גרדים מושבתים לא יפעילו אזהרות "API לא מקוון" בלוח הבקרה. אם אינכם משתמשים בגרד, השביתו אותו בהגדרות → גירוד → גרד במקום למחוק את מפתח ה-API.

  4. בחרו את התוצאה הנכונה מבין ההתאמות

איסוף היברידי

RetroDB משלב אוטומטית נתונים ממספר מקורות כדי למקסם את כיסוי המטא-נתונים:

  • מטא-נתוני טקסט מהמקור הזמין בעל העדיפות הגבוהה ביותר
  • תמונות ומדיה ממקורות משניים כשלמקור העיקרי אין אותם
  • מילוי פערים אוטומטי בין המאספים לכיסוי מרבי
  • כותרת המיון נוצרת אוטומטית מכותרת המשחק במהלך האיסוף

טיפול במדיה

  • שדות מדיה (עטיפה, עטיפת תלת-ממד, צילומי מסך, אמנות אוהדים, וידאו, מדריך) לעולם אינם מוחלפים במהלך איסוף רגיל — רק ממולאים כשהם ריקים
  • צילומי מסך תמיד מתווספים, לעולם לא מוחלפים
  • כדי להוריד מדיה מחדש, נקו תחילה את התמונה הקיימת בחלון העריכה, ואז אספו מחדש
  • מצב איסוף מחדש מלא עוקף זאת ומחליף את הכול
  • הפניות מדיה מיושנות (הקובץ נמחק אך שם הקובץ עדיין במסד הנתונים) מנוקות אוטומטית לפני האיסוף כדי שניתן יהיה להוריד מדיה חדשה
  • תמונות שהורדו מתוקננות אוטומטית לגדלי היעד (ראו תקנון תמונות)

עדיפות מאספים

הגדירו אילו מאספים פועלים ראשונים ואילו מופעלים/מושבתים בהגדרות → איסוף → מאסף. גררו ושחררו כדי לשנות את סדר העדיפות. מאספים מושבתים לא ינוסו במהלך האיסוף ולא יפעילו אזהרות מצב API בלוח הבקרה.

הגבלת קצב

לכל מאסף יש הגבלות קצב הניתנות להגדרה כדי למנוע חנק של ה-API. השהיות ברירת המחדל מוגדרות בזהירות. הפחיתו את ההשהיות על אחריותכם — חריגה ממגבלות הקצב של ה-API עלולה לגרום לחסימות זמניות מהשירות הרלוונטי.

איסוף בכמות

התחלת איסוף בכמות

  1. עברו לעמוד מערכת או ספרייה כלשהו
  2. לחצו על "Select" כדי להיכנס למצב בחירה
  3. בחרו משחקים בנפרד או השתמשו בבחירה מהירה:
    • בחר הכול — כל המשחקים הנראים
    • בחר לא-נאספים — רק משחקים ללא מטא-נתונים
  4. בחרו מצב: מילוי חסרים או איסוף מחדש מלא
  5. לחצו על "Scrape Selected"

פקדים

  • השהה / המשך — השהו או המשיכו את האיסוף
  • ביטול — עצירה מוחלטת
  • רקע — מזערו והמשיכו לגלוש בזמן שהאיסוף רץ

התראת טוסט

כשהאיסוף רץ ברקע, טוסט קבוע מציג את ההתקדמות בכל העמודים:

  • שם המשחק הנוכחי, ספירת התקדמות, וסטטיסטיקות תוצאה (הצליחו, נכשלו, דולגו)
  • פקדי השהיה/ביטול זמינים מכל עמוד
  • לחצו על הטוסט כדי לחזור לחלון האיסוף

מערכת תור

מספר איסופים בכמות נכנסים לתור אוטומטית:

  • התחילו איסוף חדש בזמן שאחד רץ — הוא ייכנס לתור
  • התור מוצג בטוסט עם ספירת המשימות הממתינות
  • המשימות מעובדות אוטומטית לפי הסדר
  • השתמשו במנהל התור כדי לצפות, לסדר מחדש, או לבטל משימות בתור

אפשרויות איסוף

  • מילוי חסרים בלבד — מלאו רק שדות מטא-נתונים ריקים, תוך שמירה על הנתונים הקיימים
  • איסוף מחדש מלא — החליפו את כל השדות כולל מדיה (מוריד תמונות וסרטונים חדשים)
  • בדוק RetroAchievements — בדקו גם קיום סטים של הישגי RetroAchievements במהלך האיסוף

שחזור משימות

אם RetroDB מופעל מחדש בזמן שמשימה רצה, משימות שנקטעו מופיעות בכרזת שחזור בלוח הבקרה. לחצו על "Resume" על משימות בודדות או על "Resume All" כדי להפעילן מחדש. טוסט ההתקדמות מופיע מיד לאחר החידוש.

מילוי AI

מה זה עושה

מילוי AI משתמש במודל שפה גדול (Gemini, OpenAI, או Claude) כדי למלא בחוכמה מטא-נתונים חסרים או לא שלמים של משחק. הוא חכם יותר מאיסוף רגיל כי הוא משתמש בידע הקשרי על המשחק כדי לספק נתונים מדויקים שלמאספים אולי אין.

איך להשתמש

  1. פתחו את חלון הפרטים של משחק (או את עמוד הפרטים המלא)
  2. לחצו על "AI Fill" (דורש מפתח API של AI המוגדר בהגדרות)
  3. ה-AI מנתח את כותרת המשחק והמערכת, ואז ממלא שדות חסרים
  4. סקרו את התוצאות — השינויים נשמרים אוטומטית

מה מילוי AI יכול לספק

  • ז'אנר, תיאור, מפתח, מפיץ, תאריך יציאה
  • שחקנים, מצבי משחק (יחיד, מרובה, שיתופי, וכו')
  • מידע על קמפיין ומבנה משחק
  • כל 8 מערכות דירוג הגיל (ESRB, PEGI, CERO, USK, ACB, FPB, GRAC, ClassInd)
  • אזור, סדרה, משחקים דומים
  • תמיכה בבקרים, סוג שמירה
  • נקודת מבט (גוף ראשון, מלמעלה, גלילה צדדית, וכו'), ממד (2D, 3D)
  • מידע על מהדורה, ציוני מבקרים ומשתמשים

לוגיקת מילוי חכם

  • שדות ריקים תמיד ממולאים
  • נתוני משתמש קיימים לעולם לא נדרסים
  • משחקים דומים תמיד מרועננים (נתוני AI אמינים יותר לשדה זה)
  • דירוגים ממופים-צולב — אם מערכת דירוג אחת ידועה, דירוגים ריקים במערכות אחרות ממולאים אוטומטית באמצעות מיפוי-צולב לפי דרג בגרות
  • כותרת מיון נוצרת אוטומטית בעת המילוי
  • שדה שחקנים מנרמל טווחים (למשל "1-4" הופך ל-4)

נרמול ז'אנרים

מילוי AI משתמש בצורות ז'אנר קנוניות עם שמות מקופפים במקף:

  • First-Person-Shooter, Shoot-em-up, Beat-em-up
  • Hack-n-Slash, Board-Card, Real-Time Strategy

דרישות

יש להגדיר לפחות מפתח API אחד של ספק AI בהגדרות → איסוף → מפתחות API. דרג המודל הזול ביותר (Gemini Flash Lite, GPT-4o Mini, או Claude Haiku) עובד היטב עבור מטא-נתונים.

פרטי משחק

חלון פרטי המשחק

לחיצה על כרטיס משחק כלשהו פותחת חלון פרטים עם תצוגה מהירה מהמטמון. החלון מציג:

  • עטיפה (דו-ממד ותלת-ממד), רקע אמנות אוהדים
  • תיאור ומידע על היציאה
  • תגי מפתח, מפיץ, וז'אנר
  • שחקנים, מצבי משחק, מבנה משחק
  • תמונת דירוג גיל (מהמערכת המועדפת עליכם, עם נפילת מיפוי-צולב)
  • גלריית צילומי מסך עם ניווט מקלדת (← →)
  • סרטון טריילר (אם זמין)
  • הערכות זמן משחק של HLTB (עלילה ראשית, ראשית + תוספות, השלמה מלאה)
  • מצב והתקדמות RetroAchievements
  • משחקים דומים (קישורים לחיצים)
  • פרטי תמיכה בבקרים
  • תגיות המשויכות למשחק
  • גודל קובץ ונתיב ROM

עמוד פרטי המשחק המלא

לחצו על קישור כותרת המשחק או נווטו מפירורי הלחם כדי לצפות בעמוד פרטי המשחק המלא. תכונות נוספות בעמוד המלא כוללות:

  • כותרת רקע של אמנות אוהדים עם ניווט פירורי לחם
  • תגי ייבוא פלטפורמה — מציג ייבוא CLZ, ייבוא Steam, ייבוא Xbox, או ייבוא PSN עם לוגואים של הפלטפורמה כשרלוונטי
  • מחוון דיסק בונוס — מציג תג וקישור "חלק מ:" למשחק ההורה עם תמונה ממוזערת
  • כפתור מחיקה — הסירו את המשחק ממסד הנתונים (עם אישור)
  • כפתור ניקוי — נקו את כל המטא-נתונים שנאספו תוך שמירת רשומת ה-ROM

חלון עריכה

לחצו על עריכה (או הקישו e) כדי לפתוח את חלון העריכה, המאורגן לסעיפים:

  • זהות — כותרת, כותרת מיון (נוצרת אוטומטית אך ניתנת לעריכה), סדרה, מהדורה
  • מידע על יציאה — תאריך יציאה, אזור (מתפריט נפתח הניתן להגדרה)
  • משחקיות — ז'אנר (תגי בחירה מרובה), מצבים, מבנה משחק, שחקנים, מפתח, מפיץ
  • טכני — בקרים (בחירה מרובה), סוג שמירה, נקודת מבט (רב-ערכי), ממד (רב-ערכי)
  • דירוגי גיל — כל 8 מערכות הדירוג עם תמונות דירוג רשמיות ומיפוי-צולב אוטומטי. שינוי דירוג אחד ממלא אוטומטית דירוגים ריקים במערכות אחרות.
  • ציונים — ציון מבקרים, ציון משתמשים
  • תיאור — טקסט תיאור המשחק
  • תמונות מותאמות — העלו עטיפה מותאמת (דו-ממד), עטיפת תלת-ממד, ואמנות אוהדים. נקו תמונות קיימות כדי לאפשר איסוף מחדש.
  • וידאו / טריילר — העלו או קשרו טריילר וידאו

פעולות מהירות

  • עריכה — פתחו את חלון העריכה (e)
  • איסוף — משכו מטא-נתונים ממקורות איסוף (s)
  • מילוי AI — מלאו שדות חסרים עם AI (דורש מפתח API של AI)
  • בדוק RA — חפשו סט הישגים של RetroAchievements

השוואת משחקים

מה זה עושה

השוואה זה-לצד-זה של המטא-נתונים של שני משחקים בתצוגת טבלה. שימושי לבדיקת איכות המטא-נתונים, איתור כפילויות, או השוואת גרסאות של אותו משחק בין מערכות.

איך משתמשים

  1. עברו אל השוואה (נגיש מעמוד הספרייה)
  2. חפשו ובחרו את המשחק הראשון
  3. חפשו ובחרו את המשחק השני
  4. עיינו בטבלת ההשוואה — ההבדלים מודגשים

שדות מושווים

מערכת, מפתח, מוציא לאור, תאריך יציאה, ז'אנר, זכיינות, אזור, שחקנים, מצבים, נקודת מבט, ממד, כל 8 דירוגי הגיל, דירוג משתמשים, ציון מבקרים, הערכות זמן משחק, תמיכת בקרים, סוג שמירה, גודל קובץ, משחקים דומים, תיאור, ועוד.

אוספים (תגיות, רשימות, רשימת משאלות)

תגיות

צרו תגיות מותאמות אישית עם קודי צבע כדי לארגן את המשחקים שלכם. תגיות עובדות כמו תוויות — לכל משחק יכולות להיות מספר תגיות, וכל תגית יכולה להכיל מספר משחקים.

  • צרו תגיות עם שמות וצבעים מותאמים אישית מעמוד תגיות
  • שייכו תגיות למשחקים דרך חלון פרטי המשחק
  • לחצו על תגית כלשהי כדי לעיין בכל המשחקים עם אותה תגית
  • ערכו או מחקו תגיות מעמוד ניהול התגיות

רשימות בעלות שם

צרו רשימות משחקים אוצרות עם סדר מותאם אישית. רשימות הן כמו רשימות השמעה — אתם שולטים בסדר המדויק של המשחקים.

  • צרו רשימות עם שם, תיאור וסמל מעמוד רשימות
  • הוסיפו משחקים לרשימות דרך חלון פרטי המשחק או עמוד הרשימה
  • גררו ושחררו כדי לסדר מחדש משחקים בתוך רשימה
  • מיינו לפי סדר מותאם אישית או לפי סדר אלפביתי

רשימת משאלות

עקבו אחר משחקים שברצונכם לרכוש, בין אם פיזיים או דיגיטליים.

  • הוסיפו משחקים ידנית עם כותרת, מערכת, הערות ועדיפות (1–5)
  • ניתן לקשר פריטים ברשימת המשאלות למשחקים קיימים בספרייה אם נמצאו
  • ממוינים לפי עדיפות (הגבוהה ביותר קודם), ואז לפי תאריך ההוספה
טיפ: השתמשו בתגיות עבור תוויות רוחביות (למשל "מועדפים", "קו-אופ בסלון", "ערימת המתנה") וברשימות עבור אוספים אוצרים ספציפיים (למשל "10 משחקי SNES המובילים", "משחקים לשידור").

ייבוא משחקים

ייבאו אוספי משחקים ממקורות חיצוניים. גישה דרך ייבוא משחקים בסרגל הצד. כל סוגי הייבוא מאוחדים לעמוד יחיד עם לשוניות.

ייבוא CLZ Games

ייבאו את אוסף המשחקים הפיזי שלכם מ-CLZ Games.

  1. ייצאו את אוסף CLZ Games שלכם כקובץ PDF
  2. עברו אל ייבוא משחקים → לשונית CLZ
  3. העלו את קובץ ה-PDF
  4. עיינו במשחקים שנותחו
  5. בחרו אילו משחקים לייבא

ייבוא CLZ נעקב בנפרד ממשחקי ROM (באמצעות קידומת clz_import/), ומאפשר לכם לקטלג אוספים פיזיים ודיגיטליים כאחד. ניתן לנקות את כל ייבוא ה-CLZ מ-הגדרות → מערכת → תחזוקה.

ייבוא Steam

ייבאו את ספריית משחקי ה-Steam שלכם ועקבו אחר הישגים.

  1. הגדירו את מפתח ה-Steam Web API ואת ה-Steam ID שלכם בהגדרות
  2. עברו אל ייבוא משחקים → לשונית Steam
  3. לחצו על "אחזר ספרייה" כדי לקבל את משחקי ה-Steam שלכם
  4. בחרו משחקים לייבוא (כפילויות מזוהות אוטומטית)
  5. משחקים מיובאים מתויגים עם ה-Steam App ID שלהם למעקב הישגים

ייבוא Xbox

ייבאו את ספריית משחקי ה-Xbox שלכם דרך חשבון Microsoft.

  1. עברו אל ייבוא משחקים → לשונית Xbox
  2. לחצו על "התחבר" כדי לאמת מול חשבון ה-Microsoft שלכם (תהליך OAuth2)
  3. היסטוריית הכותרים של ה-Xbox שלכם מאוחזרת אוטומטית
  4. בחרו משחקים לייבוא עם זיהוי כפילויות
  5. משחקים מיובאים מתויגים עם ה-Xbox Title ID שלהם למעקב הישגים

אסימוני Xbox נשמרים במטמון ב-data/xbox_tokens.json ומרועננים אוטומטית.

ייבוא PSN

ייבאו את ספריית משחקי ה-PlayStation Network שלכם.

  1. עברו אל ייבוא משחקים → לשונית PSN
  2. הזינו את עוגיית ה-NPSSO שלכם (ראו גביעים → אימות PSN להסבר כיצד להשיג אותה)
  3. לחצו על "אחזר ספרייה" כדי לקבל את משחקי ה-PSN שלכם
  4. בחרו משחקים לייבוא

לאחר הייבוא

  • משחקים מיובאים מופיעים בספרייה שלכם עם תגי פלטפורמה ייחודיים
  • השתמשו בגירוד מרובה כדי לאחזר מטא-נתונים למשחקים המיובאים
  • מעקב הישגים/גביעים מקושר אוטומטית לפלטפורמת המקור
  • ניתן לסנן משחקים מיובאים בספרייה באמצעות מסנן המקור
טיפ: לאחר ייבוא משחקים מכל פלטפורמה, תוכלו לגרד עבורם מטא-נתונים באמצעות גירוד מרובה, בדיוק כמו משחקי ROM. משחקים מיובאים יכולים גם לעקוב אחר הישגים מהפלטפורמות שלהם בהתאמה.

RetroAchievements

הגדרה

  1. צרו חשבון ב-retroachievements.org
  2. צרו מפתח API בהגדרות הפרופיל שלכם
  3. הזינו את שם המשתמש ומפתח ה-API שלכם בהגדרות → חשבון → RetroAchievements

עמוד ההישגים

  • לשוניות מערכת — עיינו בהישגים לפי פלטפורמה (זוכר את הלשונית שצפיתם בה לאחרונה)
  • ניווט אלפביתי — קפצו למשחקים לפי אות ראשונה בתוך כל לשונית מערכת
  • רענון התקדמות — סנכרנו את התקדמות ההישגים שלכם מ-RetroAchievements
  • סטטיסטיקה כוללת — הישגים ונקודות שהושגו בכל המערכות
  • התקדמות לכל משחק — ראו אחוז השלמה לכל משחק עם סרגלי התקדמות

תור סנכרון

ניתן להוסיף לתור מספר סנכרוני מערכת:

  • לחצו על "רענון התקדמות" בכל מערכת כדי להתחיל או להוסיף סנכרון לתור
  • אם סנכרון כבר פועל, בקשות חדשות מתווספות לתור אוטומטית
  • התור מעובד אוטומטית כשהסנכרון הנוכחי מסתיים
  • הודעת טוסט מציגה את ההתקדמות הנוכחית וספירת התור

מציאת משחקים עם הישגים

  • מסנן ספרייה — השתמשו במסנן "יש RA" כדי להציג רק משחקים עם הישגים
  • בדיקה ל-RA — בחלונות פרטי המשחק, לחצו כדי לחפש סט הישגים
  • גירוד מרובה — הפעילו את אפשרות "בדוק RA" כדי למצוא הישגים במהלך הגירוד
  • עבודת רענון RA — סרקו את כל המשחקים במערכת כדי לזהות אילו תומכים ב-RA

פרטים ברמת המשחק

לחצו על משחק כלשהו בעמוד ההישגים כדי לראות מידע מפורט על הישגים לכל משחק, כולל שמות הישגים בודדים, תיאורים, ערכי נקודות וסטטוס השגה.

הערה: "רענון התקדמות" מסנכרן את ההתקדמות שלכם עבור משחקים שכבר מקושרים ל-RetroAchievements. כדי למצוא סטים חדשים של הישגים, השתמשו ב-"בדיקה ל-RA" בחלונות פרטי המשחק או הפעילו זאת במהלך גירוד מרובה.

גביעי PS3 / PSN

גביעים מקומיים של RPCS3

עקבו אחר גביעים שהושגו במשחקי PS3 דרך אמולטור ה-RPCS3.

  1. הגדירו את נתיב גביעי ה-RPCS3 שלכם ב-הגדרות → נתונים → גביעים
  2. לחצו על "סרוק גביעים" כדי לייבא גביעים שהושגו
  3. צפו ברשימות גביעים ובפרטי גביעים בודדים בקטע גביעי RPCS3

RPCS3 קורא את נתוני ה-XML של הגביעים מספריית המשתמש של ה-RPCS3 שלכם ומתאים משחקים לספרייה שלכם אוטומטית.

גביעי PSN API

סנכרנו את נתוני גביעי ה-PlayStation Network שלכם מחשבון ה-PSN שלכם.

  1. השיגו את עוגיית ה-NPSSO שלכם (ראו למטה)
  2. הזינו אותה ב-הגדרות → חשבון → PSN
  3. ספריית גביעי ה-PSN שלכם מאוחזרת דרך ה-PlayStation API
  4. צפו בהתקדמות הגביעים לכל משחק עם ספירות שהושגו/כולל
  5. פרטי גביעים בודדים כוללים תיאור, נדירות וחותמות זמן של פתיחה

אימות PSN (עוגיית NPSSO)

PSN משתמשת בעוגיית אימות מיוחדת בשם אסימון NPSSO. כדי להשיג אותה:

  1. פתחו דפדפן והתחברו אל store.playstation.com
  2. לאחר ההתחברות, נווטו אל: https://ca.account.sony.com/api/v1/ssocookie
  3. העמוד יציג JSON המכיל את אסימון ה-NPSSO שלכם
  4. העתיקו את הערך npsso והדביקו אותו בהגדרות → חשבון → PSN

לאחר האימות, RetroDB שומר את אסימוני הגישה במטמון בצורה מאובטחת במסד הנתונים שלו (לכל משתמש) ומרענן אותם אוטומטית — אינכם מדביקים שוב את ה-NPSSO בכל סנכרון. הסשן נשאר תקף למשך כחודשיים, ו-RetroDB כעת גם מחדש אותו אוטומטית ברקע, כך שבשימוש רגיל תזדקקו לעיתים רחוקות ל-NPSSO חדש.

פרטי גביעים

  • סוגי גביעים: ארד, כסף, זהב, פלטינה
  • סמלי גביעים מורדים ונשמרים במטמון מקומי
  • אחוז השלמה לכל משחק
  • חותמות זמן של פתיחה לכל גביע שהושג

סנכרון מרובה

סנכרנו את כל גביעי משחקי ה-PSN בבת אחת דרך עבודת רקע. ההתקדמות מוצגת בהודעת טוסט. הגבלת קצב (2.5 שניות בין בקשות) מונעת חנק של ה-PSN API.

מוזיאון

מה זה

אנציקלופדיה אינטראקטיבית של מערכות משחק המאורגנת לפי דור. למד על ההיסטוריה, המפרטים והמשחקים הבולטים של כל פלטפורמה באוסף שלך.

עמוד הנחיתה

עמוד הנחיתה של המוזיאון מציג ציר זמן של מערכות משחק המקובצות לפי דור (דור 1–9, מכשירים ניידים, ארקייד, מחשבים). כל כרטיס מערכת מציג את תמונת החומרה ואת מספר המשחקים מהספרייה שלך.

עמודי פירוט מערכת

לחץ על מערכת כלשהי כדי לצפות בעמוד המוזיאון שלה, הכולל:

  • תמונת חומרה — צילום של הקונסולה/המערכת
  • מפרטים טכניים — CPU, GPU, RAM, רזולוציה, סוג מדיה
  • היסטוריה — נרטיב שנוצר על ידי AI על הפיתוח, ההשקה והמורשת של המערכת
  • 10 המשחקים המובילים — הכותרים הבולטים ביותר של המערכת (מציוני מבקרים והצעות AI)
  • גלריית בקרים — תמונות של בקרי המערכת עם תיאורים

יצירת תוכן באמצעות AI

תוכן המוזיאון נוצר באמצעות AI (Gemini, OpenAI, או Claude). ניתן ליצור תוכן עבור:

  • מערכת בודדת — לחץ על "Generate" בעמוד המוזיאון של כל מערכת
  • יצירה מרוכזת — צור תוכן עבור כל המערכות בבת אחת מעמוד הנחיתה (רץ כמשימת רקע עם התקדמות בהודעות קופצות)

תמונות בקרים

ניתן להוסיף תמונות בקרים באמצעות:

  • חיפוש תמונות — חפש צילומי בקרים באמצעות Bing Image Search. התוצאות מדורגות לפי רלוונטיות (שם הבקר + יצרן + וריאציות מערכת).
  • העלאה ידנית — העלה תמונות בקרים משלך
  • הסרת רקע — הסר רקעים אוטומטית באמצעות AI מקומי (ספריית rembg) לתמונות בקרים שקופות על כל רקע
  • הפצת תמונות — כאשר נמצאת תמונת בקר, היא משותפת אוטומטית עם אותו בקר במערכות אחרות (בקרים אחים)
  • שליפה מרוכזת — שלוף תמונות עבור כל הבקרים במערכת בבת אחת

כל תמונות הבקרים מתוקננות לגודל היעד ונשמרות בפורמט WebP.

טיפ: נדרש מפתח AI API ליצירת תוכן. המוזיאון משתמש באותו ספק AI המוגדר ב-Settings → Scraping → API Keys.

דוחות ROM

מה זה עושה

מאמת שמות קבצי ROM מול מוסכמות שמות תקניות ומזהה בעיות אפשריות. גישה דרך ROM Reports בסרגל הצד.

סוגי דוחות

לשוניתמה היא בודקת
שמות לא תקנייםקבצי ROM עם שמות שאינם תואמים למוסכמות השמות. מציג את שם הקובץ הנוכחי, בעיות שזוהו, ושם מתוקן מוצע.
אי-התאמות שםקבצי ROM שבהם שם הקובץ אינו תואם לכותרת המטא-דאטה שנגרדה. מציג את שם הקובץ הנוכחי מול הכותרת שנגרדה, אזור, שנה, ומפתח.

מה נבדק

  • תווים לא חוקיים בשמות קבצים (: ? * / " < > | \)
  • תגי אזור חסרים או שגויים (למשל (USA), (Europe))
  • תגי שנה חסרים
  • אי-התאמות בין שם קובץ לכותרת במסד הנתונים

הדוחות ניתנים למיון לפי מערכת, שם קובץ, וסוג בעיה. השתמש בהם כדי לשמור על ספריית ה-ROM שלך מאורגנת ובעלת שמות עקביים.

כלי ROM

גש למרכז כלי ה-ROM מסרגל הצד. כל כלי רץ כמשימת רקע עם עדכוני התקדמות בזמן אמת, תמיכה בהשהיה/המשך, ורישום לוג.

סורק ארכיונים

חלץ ארכיוני ROM (ZIP, 7Z, RAR) עם אפשרויות עבור:

  • סריקה רקורסיבית של תת-תיקיות
  • הסרת קבצים לא רצויים לאחר החילוץ
  • יצירת רשימת השמעה M3U אוטומטית למשחקים מרובי-דיסקים

דורש: 7z או unzip

ממיר CHD

המר תמונות דיסק (ISO, BIN/CUE, GDI) לפורמט CHD דחוס. חוסך אחסון משמעותי תוך שמירה על תאימות מלאה עם אמולטורים.

דורש: chdman (מ-mame-tools)

אימות CHD

אמת את שלמות קבצי CHD עם ולידציית hash. מזהה המרות פגומות או לא שלמות.

דורש: chdman

מאתר כפילויות

מצא קבצי ROM כפולים לפי hash או שם קובץ, עם אפשרויות לתעדוף לפי תגי אזור.

מארגן מרובי-דיסקים

ארגן משחקים מרובי-דיסקים לתת-תיקיות וצור רשימות השמעה M3U עבור אמולטורים התומכים בהן. שימושי למערכות כמו PlayStation ו-Saturn.

ללא תלויות חיצוניות

ניכוי כפילויות צילומי מסך

מצא והסר צילומי מסך כפולים ברחבי ספריית המשחקים שלך כדי לפנות שטח אחסון.

  • Hash מדויק (MD5) — מזהה קבצים זהים בלבד
  • דמיון חזותי — השוואת perceptual hash עם סף מתכוונן (1–20, נמוך יותר = התאמה מחמירה יותר)

סורק בהדרגה עם סטטיסטיקה חיה המציגה משחקים שנסרקו, מספר כפילויות, ושטח שניתן לשחזור. התוצאות מקובצות לפי משחק ומערכת. ניתן לבחור איזה קובץ לשמור בכל קבוצת כפילויות, או להשתמש ב-"Select Largest" כדי לשמור אוטומטית את הגרסה ברזולוציה הגבוהה ביותר.

תקנן מדיית משחקים לגדלי יעד עקביים. ראה תקנון תמונות לפרטים מלאים.

ללא תלויות חיצוניות (הגדלת AI מבוססת Python)

מילוי כותרות חלופיות

סרוק את הספרייה לאיתור משחקים ששדה הכותרות החלופיות שלהם ריק ומלא אותו מ-IGDB / TGDB / ScreenScraper. שימושי לאחר ייבוא קטלוג גדול או מעבר מכלי אחר שלא שמר כותרות אזוריות / יפניות / משנה. רץ ברקע; ההתקדמות מוצגת בכרטיס הכלי.

דורש לפחות מפתח scraper API אחד (IGDB / TGDB / ScreenScraper)

חיפוש HLTB מרוכז

הרץ חיפוש HowLongToBeat עבור כל משחק שחסר לו הערכת זמן משחק. כל התאמה מדורגת לפי כותרת + פלטפורמה + שנת יציאה; התאמות בעלות ביטחון גבוה נשמרות אוטומטית. כל דבר מתחת לסף הביטחון (או עם פלטפורמות סותרות) מוחזק לבדיקה אנושית.

ללא תלויות חיצוניות (משתמש במאגר HLTB לא-מקוון המצורף)

בדיקת HLTB ממתינה

תור בדיקה להתאמות עמומות שהועלו על ידי חיפוש HLTB מרוכז. כל שורה ממתינה מציגה את משחק המקור לצד מועמד HLTB (כותרת, פלטפורמה, שנת יציאה, ביטחון). אשר, דחה, או בחר התאמה אחרת לכל שורה. כרטיס כלי הבדיקה מופיע במרכז כלי ה-ROM רק כאשר יש לפחות התאמה ממתינה אחת.

  • לשוניות סינון להתאמות בעלות ביטחון נמוך, כותרת חלופית, ואי-התאמת פלטפורמה.
  • אישור כותב את הערכת זמן המשחק; דחייה משמיטה את המועמד ושומרת על תור החיפוש נקי.

הגדרות כלים

הגדר נתיבים, מיקומי כלים, סוגי ארכיונים, והעדפות משותפות לכל כלי ה-ROM.

טיפ: כל כלי ה-ROM תומכים בהשהיה/המשך ורצים ברקע. ההתקדמות והתוצאות נרשמות בלוג וניתנות לצפייה במציג הלוג. סטטוס הכלי (זמין מול דורש התקנה) מוצג בכל כרטיס כלי.

תקנון

מה זה עושה

מתקנן ערכי ז'אנר ומצב משחק לצורות קנוניות עקביות. זה קורה אוטומטית במהלך גרידה ומילוי AI, וניתן גם להחיל אותו ידנית על הספרייה הקיימת שלך.

למה זה חשוב

scrapers שונים משתמשים בשמות שונים לאותו דבר. תקנון מבטיח עקביות בכל הספרייה שלך:

  • platform → Platformer
  • fps, first person shooter → First-Person-Shooter
  • shoot 'em up, shmup → Shoot-em-up
  • beat 'em up, brawler → Beat-em-up
  • hack and slash → Hack-n-Slash
  • rts, real time strategy → Real-Time Strategy
  • board game, card game → Board-Card

כללים מותאמים אישית

ניתן להוסיף כללי תקנון מותאמים אישית ב-Settings → Data → Normalization. כללים מותאמים אישית עוקפים את המיפויים המובנים, ומאפשרים לך להגדיר שמות ז'אנר ומצב מועדפים משלך. הכללים נשמרים במסד הנתונים.

תצוגה מקדימה והחלה

לפני החלת התקנון, ניתן לצפות בתצוגה מקדימה של אילו משחקים יושפעו ואילו שינויים יבוצעו. זה מאפשר לך לבדוק לפני ביצוע שינויים בספרייה שלך.

תקנון תמונות

מה זה עושה

מתקנן את כל מדיית המשחקים לגדלי יעד עקביים למראה אחיד בכל הספרייה שלך. תמונות שנמצאות בטווח של 80–120% מגודל היעד מדולגות.

איך זה עובד

  • הגדלה — תמונות קטנות מגודל היעד מוגדלות באמצעות Real-ESRGAN x4 (רזולוציית-על של AI דרך ONNX Runtime) להגדלה באיכות גבוהה, ולאחר מכן משונות גודל לגודל היעד המדויק
  • הקטנה — תמונות גדולות מגודל היעד מוקטנות באמצעות סינון Lanczos לתוצאות חדות
  • רצועת סף — תמונות בטווח של 80–120% מהיעד נשארות ללא שינוי כדי להימנע מעיבוד חוזר מיותר

תמיכת חומרה

מודל Real-ESRGAN מזהה אוטומטית את החומרה שלך ומשתמש בספק הטוב ביותר הזמין:

  • CUDA — האצת GPU של NVIDIA
  • ROCm — האצת GPU של AMD (עם עקיפת גרסת gfx אוטומטית לסדרת RX 6000)
  • CoreML — האצת Apple Silicon
  • CPU — חלופה למערכות ללא תמיכת GPU

קובץ מודל ה-ONNX מורד אוטומטית מ-Hugging Face בשימוש הראשון ונשמר במטמון מקומי.

תחזוקה

פעולות תחזוקה זמינות ב-Settings → System → Maintenance. אלה עוזרות לשמור על הספרייה שלך נקייה ומאופטמת.

סריקת ספרייה

  • סרוק ספרייה — סרוק את תיקיות ה-ROM שלך למשחקים חדשים. מזהה תיקיות מערכת וסוגי קבצים נתמכים באמצעות רשימות סיומות של ES-DE systeminfo.txt. זמין גם מלוח הבקרה.

פעולות ניקוי

  • נקה קבצי ROM חסרים — הסר רשומות מסד נתונים עבור משחקים שקבצי ה-ROM שלהם כבר לא קיימים בדיסק. שימושי לאחר ארגון מחדש או מחיקת קבצי ROM.
  • ניקוי מדיה יתומה — מצא ומחק קבצי תמונה בדיסק (תמונת קופסה, צילומי מסך, fanart) שאין להם רשומת מסד נתונים תואמת. צפה בתצוגה מקדימה לפני המחיקה לאישור.
  • נקה נתונים שנגרדו — הסר את כל המטא-דאטה שנגרדה מהמשחקים תוך שמירה על רשומות קבצי ה-ROM. שימושי להתחלה רעננה עם גרידה. תצוגה מקדימה מציגה את המשחקים המושפעים לפני הביצוע.
  • נקה ייבוא CLZ — הסר את כל רשומות הייבוא של CLZ Games (רשומות מטא-דאטה בלבד ללא קבצי ROM).

אופטימיזציית מסד נתונים

  • אופטימיזציית מסד נתונים — מריץ SQLite VACUUM ו-ANALYZE כדי לשחזר אחסון מרשומות שנמחקו ולעדכן סטטיסטיקות מתכנן שאילתות. מומלץ לאחר מחיקות גדולות או פעולות ניקוי.

כל משתמש יכול להגדיר את הפרטים האישיים שלו:

  • נתיב גביעי RPCS3
  • פרטי RetroAchievements (שם משתמש + מפתח API)
  • פרטי PSN (עוגיית NPSSO)

גיבוי ושחזור

יצירת גיבויים

  1. עברו אל הגדרות → ספרייה → גיבוי
  2. לחצו על "צור גיבוי"
  3. הגיבוי נשמר בתיקייה backups/ עם שם קובץ הנושא חותמת זמן

מה מגובה

הגיבוי כולל את כל מסד הנתונים SQLite (roms.db), המכיל את כל המטא-נתונים של המשחקים, חשבונות המשתמשים, ההגדרות, נתוני הגביעים, התקדמות ההישגים, תגיות, רשימות ופריטי רשימת המשאלות.

מה לא מגובה

קובצי מדיה (עטיפות, צילומי מסך, אמנות מעריצים, סרטונים, מדריכים) אינם כלולים בגיבוי מסד הנתונים מכיוון שניתן להוריד אותם מחדש באמצעות גירוד. שקלו לגבות את התיקייה static/images/ בנפרד אם יש לכם העלאות מותאמות אישית.

שחזור

  1. מצאו את הגיבוי ברשימת הגיבויים
  2. לחצו על "שחזר"
  3. אשרו את הפעולה
אזהרה: שחזור גיבוי דורס את מסד הנתונים הנוכחי שלכם. צרו גיבוי טרי לפני שחזור גיבוי ישן יותר!

עדכון RetroDB

כיצד לעדכן

  1. הורידו את גרסת RetroDB החדשה
  2. גבו את הקבצים הבאים (הם מכילים את הנתונים האישיים שלכם):
    • config.py (הנתיבים ומפתחות ה-API שלכם)
    • data/settings.json (העדפות ממשק המשתמש שלכם)
    • data/scraper_settings.json (תצורת הגירוד שלכם)
    • data/rom_tools_config.json (העדפות כלי ה-ROM שלכם)
    • התיקייה database/ (מסד נתוני ספריית המשחקים שלכם, ואסימוני הכניסה השמורים של PSN/Xbox)
  3. חלצו את הגרסה החדשה מעל ההתקנה הקיימת
  4. הריצו python install.py כדי להתקין תלויות חדשות
  5. הפעילו מחדש את השרת

קבצים שבטוח לדרוס

כל קובצי קוד המקור (.py, .html, .css, .js) ניתנים לדריסה בבטחה. תוכנית ההתקנה לא תדרוס את קובצי התצורה האישיים שלכם.

קבצים לשמור

לעולם אל תמחקו או תדרסו: config.py, database/roms.db, data/settings.json, data/scraper_settings.json, data/rom_tools_config.json.

העברות מסד נתונים

RetroDB מטפל אוטומטית בשינויי סכימת מסד הנתונים בהפעלה. עמודות וטבלאות חדשות נוספות לפי הצורך ללא אובדן נתונים. אינכם צריכים לעשות דבר מיוחד — פשוט הפעילו את הגרסה החדשה ומסד הנתונים מתעדכן אוטומטית.

פתרון בעיות

בעיות נפוצות

"לא נמצאו סיומות למערכת"

תיקיית המערכת זקוקה לקובץ ES-DE systeminfo.txt תקין המגדיר את סיומות קובצי ה-ROM הנתמכות. ודאו שמבנה ספריית ה-ROM שלכם תואם לתקני ES-DE.

"החיבור ל-API נכשל"

  • בדקו את חיבור האינטרנט שלכם
  • אמתו את מפתחות ה-API בהגדרות → גירוד → מפתחות API
  • המתינו אם הגעתם למגבלת קצב (לחלק מה-API יש מכסות יומיות/שעתיות)
  • בדקו אם הגורד מופעל (גורדים מושבתים מציגים "מושבת" בסטטוס לוח הבקרה)
  • בדקו את מציג היומן להודעות שגיאה מפורטות

"גירוד בכמות תקוע"

עברו אל הגדרות → מערכת → פתרון בעיות → "נקה גירוד בכמות תקוע". זה מאפס את מצב המשימה מבלי להשפיע על הנתונים שלכם.

"תור סנכרון RA תקוע"

נקו את תור הסנכרון של RetroAchievements מהגדרות → מערכת → פתרון בעיות.

"סנכרון PSN תקוע"

נקו את משימת רענון ה-PSN מהגדרות → מערכת → פתרון בעיות.

"יצירת מוזיאון תקועה"

נקו את משימת יצירת המוזיאון מהגדרות → מערכת → פתרון בעיות.

"שגיאות מסד נתונים"

  1. צרו גיבוי אם אפשר (הגדרות → ספרייה → גיבוי)
  2. נסו הגדרות → מערכת → תחזוקה → ייעל מסד נתונים
  3. בדקו את הרשאות הקבצים בתיקייה database/
  4. מוצא אחרון: שחזרו מגיבוי או מחקו את מסד הנתונים וסרקו מחדש

"תמונות לא נשמרות"

בדקו הרשאות כתיבה בספריות המדיה: chmod -R 755 static/images/

"העמוד איטי או לא מגיב"

  • אוספים גדולים עשויים לקחת זמן להיטען — גלילה אינסופית נטענת באצוות של 100
  • נסו לרענן את העמוד כדי לנקות זיכרון שהצטבר
  • בדקו את מסוף הדפדפן לשגיאות JavaScript
  • נסו לעבור לערכת נושא עם אפקט קנבס קל יותר (למשל Amber או Elite)
  • אפקטי קנבס מזהים אוטומטית את החומרה; מכשירים חלשים יותר משתמשים בגיבוי מעבד בקצב פריימים מופחת

באנר "משימות שהופרעו" בלוח הבקרה

אם RetroDB מופעל מחדש בזמן שמשימות פועלות, הן מופיעות בבאנר שחזור. לחצו על "המשך" בנפרד או על "המשך הכל" כדי להפעילן מחדש. לחצו על "התעלם" או על "התעלם מהכל" כדי לנקות אותן.

"אימות PSN נכשל"

  • אסימוני NPSSO פגים — צרו אסימון חדש מ-ca.account.sony.com/api/v1/ssocookie
  • ודאו שאתם מחוברים ל-store.playstation.com לפני ביקור בכתובת העוגייה
  • RetroDB שומר במטמון את הפעלת ה-PSN שלכם למשך כחודשיים וכעת מחדש אותה אוטומטית ברקע; אם היא עדיין פוקעת, פשוט הדביקו NPSSO טרי בהגדרות → חשבון → PSN

"אימות Xbox נכשל"

  • אמתו מחדש בלחיצה על "התחבר" בכרטיסייה ייבוא משחקים → Xbox
  • אסימוני Xbox נשמרים במטמון ב-data/xbox_tokens.json ומתרעננים אוטומטית

"שגיאות שדרוג תמונות"

  • מודל Real-ESRGAN ONNX מורד בשימוש הראשון — ודאו גישה לאינטרנט
  • האצת GPU דורשת מנהלי התקן תואמים (CUDA עבור NVIDIA, ROCm עבור AMD)
  • אם ה-GPU נכשל, המערכת עוברת לעיבוד מעבד אוטומטית

טיפים לביצועים

  • שמרו על הדפדפן שלכם מעודכן לביצועים מיטביים
  • סגרו כרטיסיות דפדפן אחרות בעבודה עם אוספים גדולים מאוד
  • השתמשו במסנני מערכת כדי לצמצם את המשחקים המוצגים בבת אחת
  • הריצו ייעול מסד נתונים מעת לעת לאחר פעולות גדולות (גירוד, ניקוי, ייבוא)
  • אפקטי קנבס של ערכת הנושא מזהים אוטומטית את החומרה; מכשירים חלשים יותר משתמשים בגיבוי מעבד

אבטחה והצהרת אחריות

שיטות עבודה מומלצות לאבטחה

  • שנו את סיסמת ברירת המחדל — יש לשנות את סיסמת המנהל שברירת המחדל (admin) מיד בהתחברות הראשונה. השתמשו בסיסמה חזקה של לפחות 8 תווים.
  • השתמשו בפרוקסי הפוך של HTTPS — RetroDB אינו מספק TLS/SSL בעצמו. הציבו אותו מאחורי פרוקסי הפוך (למשל Nginx, Caddy, Traefik) עם HTTPS מופעל כדי להצפין את התעבורה בין הלקוחות לשרת.
  • הגבילו את הגישה לרשת — הימנעו מחשיפת RetroDB ישירות לאינטרנט הציבורי. השתמשו ב-VPN או הגבילו את הגישה לרשת המקומית שלכם. אם נדרשת גישה מרחוק, השתמשו בפרוקסי הפוך עם אימות.
  • שמרו על גיבויים סדירים — השתמשו בתכונת הגיבוי המובנית תחת הגדרות כדי ליצור גיבויים תקופתיים של מסד הנתונים. אחסנו את הגיבויים במיקום נפרד מהיישום.
  • שמרו על RetroDB מעודכן — בדקו אם יש גרסאות חדשות באופן קבוע. תיקוני אבטחה ושיפורים כלולים בעדכונים.
  • הגנו על מפתחות ה-API שלכם — מפתחות API מאוחסנים ב-data/scraper_settings.json. ודאו שקובץ זה אינו נגיש לציבור. לעולם אל תשתפו את config.py או את קובצי האסימונים שלכם.

תכונות אבטחה מובנות

  • גיבוב סיסמאות — סיסמאות מנהל מגובבות באמצעות PBKDF2 (לעולם לא מאוחסנות כטקסט רגיל)
  • הגבלת קצב התחברות — הגנה מפני התקפות כוח גס בנקודת הקצה של ההתחברות
  • אימות נתיבים — כל פעולות הקבצים משתמשות בעוזרי safe_path ו-safe_filename כדי למנוע התקפות חצייה של ספריות
  • שאילתות מפורמטרות — כל שאילתות מסד הנתונים משתמשות בהצהרות מפורמטרות כדי למנוע הזרקת SQL
  • הגנת XSS — תיבות דו-שיח מודאליות משתמשות בבניית DOM בטוחה; קלט המשתמש מנוטרל
  • הגנה מפני פצצת דחיסת תמונות — ספירת הפיקסלים המרבית של תמונה מוגבלת כדי למנוע התשת זיכרון מתמונות זדוניות

הצהרת אחריות

RetroDB מסופק "כמות שהוא", ללא אחריות מכל סוג, מפורשת או משתמעת, לרבות אך לא רק אחריות לסחירות, התאמה למטרה מסוימת, ואי-הפרה. בשום מקרה לא יישאו המחברים או בעלי זכויות היוצרים באחריות לכל תביעה, נזק, או חבות אחרת, בין אם בפעולה חוזית, נזיקית, או אחרת, הנובעת, מתוך, או בקשר עם התוכנה או השימוש בה או עסקאות אחרות בתוכנה.

אתם האחראים הבלעדיים לאבטחת הפריסה שלכם, לרבות תצורת רשת, בקרת גישה, גיבויי נתונים, ועמידה בכל החוקים החלים לגבי התוכן שאתם מנהלים באמצעות תוכנה זו. המפתחים אינם נושאים באחריות לגישה בלתי מורשית, אובדן נתונים, או שימוש לרעה הנובעים מתצורה או פריסה שגויה.
