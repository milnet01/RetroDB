## Findings

### Dimension 6 — Test Isolation

**MED** · `tests/test_auth_hardening.py:53`  
`app_module.app.config['TESTING'] = True` assigned directly inside `test_login_endpoint_rejects_missing_user_id` with no teardown. The method takes no `monkeypatch` parameter — pytest will not restore the value on teardown.  
**Status:** RESIDUAL from prior synthesis (c-001.md MED finding, not resolved in v3.6.8 or any subsequent pass). Still present at line 53 (confirmed by grep).  
**Consequence:** Any test that later checks `app.config.get('TESTING')` or branches on it sees the leaked `True`. Under `pytest-xdist`, two workers sharing the app singleton can race on this key.  
**Fix:** Add `monkeypatch` to the method signature; replace line 53 with `monkeypatch.setitem(app_module.app.config, 'TESTING', True)`.

**MED** · `tests/test_auth_hardening.py:370–375` (class-scoped fixture `client`)  
`@pytest.fixture(scope="class")` fixture sets `app_module.app.config['TESTING'] = True` at line 373 with no teardown and no `try/finally` around `yield`. Class-scoped fixtures do not accept `monkeypatch` (function-scoped); the snapshot+restore pattern is required here. The `app.config` dict is a module-level singleton shared across the process.  
**Status:** RESIDUAL from prior synthesis. Confirmed at line 373. The three-TESTING-mutation problem in this file was fully enumerated in the prior c-001.md but none were resolved.  
**Consequence:** After `TestDestructiveEndpointsRequireAuth` completes its class teardown, `app.config['TESTING']` is left `True` for all subsequent tests in the run.  
**Fix:** Wrap the fixture body: `_was = app_module.app.config.get('TESTING', False); app_module.app.config['TESTING'] = True; try: yield c; finally: app_module.app.config['TESTING'] = _was`.

### Dimension 5 — Flakiness

**MED** · `tests/test_bulk_scrape_race.py:102,106,150,152`  
Four `.wait(timeout=…)` assertions use bare Python assertions (`assert …`). Lines 102–103 and 150–151 have a diagnostic string ("Worker never observed cancel flag") but lines 106–107 and 152–153 also have diagnostics ("Swap blocked too long…", "Demote blocked too long…"). On the *message* dimension these are fine. However: the `wait(timeout=2.0)` at line 102/150 fires every 50 ms in the worker loop; on a severely oversubscribed runner 40 × 50 ms = 2 s with no slack. If the scheduler delays the test thread itself, the assert can fire before the worker wakes.  
**Status:** Partially addressed from prior synthesis — the diagnostic messages are now present, which was the prior fix recommendation. The timeout margin itself remains tight for CI.  
**Consequence:** Intermittent CI fail on overloaded runners. Low probability but non-zero.  
**Fix:** Extend `worker_observed_cancel.wait(timeout=5.0)` (5s, same as the join timeout), or add `f"…job.cancelled={job.cancelled!r}, job.running={job.running!r}"` to each message for post-mortem. The join timeout at 5s is already generous; the 2s event-wait is the tighter constraint.

### Dimension 10 — Duplication / Dangerous Patterns

**MED** · `tests/test_auth_hardening.py:42,64,86,166,211,241`  
Six `open(…).read()` calls with no context manager. Lines 42, 64, 86 open `auth_mod.__file__`; line 166 opens `auth_mod.__file__` again; lines 211 and 241 open `module_path` / `pi_mod.__file__`. The `read_source()` and `read_module_source()` helpers in `tests/_util.py` were extracted specifically to centralise this pattern and ensure context-manager-safe reads, but `test_auth_hardening.py` was not migrated.  
**Status:** RESIDUAL from prior synthesis (Theme 2, c-001.md MED finding). Confirmed still present; 6 bare opens remain at the listed lines.  
**Consequence:** Under CPython refcounting the descriptors close immediately, but this is an implementation detail. Under PyPy or resource-limited environments the fd may remain open until GC. Also keeps a redundant `_REPO_ROOT` and `import os` that would become unused after migration.  
**Fix:** `from tests._util import read_source, read_module_source` at the top; replace all six bare `open(…).read()` calls with the appropriate helper. Remove `_REPO_ROOT` (line 24) and `import os` (line 21) as they become unused.
