## Findings

### HIGH

#### HIGH-1 · Isolation (dim 6) · `tests/test_routes_smoke.py:14`

Module-scoped `client` fixture assigns `app_module.app.config['TESTING'] = True` with no snapshot and no teardown.

**Consequence:** TESTING flag remains set on the live Flask app singleton for the rest of the process. Any test module that runs after `test_routes_smoke` inherits it. Under `pytest-xdist` with in-process workers this is a cross-test state bleed; under vanilla `pytest` it means every subsequent file sees TESTING=True regardless of its own setup.

**Fix:** Snapshot before `yield`, restore in `finally`:

```python
@pytest.fixture(scope="module")
def client():
    import app as app_module
    _orig = app_module.app.config.get('TESTING')
    app_module.app.config['TESTING'] = True
    try:
        with app_module.app.test_client() as c:
            yield c
    finally:
        app_module.app.config['TESTING'] = _orig
```

(`monkeypatch` is not available in module-scoped fixtures — snapshot + `try/finally` is the correct approach here.)

**Evidence lines:** 11–16

### MED

#### MED-1 · Accuracy (dim 1) · `tests/test_security_headers.py:127–135`

`TestCspNonceInTemplateContext` docstring (line 125) states the `{{ csp_nonce }}` Jinja global "must match what's sent in the header." The sole test (`test_nonce_exposed_via_context_processor`) only asserts `rendered` is truthy (line 134) and `len(rendered) >= 20` (line 135). No assertion compares the rendered nonce to the value in `Content-Security-Policy-Report-Only`.

**Consequence:** A refactor that makes `assign_request_id()` and the `after_request` security middleware generate independent nonces would silently break every inline `<script nonce="...">` block. The test would still pass because it checks non-emptiness only. The production flow in `app.py:597` writes `g.csp_nonce` and `app.py:417` reads `g.get('csp_nonce', '')` to populate the header — a refactor that writes to a different `g` attribute would produce a non-empty rendered value and an empty or stale header nonce simultaneously, invisible to this test.

**Fix:** After `assign_request_id()`, read `flask.g.csp_nonce` and compare to the rendered value:

```python
from flask import g, render_template_string
app_module.assign_request_id()
rendered = render_template_string('{{ csp_nonce }}')
assert rendered == g.csp_nonce, (
    f"Template nonce {rendered!r} does not match g.csp_nonce {g.csp_nonce!r}"
)
assert len(rendered) >= 20
```

Then add a second check: issue a request via `app_module.app.test_client().get('/health')` and assert the nonce from `g.csp_nonce` appears inside the `Content-Security-Policy-Report-Only` header string.

**Evidence lines:** 124–135

#### MED-2 · Splitting (dim 11) · `tests/test_security_headers.py:47–53` and `110–116`

Two tests iterate over feature/directive lists inside a single test body:

- `test_permissions_policy_disables_sensors` (line 47): loops over 7 sensor API features; first failure hides the remaining 6.
- `test_csp_includes_core_directives` (line 110): loops over 9 CSP directives; first failure hides the remaining 8.

**Consequence:** A regression dropping two CSP directives is reported one at a time — the developer fixes the first, re-runs, then hits the second. For security-relevant header contracts this is a meaningfully slower debug loop. MED (not LOW) because these are direct security invariants, not minor niceties.

**Fix:** Convert each loop to `@pytest.mark.parametrize`. For the permissions-policy test:

```python
@pytest.mark.parametrize("feature", [
    'camera', 'microphone', 'geolocation', 'payment',
    'usb', 'interest-cohort', 'browsing-topics',
])
def test_permissions_policy_disables_feature(self, client, feature):
    pp = client.get('/health').headers['Permissions-Policy']
    assert f'{feature}=()' in pp, f"{feature} not opt-out in Permissions-Policy"
```

Same shape for the CSP directives test.

**Evidence lines:** 47–53, 110–116

**Consequence:** If `_log_if_slow` fails to emit any record (e.g. a threshold comparison bug, an early-return regression), the test raises `IndexError: list index out of range` instead of an `AssertionError` with context. #### LOW-6 · Dangerous patterns (dim 18) · `tests/test_scrape_fill_only.py:35`

`sqlite3.connect(':memory:')` at line 35 inside `_make_conn_with_existing_row` is wrapped in `_PersistentConn`, whose `close()` method is intentionally a no-op (lines 29–30) so the test can assert after the scraper's `finally: conn.close()` fires. This means the underlying `sqlite3.Connection` is never explicitly closed.

**Consequence:** CPython's reference counting closes it when the local falls out of scope at test teardown — reliable under CPython today. Fragile on PyPy or under `pytest-xdist` process reuse. This is the same LOW pattern flagged in the prior synthesis for `test_migration_012.py:28,53,64` and `test_owner_id_self_heal.py:38,58,72,82`.

**Fix:** After the test body, call `_persistent_conn._conn.close()` (the underlying raw connection is accessible via `__getattr__` → `_conn`). Simplest approach: a `try/finally` in each test that uses `_make_conn_with_existing_row`:

```python
conn = _make_conn_with_existing_row(id=1, ...)
try:
    ...assertions...
finally:
    conn._conn.close()
```

**Evidence lines:** 18–31, 33–56
