## A. Correctness & Accuracy

### Dimension 1 — Accuracy

**MED** · `tests/test_emulator_registry_routes.py:21` — `test_mutating_routes_require_admin` asserts `'@admin_required' in src` on the entire file. Because `routes/emulators.py` imports `admin_required` at line 13 and applies it to every mutating handler, the string appears 7 times; but if a new POST/PUT/DELETE handler were added without the decorator, the assertion still passes (the string is somewhere in the file). The behavioural counterparts at lines 109–137 pin the actual contract. Fix: scope to the relevant function body using `slice_function(src, 'create_emulator')` etc., or drop the source-grep test and rely solely on the behavioural tests.

**MED** · `tests/test_hltb_endpoint.py:87` — `test_search_url_points_to_bleed` counts `src.count('/api/bleed') >= 3`. The bare `/api/bleed` substring matches the `/api/bleed/init` init URL (2 occurrences), module-docstring references (2), inline comments (2), and the two real POST f-strings (2) — total 8. Removing both POST f-strings (lines 187 and 208 in `hltb_lookup.py`) still yields a count of 6 (≥ 3). The test is vacuous when comments/docstrings are present. Fix: count only the f-string literal POST URLs, e.g. `src.count('f"{HLTB_BASE_URL}/api/bleed"') >= 2` or use `read_source` + `slice_function` to scope to `_search_hltb`.

**LOW** · `tests/test_game_query.py:52` — `assert 42 in vals or '42' in vals` is type-ambiguous: if the SUT changes to produce strings the right branch carries it silently; switching back the left carries it. Hides a real contract question. Fix: `assert 42 in vals` — fail loudly if the type changes.

**LOW** · `tests/test_game_query.py:67` — `assert "'Z'" in str(vals) or 'Z' in vals`. The first branch converts the whole list to a string and substring-searches; `['ZERO']` contains `'Z'` and would pass. Fix: `assert 'Z' in vals` (element membership directly).

**LOW** · `tests/test_emulator_autodetect.py:45–49` — `test_walk_finds_all_appimages` makes five separate `in`-membership assertions with no upper bound. A walk that returns the 5 expected names plus every other file on disk would still pass. Fix: add `assert len(paths) == 5` after the membership checks, or assert `paths == sorted([...expected...])`.

## C. Reliability & Isolation

### Dimension 5 — Flakiness

**HIGH** · `tests/test_graceful_shutdown.py:92` *(residual from prior synthesis)* — `assert elapsed < 1.5` with `timeout=0.5` in `request_shutdown`. On a CI runner under load, thread scheduling overhead can push `elapsed` above 1.5s. The immediately following `assert not slow._thread.is_alive()` is the stronger assertion (it proves the thread actually exited, which is the real contract). Fix: drop line 92, or replace with `assert elapsed < timeout * 3.0` where `timeout = 0.5`.

**MED** · `tests/test_graceful_shutdown.py:114` *(residual from prior synthesis)* — `assert elapsed < 1.0` with `timeout=0.3`. Under VM/CI jitter, 0.3s timeout + overhead approaches 1.0s. The liveness assertion on line 116–117 is the stronger check. Fix: raise to `< timeout * 4.0` or rely solely on the liveness assertion.

### Dimension 6 — Test isolation

**MED** · `tests/test_etag_and_gzip.py:20` *(residual)* — Module-scoped `client` fixture sets `app_module.app.config['TESTING'] = True` on the live app singleton with no teardown. Because `app` is a module-level singleton, the flag persists across all subsequent test modules. Fix: add `yield c; app_module.app.config.pop('TESTING', None)` after the `with` block. (`monkeypatch` cannot be used in module-scoped fixtures — teardown approach is correct here.)

**MED** · `tests/test_etag_and_gzip.py:75` *(residual)* — `test_request_parity` re-mutates `app_module.app.config['TESTING'] = True` inline, outside the module fixture, with no teardown. Fix: use the module `client` fixture instead of constructing a fresh client, or add `try/finally: app_module.app.config.pop('TESTING', None)`.

**MED** · `tests/test_graceful_shutdown.py:75` *(residual)* — `test_calls_cancel_on_running_jobs` clears `shutdown_requested` before calling `request_shutdown` but has no `try/finally` to clear it if the two assertions on lines 78–79 raise. If the test fails, `shutdown_requested` is left SET for subsequent tests. `test_sets_shutdown_event` (line 59) already uses the correct `try/finally` pattern with an explanatory comment. Fix: wrap lines 75–79 in `try/finally: base_mod.shutdown_requested.clear()`.

## D. Maintainability

### Dimension 10 — Duplication

**MED** · `tests/test_database_backup.py:25,43,68,98,149` *(residual)* — Five tests each open a `tempfile.TemporaryDirectory()` and build path strings from it. Using `tmp_path` (a pytest built-in fixture) would (a) eliminate the `import tempfile`, (b) provide automatic cleanup even on test failure, and (c) make CI artefact inspection easier (pytest's `--basetemp` keeps dirs on failure). Fix: replace each `with tempfile.TemporaryDirectory() as tmp:` + `os.path.join(tmp, ...)` with `tmp_path`-derived `Path` objects and extract a `populated_src_db(tmp_path)` fixture for the common `_populate(src)` pattern.

**LOW** · `tests/test_emulator_seeder.py:8` — `_REPO_ROOT = pathlib.Path(__file__).resolve().parent.parent` duplicates the computation already in `tests/_util.REPO_ROOT`. `conftest.py` imports `_util` so `REPO_ROOT` is already on the path. Fix: `from tests._util import REPO_ROOT as _REPO_ROOT` (one import replaces the local computation).

**LOW** · `tests/test_hltb_endpoint.py:29–32` *(residual)* — `_REPO_ROOT` + `sys.path.insert` boilerplate that `conftest.py` already handles via `_util.py`. The `sys.path.insert` is a confirmed no-op (conftest.py ensures the repo root is on `sys.path` before any test file imports). The `_read_source()` static method duplicates `read_source('scraper/hltb_lookup.py')` from `_util`. Fix: remove lines 29–32, import `read_source` from `tests._util`, and replace `self._read_source()` calls with `read_source('scraper/hltb_lookup.py')`.
