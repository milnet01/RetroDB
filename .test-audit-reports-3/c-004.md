## Findings

### F-001 · Dimension 6 (Test Isolation) · MED

**File:** `tests/test_observability.py`  
**Line:** 26  
**Evidence lines:** 24–38

The `client` fixture assigns `app_module.app.config['TESTING'] = True` at line 26 without a corresponding restore. The fixture's own teardown (lines 37–38) explicitly restores `logging.getLogRecordFactory()` and `log_manager._request_id_installed`, making the omission of TESTING visible as an inconsistency. No teardown guard or `monkeypatch.setitem` is used for this assignment.

**Consequence:** `app.config['TESTING']` is permanently `True` for all tests that run after this module in the same pytest session. No test today depends on `TESTING=False`, so there is no live breakage. However, the fixture's documentation-by-example contracts more isolation than it delivers, and any future test that checks for `TESTING=False` (e.g., to verify production error pages render) will spuriously pass.

**Fix:** Either (a) capture `_orig = app_module.app.config.get('TESTING')` before `yield` and restore it in teardown alongside the existing restores, or (b) replace line 26 with `monkeypatch.setitem(app_module.app.config, 'TESTING', True)` — but `monkeypatch` must then be accepted as a fixture parameter.

### F-002 · Dimension 6 (Test Isolation) · MED

**File:** `tests/test_pass31_migrations.py`  
**Lines:** 182–187  
**Evidence lines:** 177–217

`test_legacy_gap_rows_backfill_to_admin` (line 167) uses bare `try/finally` to swap `migrations.MIGRATIONS`:

```python
real = migrations.MIGRATIONS
try:
    migrations.MIGRATIONS = real[:4]
    migrations.apply_pending(conn)
finally:
    migrations.MIGRATIONS = real
```

The sister method `test_migrations.py:324–329` (`TestCollectionsOwnerId.test_backfill_assigns_legacy_rows_to_admin`) performs the identical mutation with `monkeypatch.setattr`, including an inline comment: _"Use monkeypatch (not try/finally) so the global list is restored even if the test is killed mid-run (SIGKILL/OOM)."_ That comment documents exactly why the `try/finally` form is insufficient here.

**Consequence:** If the process receives SIGKILL or is OOM-killed after line 184 but before line 187 executes, `migrations.MIGRATIONS` is left as `real[:4]` for the rest of the pytest session. Subsequent migration tests would operate on an incomplete four-migration chain and could produce false-green results on migration steps 5–N.

**Fix:** Accept `monkeypatch` as a parameter to `test_legacy_gap_rows_backfill_to_admin`; replace the inner `try/finally` with `monkeypatch.setattr(migrations, 'MIGRATIONS', real[:4])` before `migrations.apply_pending(conn)`.

### F-003 · Dimension 1 (Accuracy) · LOW

**File:** `tests/test_pass35_36_hardening.py`  
**Lines:** 290–292  
**Evidence lines:** 288–296

`test_36_10_assertive_container` checks `'aria-live' in src` (line 291) and `'assertive' in src` (line 292) against the full `utils.js` source — **before** `init_body` is sliced on lines 293–294.

If someone removed the `setAttribute('aria-live', ...)` calls from `init()` but left the JSDoc comment intact, lines 291–292 would still pass, while the actual aria contracts (which are verified by lines 295–296 against `init_body`) would remain correctly tested.

**Consequence:** Lines 291–292 are redundant with lines 295–296 and can mask a genuine regression if a code edit removes the `setAttribute` calls but leaves the comment. The critical checks are the `init_body` ones; the full-src checks add false confidence.

**Fix:** Remove lines 291–292 entirely. The `init_body` checks on lines 295–296 are the load-bearing assertions.

### F-005 · Dimension 1 (Accuracy) · LOW

**File:** `tests/test_pass37_a11y.py`  
**Line:** 136  
**Evidence lines:** 129–138

`test_37_4_target_blank_has_rel_noopener` checks only that a `rel=` attribute is present on `<a target="_blank">` tags — it does not check that the value includes `noopener` or `noreferrer`:

```python
if not re.search(r'\brel\s*=', tag, re.IGNORECASE):
    offenders.append(...)
```

The test docstring states _"ships rel=noopener noreferrer"_ but the assertion does not verify either token. A template edit changing `rel="noopener noreferrer"` to `rel="nofollow"` passes the test.

**Consequence:** The security contract (preventing opener access via `window.opener`) is not actually pinned. Today all templates use the full value (confirmed by grep), so there is no live vulnerability, but the test does not catch future regressions.

**Fix:** Tighten to: `if not re.search(r'\brel=["\'][^"\']*\bnoopener\b', tag, re.IGNORECASE):` — or split into two checks, one for `noopener` and one for `noreferrer`.

### F-010 · Dimension 6 (Test Isolation — resource hygiene) · LOW

**Files and lines:**
- `tests/test_migration_012.py:28` (`test_migration_012_creates_tables_and_columns`)
- `tests/test_migration_012.py:53` (`test_migration_012_is_idempotent`)
- `tests/test_migration_012.py:64` (`test_migration_012_indexes_present`)
- `tests/test_owner_id_self_heal.py:38` (`test_backfills_null_owner_ids…`)
- `tests/test_owner_id_self_heal.py:58` (`test_is_idempotent_noop_on_healthy_db`)
- `tests/test_owner_id_self_heal.py:75` (`test_skips_tables_that_do_not_exist`)
- `tests/test_owner_id_self_heal.py:84` (`test_skips_tables_without_expected_column`)

Seven test functions open `sqlite3.connect(':memory:')` (directly or via `_make_cursor_with_tables`) and never call `.close()` on the returned connection. Note: `test_owner_id_self_heal.py` returns `conn` from `_make_cursor_with_tables` and then uses `conn.cursor()` in each test, but `.close()` is never called.

**Consequence:** Under CPython's reference-counting GC, the connection is closed when the local variable goes out of scope at function return, so there is no practical impact in today's test runs. Under PyPy, or if `pytest-xdist` is introduced with process reuse, GC may not fire promptly, causing file-descriptor accumulation across a long test session. This is a robustness concern, not an active bug.

**Fix:** Wrap each `conn = sqlite3.connect(':memory:')` in `contextlib.closing(...)` or add an explicit `conn.close()` at the end of each test body.

### F-013 · Dimension 2 (Assertion Quality) · LOW

**File:** `tests/test_pass37_a11y.py`  
**Lines:** 197–198  
**Evidence lines:** 193–198

`test_37_6_base_flash_has_aria_live` uses compound `and` assertions:

```python
assert 'role="status"' in flash_zone and 'aria-live="polite"' in flash_zone
assert 'role="alert"' in flash_zone and 'aria-live="assertive"' in flash_zone
```

When one half fails, pytest reports a compound expression failure without identifying which attribute is absent.

**Consequence:** Debugging a failing aria-live regression requires manually bisecting each compound assertion. Minor inconvenience; no correctness impact.

**Fix:** Split into four separate assertions, each with a failure message:
```python
assert 'role="status"' in flash_zone, "flash zone missing role=status"
assert 'aria-live="polite"' in flash_zone, "flash zone missing aria-live=polite"
assert 'role="alert"' in flash_zone, "flash zone missing role=alert"
assert 'aria-live="assertive"' in flash_zone, "flash zone missing aria-live=assertive"
```
