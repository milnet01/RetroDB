## Findings

### Dimension 7 — Determinism

**MED** · `tests/test_launcher_registry.py:81–82`  
`test_gc_keeps_recent_exited` calls `time.time()` twice: once for `started_at=time.time()` (line 81) and once for `exit_time=time.time()` (line 82). If the scheduler yields between the two calls, `exit_time` could exceed `started_at + post_exit_ttl_s` (1.0 second), causing the GC to immediately collect the entry rather than keep it, turning the `assert registry.get('recent') is not None` at line 84 into a test failure.  
**Status:** RESIDUAL from prior synthesis (`.test-audit-reports-2/SYNTHESIS.md` LOW finding "Determinism/flakiness (LOW)" section, and explicitly listed under "Suggested roadmap shape" Pass H). v3.6.8 fixed the sibling `test_gc_removes_exited_after_ttl` (lines 65–69 now use a single `t = time.time()` baseline with a comment explaining why), but the `test_gc_keeps_recent_exited` twin was not fixed.  
**Consequence:** A scheduler preemption of >1 second between lines 81 and 82 — possible on a heavily loaded CI runner — causes a spurious test failure unrelated to the code under test.  
**Fix:** Add `t = time.time()` before line 81 and replace both calls: `started_at=t` and `exit_time=t`. Mirror the comment from the sibling fix: "Single wall-clock baseline keeps start/exit offsets internally consistent".

### Dimension 6 — Test Isolation

**MED** · `tests/test_launcher_factory.py:5–12`  
`_reset_singleton` (autouse, function-scoped fixture) resets `services.launcher._singleton` via direct attribute mutation (`launcher._singleton = None`) both before and after `yield`. If a collection-time error occurs in this file (not a test-execution failure — a collection/import error), pytest skips fixture teardowns and `_singleton` is left in whatever state the last test set it to.  
**Status:** RESIDUAL from prior synthesis (`.test-audit-reports-2/SYNTHESIS.md` MED "Isolation continuation" and `.test-audit-reports-2/c-003.md` MED finding under Dimension 6). v3.6.8 added `test_factory_defaults_to_local_when_setting_absent` but did not change the fixture itself.  
**Consequence:** Under a collection error, the global `_singleton` leaks across modules for the remainder of the pytest session, affecting any test that calls `get_launcher()` without its own reset.  
**Fix:** Replace the fixture body: use `import services.launcher as _lm; _lm._singleton = None; yield; _lm._singleton = None` — or preferably use `monkeypatch.setattr('services.launcher._singleton', None)` (monkeypatch restores even across collection-time errors). Note: `monkeypatch` is function-scoped, same as this fixture, so scoping is compatible.

### Dimension 1 — Accuracy

**MED** · `tests/test_input_hardening.py:33–58`  
`TestESDEPathTraversal.test_within_allowed_root_rejects_outside_paths` (lines 33–58) defines a local `check()` function (lines 40–51) that re-implements `_within_allowed_root` from `scraper/scrape_esde.py:819–832`. The local implementation is structurally identical to the production one (both use `os.path.realpath` + `os.path.commonpath`), but it is a copy, not an import. **Consequence:** A divergence in the production `_within_allowed_root` is invisible to this test. The test passes even if the real guard is broken.  
**Fix:** Either (a) extract `_within_allowed_root` to module scope in `scrape_esde.py` and import it directly, or (b) call `apply_esde_metadata` with a traversal-crafted XML and assert the path is not returned in the resulting media dict. Option (b) requires no production refactor.

### Dimension 3 — Coverage Gaps

`TestMuseumSSRFGuard` covers IPv4 private ranges (10.x RFC-1918, 127.x loopback, 169.254.x link-local) and disallowed schemes, but has no IPv6 test cases. So the production code is correct — but no test pins this for IPv6. A refactor that, say, adds a fast-path for "looks like an IPv4 literal" before the `ipaddress` check could silently skip IPv6.  
**Status:** RESIDUAL from prior synthesis (`.test-audit-reports-2/SYNTHESIS.md` MED "Coverage gaps" section; `.test-audit-reports-2/c-003.md` MED Dimension 3 finding). Confirmed unresolved: v3.6.8 added `monkeypatch.setitem` for TESTING isolation but added no IPv6 cases.  
**Consequence:** A regression in IPv6 handling is uncaught by the test suite.  
**Fix:** Add `test_ipv6_loopback_rejected` and `test_ipv6_link_local_rejected` in `TestMuseumSSRFGuard` using `http://[::1]/admin` and `http://[fe80::1]/foo` respectively (both require URL-encoding of bracket syntax).
