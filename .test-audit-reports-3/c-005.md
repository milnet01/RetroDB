#### H-1 — Isolation — `test_pass45_security.py` — 7 bare `app.config['TESTING'] = True` mutations with no teardown

**Dimension:** 6 (Test isolation)
**Severity:** HIGH
**File:** tests/test_pass45_security.py
**Lines:** 81, 237, 1257, 1421, 1445, 1538, 1602
**Summary:** Seven direct `app_module.app.config['TESTING'] = True` assignments across six test methods. None use `monkeypatch.setitem`. The prior v3.6.8 fix-pass missed this file entirely.
**Consequence:** Any test collecting after one of these that relies on `TESTING=False` sees the mutated global. The mutation is permanent for the process lifetime of that pytest worker — no fixture teardown can undo it.
**Fix:** Replace each with `monkeypatch.setitem(app_module.app.config, 'TESTING', True)`. The `monkeypatch` parameter is already injected by the containing test method or is available via the test signature.
**Evidence lines:** 81, 237, 1257, 1421, 1445, 1538, 1602

#### M-1 — Isolation — `test_pass41_security.py:848,849` — `hltb_lookup._auth_token` reset without restore

**Dimension:** 6 (Test isolation)
**Severity:** MED
**File:** tests/test_pass41_security.py
**Lines:** 848, 849
**Summary:** `hltb_lookup._auth_token = None` and `hltb_lookup._auth_token_time = 0` are direct attribute assignments with no monkeypatch teardown. If a prior test ran `_get_auth_token()` and cached a real token, this reset is correct. But if this test runs before a test that expects the cache to have been warm (or populated by a prior call), the sequence dependency is invisible.
**Consequence:** Any test after this one that relies on the token cache being in its pre-test state will silently observe `None` instead. The bug is ordering-dependent — it is silent in the current collection order but fragile under `--randomly-seed` or `pytest-xdist`.
**Fix:** `monkeypatch.setattr(hltb_lookup, '_auth_token', None)` and `monkeypatch.setattr(hltb_lookup, '_auth_token_time', 0)` — restore is then automatic.
**Evidence lines:** 842–855

#### M-2 — Isolation — `test_pass45_security.py:69–92` — `ROLE_PERMISSIONS['admin']` mutation via `try/finally` with asymmetric teardown

**Dimension:** 6 (Test isolation)
**Severity:** MED
**File:** tests/test_pass45_security.py
**Lines:** 69–92
**Summary:** `auth_mod.ROLE_PERMISSIONS['admin']` is reassigned inline (line 70) with `try/finally` restore (line 92). **Evidence lines:** 68–92

#### M-3 — Assertion quality — `test_pass41_security.py:97–126` — `src[A:B]` slice with no order guard

**Dimension:** 2 (Assertion quality)
**Severity:** MED
**File:** tests/test_pass41_security.py
**Lines:** 97–126
**Summary:** Both `test_change_password_does_not_pass_bare_ip_to_rate_limit` and `test_record_login_attempt_uses_composite_bucket` slice:
```python
body = src[
    src.index("def api_change_password"):
    src.index("def api_force_change_password")
]
```
No guard asserts that `api_change_password` precedes `api_force_change_password`. If the two functions are reordered, `src.index("def api_force_change_password")` may return an index before `api_change_password`, producing a negative-length empty slice. `assert "rate_limit_login(client_ip)" not in ""` passes vacuously and the test covers nothing.
**Consequence:** A refactor reordering the two password-change endpoints silently voids two rate-limit regression tests without failing.
**Fix:** Add `assert src.index("def api_change_password") < src.index("def api_force_change_password")` before slicing, or use `slice_function(src, "api_change_password")` from `tests._util`.
**Evidence lines:** 96–126

#### L-2 — Resource hygiene — `test_pass38_scrape_history_helper.py:21–36` — `connection` fixture does not close the sqlite3 connection

**Dimension:** 18 (Dangerous patterns)
**Severity:** LOW
**File:** tests/test_pass38_scrape_history_helper.py
**Lines:** 21–36
**Summary:** The `connection` fixture creates a `sqlite3.connect()` and `return conn` without a `try/finally conn.close()` or a `yield conn` with cleanup. Five test methods in `TestBuildScrapeHistoryJson` each receive this fixture and call `connection.cursor()` / `connection.commit()` but never close the connection. `tmp_path` will remove the file, but the connection object is not explicitly closed.
**Consequence:** Under CPython the reference-count mechanism closes the connection when the fixture falls out of scope. Under PyPy or `pytest-xdist` process reuse, the unclosed connection holds a WAL lock and can delay cleanup or cause `sqlite3.OperationalError: database is locked` on the next test in the same process.
**Fix:** Convert to `yield` fixture:
```python
try:
    yield conn
finally:
    conn.close()
```
**Evidence lines:** 20–36
