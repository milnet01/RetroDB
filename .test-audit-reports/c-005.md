## Findings by Dimension

### Isolation (dimension 6)

**FINDING ISO-1 — HIGH**  
File: `test_pass32_hardening.py`, line 199–208  
`test_32_14_ra_cache_is_bounded` writes directly into `ra._ra_console_cache` (a module-level dict) via `ra._ra_cache_set()` and never restores it. Any test that runs after this one in the same process and reads `ra._ra_console_cache` (including other hardening tests that exercise the cache path) will see a fully-populated cache of `limit` entries.  
Fix: Save `ra._ra_console_cache` before the loop and restore it in a `monkeypatch`/teardown, or use `monkeypatch.setattr(ra, '_ra_console_cache', {})` at the start.

**FINDING ISO-2 — HIGH**  
File: `test_pass33_34_hardening.py`, lines 117–131 (`test_33_9_rate_limit_functional`)  
The test manually calls `sec._login_attempts.clear()` under `sec._lock` at the start but does not restore the state on test exit. After the test runs, `_login_attempts` contains entries for IP `203.0.113.99` (the test doesn't reset on success). Any subsequent test that calls `rate_limit_login` or `record_login_attempt` for a random IP but with the rate-limiter reset elsewhere could still see stale lock state if test ordering changes.  
Fix: Use `monkeypatch` to replace `sec._login_attempts` with a fresh `OrderedDict()` for the duration of the test, which auto-restores on exit.

**FINDING ISO-3 — MED**  
File: `test_pass33_34_hardening.py`, lines 80–92 (`test_33_6_logout_clears_session`)  
The test imports `app as app_module` and sets `app_module.app.config['TESTING'] = True` directly on the shared app singleton without resetting it afterward. If other tests in the same session import the same app object and run in a state where `TESTING` is already `True` (benign) or, conversely, expect it to be `False`, this mutation is invisible.  
Fix: Use `monkeypatch.setitem(app_module.app.config, 'TESTING', True)` so the flag is restored, or use the standard Flask test-client approach via a session-scoped fixture.

### Flakiness (dimension 5)

**FINDING FLAKY-1 — MED**  
File: `test_pass33_34_hardening.py`, lines 201–225 (`test_34_5_log_filename_uses_utc`)  
The test patches `log_manager.datetime` with a custom subclass. The subclass overrides `datetime.now()` but does NOT override `datetime.utcnow()` or `datetime.today()`. If `get_log_filename` is ever refactored to use `datetime.utcnow()` instead of `datetime.now(tz=...)`, the monkeypatch silently stops working and the test passes for the wrong reason (the unfrozen clock would still return a date matching the test expectation most of the time, causing spurious passes rather than spurious failures).  
Fix: Also override `utcnow` in `_FixedDateTime`, or use `freezegun.freeze_time` which patches all datetime access points simultaneously.

**FINDING FLAKY-2 — LOW**  
File: `test_pass32_hardening.py`, lines 125–147 (`test_32_7_pin_host_ip_is_thread_local`)  
The thread started at line 143 is `join()`-ed correctly, so there is no race. However, the test accesses `sys.modules['services.ssrf']._pinned` directly by attribute name. If the module-level thread-local variable is renamed, the test silently returns `None` from `getattr(..., None)` and asserts `None is None` — a vacuous pass.  
Fix: Assert `captured['thread'] is None` AND add a guard that the attribute name exists on the module before the thread starts (import and `hasattr` check).

### Fixtures (dimension 12 / 16)

**FINDING FIX-1 — MED**  
File: `test_pass38_ra_check_helper.py`, lines 24–58 (`temp_db` fixture)  
The `temp_db` fixture uses `monkeypatch.setattr(_config, 'DB_PATH', ...)` and `monkeypatch.setattr(base_scraper, 'get_scraper_conn', _temp_conn)`. These monkeypatches are function-scoped (correct). However, the fixture also calls `conn.commit()` and `conn.close()` explicitly — the `tmp_path` fixture already handles directory cleanup. The concern is that if the fixture body raises between `conn = sqlite3.connect(...)` and `conn.close()`, the connection leaks. In CPython this is usually fine (GC closes it), but it's not explicit.  
Fix: Use a try/finally or a `with sqlite3.connect(...) as conn:` context manager inside the fixture.

**FINDING FIX-2 — LOW**  
File: `test_pass38_region_helper.py`, lines 27–42 (`stub_settings` fixture)  
The `stub_settings` fixture patches `sys.modules['settings_manager']` using `monkeypatch.setitem`. This is correct. However, the fixture returns a factory function (`_factory`) that the caller must call with a payload dict. If a test calls `stub_settings` but forgets to call the returned factory, `fake_module.load_settings` is undefined and will raise `AttributeError` — silently producing a different failure than intended. This pattern is non-obvious for future test authors.  
Fix: Rename to `stub_settings_factory` and add a docstring note, or use a two-argument fixture (`stub_settings(payload)`) via `pytest.fixture` with a `request` param. Alternatively, provide a sane default payload so calling without args still works.
