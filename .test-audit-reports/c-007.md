## MED

### MED-1 · isolation · `test_slow_query_log.py` lines 21–104
**Problem:** Manual `_CaptureHandler` + `try/finally` pattern used in all 6 tests instead of pytest's built-in `caplog` fixture.  
**Consequence:** If any test throws before entering its `try` block (unlikely, but possible if a future edit inserts code between `self._capture()` and `try:`), the handler is added to the `services.database` logger and never removed. Subsequent tests in the same session see extra handler instances, causing spurious log records that make `assert handler.records == []` fail.  
**Fix:** Replace `_capture()` + `try/finally` with `caplog` parameter (`caplog.set_level(logging.WARNING, logger='services.database')`) — pytest guarantees teardown even on unexpected exceptions, and the pattern is ~4 lines vs ~10.

### MED-2 · duplication · `test_scan_library_rom_path.py` lines 69–106 vs 189–225
**Problem:** `_FakeCursor` / `_FakeConn` classes are defined twice — once inside the module-level `_stub_db` helper and again inlined inside `test_run_inline_scan_uses_settings_manager_path`. The SQL routing logic (SELECT systems → row=(1,), SELECT games → row=None, INSERT → append) is verbatim identical.  
**Consequence:** If the scanner's DB schema changes (column name, query shape), the duplicate must be updated in two places. The two already diverged slightly (`_FakeConn.cursor()` in `_stub_db` returns `self._cursor` via instance attribute; the inline version creates a new `_FakeCursor()` on each `cursor()` call — line 213 vs 95). That difference is silent and could mask a bug where the cursor is called multiple times.  
**Fix:** Extend `_stub_db` to also accept a `get_db_with_context` connection style — or add a second module-level helper `_stub_db_context(monkeypatch, scan_mod)` that wraps the same `_FakeCursor`/`_FakeConn` in a context manager. Delete the inline duplicate.

### MED-3 · isolation · `test_security_headers.py` line 62
**Problem:** `test_hsts_absent_on_plain_http` mutates `app_module.app.config['SESSION_COOKIE_SECURE'] = False` with no `try/finally` and no restoration.  
**Consequence:** If `SESSION_COOKIE_SECURE` was `True` at test-start (e.g. CI sets `RETRODB_SECURE_COOKIES=1`), this test permanently sets it `False` for all tests that run after it within the module-scoped `client` fixture lifetime. `TestCspReportOnly` tests would then run under a different security posture than intended.  
**Fix:** Mirror the pattern already used by `test_hsts_present_when_secure_cookies_enabled` (lines 68–76) — save `original = app_module.app.config.get('SESSION_COOKIE_SECURE')` and restore in `finally`. Or use `monkeypatch.setitem(app_module.app.config, 'SESSION_COOKIE_SECURE', False)` (auto-restores).

## LOW

### LOW-1 · assertions · `test_security_headers.py` lines 102–103
**Problem:** `pat.search(...).group(1)` called without a None guard. If the nonce regex doesn't match (e.g. CSP format changes to double-quotes), this raises `AttributeError` rather than `AssertionError`.  
**Consequence:** CI log says `AttributeError: 'NoneType' object has no attribute 'group'` instead of a clear assertion failure — harder to diagnose.  
**Fix:** `m = pat.search(csp); assert m is not None, f"Nonce not found in CSP: {csp[:100]}"` then use `m.group(1)`.

### LOW-2 · coverage_gaps · `test_scan_library_rom_path.py` `_stub_db` lines 104–105
**Problem:** `_stub_db` only patches `get_scraper_conn` if `hasattr(scan_mod, 'get_scraper_conn')`. If a future refactor stops importing `get_scraper_conn` at module level (e.g. moves to a lazy import inside the function), the `hasattr` check silently returns False, the mock is not applied, and `scan_roms()` calls the real DB — but the test may still pass (or produce a confusing error) rather than failing loudly on the missing mock.  
**Fix:** Change the guard to an unconditional `monkeypatch.setattr(scan_mod, 'get_scraper_conn', lambda: _FakeConn())` (which raises `AttributeError` if the attribute is gone, making the failure explicit). The `if hasattr` guard hides a potential test-configuration error.

### LOW-3 · coverage_gaps · `test_scrape_fill_only.py` (whole file)
**Problem:** Both tests cover only the "empty API response preserves existing values" path. Neither test covers the path where `apply_metadata_to_game` returns `False` (or raises), which is the failure path the COALESCE invariant is designed to protect.  
**Consequence:** A regression that causes the function to return `False` silently (e.g. wrong game id, DB error) goes undetected by this contract-pinning suite.  
**Fix:** Add one test per scraper: `test_igdb_apply_returns_false_when_game_not_found` — use `_make_conn_with_existing_row` with id=1, call `apply_metadata_to_game(999, {...})`, assert `result is False` (or `pytest.raises(...)`).

### LOW-4 · assertions · `test_scan_library_rom_path.py` lines 254, 265
**Problem:** `pytest.raises(RomPathNotConfigured)` used without `match=` parameter on both `test_scan_roms_raises_when_path_empty` and `test_run_inline_scan_raises_when_path_empty`.  
**Consequence:** Any code path that raises `RomPathNotConfigured` (even one with an empty or misleading message) satisfies the test. The remediation message ("Go to Settings → Paths") is untested by this layer.  
**Fix:** Add `match=r'[Ss]ettings'` (or the expected message substring) to pin that the exception is user-actionable: `with pytest.raises(RomPathNotConfigured, match=r'[Ss]ettings')`.

### LOW-5 · verbosity · `test_slow_query_log.py` lines 28–104
**Problem:** The `try/finally` boilerplate is repeated in all 6 test methods (~4 lines each). With `caplog` (see MED-1) this collapses entirely; even without that change, the pattern could be extracted to a `@pytest.fixture` that adds/removes the handler via `yield`.  
**Consequence:** No functional bug — purely maintenance friction.  
**Fix:** Extract a `capture_db_log` fixture using `yield` (auto-teardown) to replace the 6 inline `try/finally` blocks.

### LOW-6 · doc_strings · `test_terminal_status.py` lines 11–38
**Problem:** None of the 4 top-level test functions have docstrings. The module docstring explains the contract well, but individual tests lack the one-line rationale for *why* each variant matters.  
**Consequence:** Low — but the module docstring specifically calls out the SIGTERM / user-cancel distinction; the test for `cancelled=True` with `shutdown_requested` set (the subtlest invariant) has no inline explanation of why shutdown must win.  
**Fix:** Add a one-line docstring to `test_shutdown_takes_precedence_over_user_cancel` explaining the SIGTERM drain scenario (the comment block at lines 22–25 already has the words; promote to docstring).

### LOW-7 · naming · `test_scrape_fill_only.py` line 60
**Problem:** Fixture named `_noop_download` with a leading underscore. In pytest, leading-underscore names signal "private helper, not a fixture" by convention — but pytest discovers it normally when explicitly requested. This is inconsistent with the rest of the test suite.  
**Consequence:** A reader unfamiliar with the project may not realize `_noop_download` is a pytest fixture (vs a module-level helper function) and may be confused by its appearance in the test signatures.  
**Fix:** Rename to `noop_download` (no leading underscore). Pytest fixture naming convention does not use underscores to indicate scope.
