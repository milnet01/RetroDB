## Performance

### PERF-1 · HIGH · `test_auth_hashing.py` lines 19, 31–33, 65–66
**Problem:** Four `hash_password()` calls run at the production PBKDF2 iteration count of 600,000. Each costs ~0.3–0.8 s on typical hardware; together they add ~1.5–3 s to every test run, even when unrelated code changes.

**Files/lines:** `test_auth_hashing.py:19`, `:31`, `:65` (plus `verify_password` at `:32–33` which also runs 600k internally).

**Consequence:** This single file contributes the majority of CI wall-time for the test suite's unit tier. As the suite grows, the cost compounds.

**Fix:** Call `hash_password("x", iterations=1)` (or a small test constant like 1000) in every test that checks format/structure/round-trip. Reserve the full production iteration count for exactly one dedicated test that asserts `PBKDF2_ITERATIONS` is still ≥ 600,000 — that test documents the compliance floor without paying the cost everywhere.

## Isolation

### ISO-1 · MED · `test_auth_hardening.py` lines 204–205
**Problem:** `_isolated_db()` resets `database._db_pool = {}` via a bare assignment rather than `monkeypatch.setattr`. `monkeypatch` does restore `config.DB_PATH`, but the pool dictionary is permanently discarded for the rest of the process. If a later test (in a different class or module) calls `get_db()` and expects a warm pool, it will open a fresh connection to whatever `config.DB_PATH` is at that point — which after `monkeypatch` teardown is the real DB path, so the connection is correct, but the pool warming that may have happened earlier is silently lost.

**Evidence:** `test_auth_hardening.py:204–205`
```python
if hasattr(database, '_db_pool'):
    database._db_pool = {}
```

**Fix:** Replace with `monkeypatch.setattr(database, '_db_pool', {})` so pytest automatically restores the original pool reference after the test.

## Duplication

### DUP-1 · MED · `test_auth_hashing.py` lines 40–43 and 49–52
**Problem:** The legacy-hash construction block (`password = "legacy_password"` / `salt = "deadbeef" * 4` / `hashlib.pbkdf2_hmac(...)` / `legacy_stored = f"{salt}:{legacy_hash}"`) is copy-pasted verbatim across `test_verify_accepts_legacy_format` and `test_needs_rehash_flags_legacy_format`.

**Consequence:** A change to the legacy format (e.g. different salt length) requires editing both tests; drift is likely since nothing enforces they stay in sync.

**Fix:** Extract to a module-level helper `def _make_legacy_hash(password="legacy_password")` returning `legacy_stored`, or use a `@pytest.fixture`. Call it from both tests.

## Security

### SEC-1 · MED · `test_auth_hardening.py` line 261
**Problem:** The string `AIzaSyABCDEFGHIJKLMNOPQRSTUVWXYZ01234567` uses the real Google API key prefix `AIzaSy`. Gitleaks ships a built-in `google-api-key` rule (`AIza[0-9A-Za-z\-_]{35}`); this string is 40 chars total / 36 after `AIza`, which is one character over the rule's match length — so today it likely slips through. However, the sequential suffix is not guaranteed to stay outside the gitleaks pattern window across rule updates, and `test_auth_hardening.py` is not in `.gitleaks.toml`'s path allowlist.

**Consequence:** A gitleaks rule update (or a different scanner) will start failing the pre-commit hook on this file. The string also desensitises reviewers to real `AIzaSy` leaks by normalising the prefix in test code.

**Fix:** Replace with a prefix that is obviously not a real key format, e.g. `FAKE_API_KEY_ABCDEFGHIJKLMNOPQRSTUVWXYZ01`. The test is asserting the *redactor* works — the key value itself is irrelevant; it just needs to match the field-name trigger `api_key=`. Alternatively, add `tests/test_auth_hardening\.py` to `.gitleaks.toml` with a scoped regex allowlist matching only this test class.

## Accuracy

### ACC-1 · LOW · `test_auth_hardening.py` lines 34–54 (multiple source-grep tests)
**Problem:** Several tests in `TestPasswordRequiredForAllRoles` assert that specific string literals exist in the source of `routes/auth.py` (e.g. `"This account has no password set"`, `"password_hash = None"`). Source-grep tests pass even when the code path containing the string is dead code, unreachable, or inside an `if False:` block. They also break silently on legitimate message rewording.

**Evidence lines:** 42–45, 51–54.

**Consequence:** A refactor that renames the error message to `"Account has no password configured"` will fail this test even though the behaviour is correct. Conversely, a regression that makes the check unreachable won't be caught.

**Fix:** These are explicitly acknowledged in the file header (lines 1–19) as narrow "code-path pin" checks used where full integration tests are impractical. The finding stands at LOW severity — the tests provide value by preventing certain regressions — but each source-grep assertion should be paired with at least one behavioural assertion (even a minimal one that actually calls the auth flow) to close the "string in dead code" loophole.

### ACC-2 · LOW · `test_auth_hardening.py` lines 64–73
**Problem:** `test_login_calls_session_clear` verifies ordering by finding `session.clear()` and `session['user_id'] = user['id']` in source text and comparing their character indexes. This passes as long as the strings appear in order anywhere in the file — including in comments, docstrings, or strings inside unrelated functions.

**Consequence:** Adding a comment like `# we used to do: session['user_id'] = ...` above the `session.clear()` call would cause this test to report a false pass. The ordering contract is important for session fixation prevention but the test doesn't actually guarantee it.

**Fix:** The functional `TestDestructiveEndpointsRequireAuth` pattern below (line 297) is the right model — exercise the real login endpoint with a test client, verify session state before and after. The source-index check can be removed once a behavioural test covers the ordering.

## Verbosity / Parametrisation

### VERB-1 · LOW · `test_auth_hashing.py` lines 69–80
**Problem:** `test_needs_rehash_flags_malformed_hash` and `test_verify_rejects_malformed_hash` each test multiple independent inputs in a single function body. The inputs are structurally identical — different malformed strings fed to the same function.

**Evidence:** Lines 72–74 (3 `needs_rehash` calls), 78–80 (3 `verify_password` calls).

## Fixtures

### FIX-1 · LOW · `test_atomic_io.py` lines 14–76 (all 6 tests)
**Problem:** All tests use `tempfile.TemporaryDirectory()` as an inline context manager rather than pytest's `tmp_path` fixture. `tmp_path` is the idiomatic pytest approach, provides test-labelled paths in CI artefacts (making post-failure inspection easier), and integrates with pytest's `--basetemp` override.

**Consequence:** No functional problem, but debugging a failing test on CI requires inferring which `/tmp/tmpXXXXXX` directory corresponds to which test.

**Fix:** Accept `tmp_path` as a parameter and replace `with tempfile.TemporaryDirectory() as tmp:` + `os.path.join(tmp, ...)` with `path = tmp_path / "settings.json"` (pathlib). Also remove the `import tempfile` import.
