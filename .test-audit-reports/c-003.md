## Test isolation (dim 6)

### ISO-1 — HIGH
**File:** `tests/test_input_hardening.py:52–53`  
**Problem:** `app_module.app.config['TESTING'] = True` mutates the global Flask application config object in-place with no teardown. If this test runs before a test that expects `TESTING` to be `False`, the leftover mutation leaks.  
**Consequence:** Test-ordering dependent behaviour; in parallel runs (`pytest-xdist`) this is a race. A test in another file that checks `app.config['TESTING']` would see the contaminated value.  
**Fix:** Use `monkeypatch.setitem(app_module.app.config, 'TESTING', True)` — pytest resets it automatically after the test.

## Security (dims 17–18)

### SEC-1 — LOW
**File:** `tests/test_input_hardening.py:131`  
**Problem:** `src = open(mod.__file__).read()` uses bare `open()` without a context manager (`with`). The file handle is leaked if the `.read()` raises (e.g. `PermissionError` on a pyc-only install).  
**Consequence:** Unclosed file handle; in a long test session or on constrained CI, this contributes to fd exhaustion.  
**Fix:** `with open(mod.__file__, encoding='utf-8') as f: src = f.read()`

### SEC-2 — LOW
**File:** `tests/test_hltb_endpoint.py:63–78` (`test_no_residual_stale_paths`)  
**Problem:** The stale-URL check skips lines that contain `"""` or `'''` to exempt docstrings, but it checks line-by-line and only skips lines where a triple-quote appears on that line. Body lines of multi-line docstrings that contain `/api/find/init` (without triple quotes on the same line) would not be skipped and would trigger a spurious assertion failure.  
**Consequence:** The test is a false-negative time bomb: currently safe because the only `/api/find` reference in the module docstring body does not include a trailing slash (`/api/find →` not `/api/find/`). If a future documentation line adds `/api/find/init` to a docstring body, CI breaks with a misleading error.  
**Fix:** Track `in_docstring` state across lines, or use Python's `ast` module to strip docstrings before the pattern search.

### SEC-3 — INFO
**File:** `tests/test_input_hardening.py:43–55` (`_insert_job` in test_job_history_sweep.py:43–54`)  
**Problem:** `_insert_job` builds SQL via f-string with `completed_days_ago` interpolated. In this test file it is always called with integer literals or `None`, so there is no injection risk in practice. Flagged for completeness — the pattern is a SQL-injection smell in test helper code, even though the call sites are controlled.  
**Note:** `pyproject.toml` suppresses `S608` (hardcoded SQL) globally for the test dir. This is documented and intentional. No action required.
