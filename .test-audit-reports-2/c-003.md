### Dimension 3 — Coverage gaps

**MED** `tests/test_input_hardening.py:85–119` — `TestMuseumSSRFGuard` covers RFC-1918 (10.x), loopback (127.x), link-local (169.254.x), and non-HTTPS schemes, but no IPv6 private ranges (`::1`, `fc00::/7`, `fe80::/10`). If the underlying `_is_public_https_url`/`validate_outbound_url` rejects IPv6 loopback via a separate code path, a regression there would not be caught. This was called out in the prior SYNTHESIS as still open ("IPv6 private-range SSRF rejection untested — only IPv4 covered"). · Fix: Add `test_ipv6_loopback_rejected` and `test_ipv6_link_local_rejected` using `http://[::1]/admin` and `http://[fe80::1]/foo`.

**MED** `tests/test_hybrid_scraper.py` (whole file) — `_pick_best_fallback` and `_pick_best_secondary` are never called with an empty list (`[]`). The docstring says `_pick_best_fallback` returns `None` when there are no results — that path is untested. A regression that turns an empty-list call into an `IndexError` or `StopIteration` escape would not be caught. · Fix: Add `test_pick_best_fallback_empty_list_returns_none` and `test_pick_best_secondary_empty_list_returns_none`.

**LOW** `tests/test_image_pipeline.py` (whole file) — `finalize_downloaded_image` with a corrupt/unreadable source file is not covered at the integration level (`TestFinalizePipeline` only covers the happy path). `TestFormatNormalize.test_unidentified_image_error_handled` covers `_ensure_format_matches_extension` in isolation, but the full pipeline behaviour on a corrupt input (does it propagate, swallow, or leave artefact variant files?) is unverified. · Fix: Add `test_pipeline_corrupt_bytes_does_not_raise` at the `TestFinalizePipeline` level mirroring the isolation test.

**LOW** `tests/test_metadata_merger.py:259–264` — `TestApplyRawg.test_franchise_only_fills_empty` tests with `fill_only=False` and verifies `'Existing'` is preserved (because franchise always ignores the flag and only fills when empty). But there is no matching test with `fill_only=True` to confirm the invariant holds from that direction too. The comment on line 262 documents the contract; a test confirming `fill_only=True` also preserves existing franchise would be the minimum pin. · Fix: Add `test_franchise_preserved_when_fill_only_true`.

**LOW** `tests/test_launcher_factory.py` — `test_factory_raises_for_remote_in_v1` and `test_factory_raises_for_unknown` pin error raises, but neither checks the exception message. A refactor that changes `NotImplementedError("remote backend not implemented in v1")` to a bare `NotImplementedError()` would pass both tests silently. · Fix: Add `match=r"remote"` / `match=r"spaceship"` to the `pytest.raises` context managers.

### Dimension 5 — Flakiness risk

**MED** `tests/test_launcher_registry.py:81–82` — `test_gc_keeps_recent_exited` calls `time.time()` twice at lines 81 and 82 to set `started_at` and `exit_time` respectively. If the scheduler yields between the two calls, `exit_time` could be fractionally newer than `started_at + post_exit_ttl_s`, causing the GC to immediately collect an entry that should survive. The prior SYNTHESIS flagged the `test_gc_removes_exited_after_ttl` twin-call at lines 64-66 and it was fixed (single `t = time.time()` baseline). The `test_gc_keeps_recent_exited` case was not fixed. · Fix: Add `t = time.time()` before line 81 and use `started_at=t` / `exit_time=t` (same single baseline as the sibling test).

Note: `test_launcher_local.py:27` (pre-pass finding) — `time.sleep(0.05)` inside `_poll_exited` is an intentional polling interval with a `pytest.fail()` on deadline breach. This is the fixed form of the pattern cited in the prior SYNTHESIS (which flagged the old bare poll loops at lines 46/66/101 with no diagnostic). The prior finding was already resolved. See "False positives ruled out" section below.

### Dimension 6 — Test isolation

**MED** `tests/test_launcher_factory.py:5–12` — `_reset_singleton` (autouse fixture) directly mutates `services.launcher._singleton = None` rather than using `monkeypatch.setattr`. The `yield`-based teardown guarantees cleanup under normal pytest flow, but if a test in this file causes a collection error (not a test failure — a collection/import error), pytest does not run fixture teardowns before the error propagates, leaving `_singleton` set. · Fix: Replace with `monkeypatch.setattr('services.launcher._singleton', None)` in the fixture body; pytest's monkeypatch is guaranteed to restore even across collection errors.

**LOW** `tests/test_log_redactor.py:94–131` — `TestInstallGlobalRedactor` tests now include `try/finally` blocks that strip `SecretRedactor` from `root.filters` after each test. This addresses the prior SYNTHESIS HIGH finding (`test_log_redactor.py:94-105`). The cleanup in `test_install_covers_basicconfig_handler` (lines 128–131) strips from both `root.filters` and removes the `StreamHandler`. However, if `log_manager.install_global_redactor()` also mutates handler-level filters (not just `root.filters`), the cleanup may be incomplete for any other handler already on the root logger at test time. · Fix: Scope `root.handlers` snapshot before and restore after, or use `monkeypatch` to reset `root.filters` automatically.

## False Positives Ruled Out

**Pre-pass finding: `tests/test_launcher_local.py:27` — `sleep_call`**

Verdict: **mitigated**. The `time.sleep(0.05)` at line 27 is inside the `_poll_exited` helper, not in a test body directly. The helper:
1. Is gated by a `deadline = time.time() + deadline_s` loop that caps total wait at 2 seconds.
2. Calls `pytest.fail(f"timed out waiting for state; last={st!r}")` on deadline breach — giving a diagnostic rather than a silent hang.

This is the exact fix recommended in the prior SYNTHESIS for the old bare poll loops (`test_launcher_local.py:46/66/101`). The pre-pass grep hit on the sleep inside the helper, not on a bare sleep-and-assert. **No action required.**
