## Findings

### Dimension 6 — Test Isolation

#### MED · `tests/test_observability.py:26`

`app_module.app.config['TESTING'] = True` is set inside the `client` fixture without a matching restore. The fixture explicitly documents restoring two other globals (log-record factory at line 37 and `_request_id_installed` at line 38), so the omission of TESTING is notable — a reader who trusts the docstring is misled about the isolation provided.

**Consequence:** `app.config['TESTING']` is permanently `True` for all tests that run after this fixture in the same pytest session. No test currently requires `TESTING=False` so there is no live breakage, but the fixture's own documentation contracts more isolation than it delivers, and the omission will cause a hard-to-diagnose failure if any future test depends on the default value.

**Fix:** Capture `_orig_testing = app_module.app.config.get('TESTING')` before `yield`; restore it in teardown. Or switch to `monkeypatch.setitem(app_module.app.config, 'TESTING', True)` — the pattern already used in the sibling test `test_33_6_logout_clears_session` in the same suite.

#### MED · `tests/test_pass31_migrations.py:183–187`

`migrations.MIGRATIONS` is mutated via bare `try/finally` instead of `monkeypatch`:

```python
real = migrations.MIGRATIONS
try:
    migrations.MIGRATIONS = real[:4]
    migrations.apply_pending(conn)
finally:
    migrations.MIGRATIONS = real
```

`test_migrations.py:324–329` performs the identical operation with `monkeypatch.setattr`, accompanied by an explicit comment: *"Use monkeypatch (not try/finally) so the global list is restored even if the test is killed mid-run (SIGKILL/OOM)."* The sister file documents the preferred pattern; this file is the one remaining unconverted site in the chunk.

**Consequence:** If the process is killed (SIGKILL, OOM eviction, hard timeout) after line 184 but before line 187 executes, `migrations.MIGRATIONS` is left as `real[:4]` for the rest of the pytest session. All subsequent migration tests silently operate on an incomplete four-migration chain and may produce false passes on schemas they never validated.

**Fix:** Accept `monkeypatch` as a parameter to `test_legacy_gap_rows_backfill_to_admin`; replace the inner `try/finally` block with `monkeypatch.setattr(migrations, 'MIGRATIONS', real[:4])`.

#### LOW · `tests/test_pass37_a11y.py:136`

`test_37_4_target_blank_has_rel_noopener` checks only that a `rel=` attribute is present on `<a target="_blank">` tags, not that the value includes both `noopener` and `noreferrer`:

```python
if not re.search(r'\brel\s*=', tag, re.IGNORECASE):
    offenders.append(...)
```

A link with `rel="nofollow"` passes. The docstring says "ships rel=noopener noreferrer" but the assertion doesn't verify it.

**Consequence:** A template edit that changes `rel="noopener noreferrer"` to `rel="nofollow"` passes the test despite omitting the security requirement. Today all templates use the full value (grep-confirmed), so no live breakage, but the test doesn't pin the contract it claims to.

### Dimension 2 — Assertion Quality

#### LOW · `tests/test_pass37_a11y.py:197–198`

`test_37_6_base_flash_has_aria_live` chains two independent boolean conditions per assertion with `and`:

```python
assert 'role="status"' in flash_zone and 'aria-live="polite"' in flash_zone
assert 'role="alert"' in flash_zone and 'aria-live="assertive"' in flash_zone
```

When either half fails, pytest shows `AssertionError` with the full compound expression but no diff or indication of which half is false.

**Consequence:** Debugging a failing aria-live regression requires manually re-running each half of the compound assertion to determine which attribute is absent.

**Fix:** Split into four separate assertions, each with an `f"…"` failure message:

```python
assert 'role="status"' in flash_zone, "flash zone missing role=status"
assert 'aria-live="polite"' in flash_zone, "flash zone missing aria-live=polite"
assert 'role="alert"' in flash_zone, "flash zone missing role=alert"
assert 'aria-live="assertive"' in flash_zone, "flash zone missing aria-live=assertive"
```

### Dimension 6 — Test Isolation (resource hygiene)

#### LOW · `tests/test_migration_012.py:28,53,64`

Three test functions open `sqlite3.connect(':memory:')` and never call `.close()`:
- `test_migration_012_creates_tables_and_columns` (line 28)
- `test_migration_012_is_idempotent` (line 53)
- `test_migration_012_indexes_present` (line 64)

**Consequence:** Under CPython, reference counting closes the connection immediately, so there is no practical impact today. Under PyPy or with `pytest-xdist` process reuse, GC may not fire before the next test acquires resources, causing file-descriptor exhaustion on long suites.

**Fix:** `with contextlib.closing(sqlite3.connect(':memory:')) as conn:` or explicit `conn.close()` at end of each test body.

---

#### LOW · `tests/test_owner_id_self_heal.py:38,58,72,82`

Same pattern: four test functions in this file open in-memory SQLite connections via `_make_cursor_with_tables` or direct `sqlite3.connect(':memory:')` and never explicitly close them. (The helper `_make_cursor_with_tables` returns the connection to the caller, which then uses `cursor = conn.cursor()` but never calls `conn.close()`.)

**Fix:** Same as above — add `conn.close()` at the end of each test body, or wrap in `contextlib.closing`.
