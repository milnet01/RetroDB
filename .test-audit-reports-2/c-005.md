## Dimension scan results

### Isolation (dimension 6) — HIGH

**`tests/test_pass41_security.py:1102` — bare `app_module.app.config['TESTING'] = True` with no teardown (HIGH)**
`test_admin_cleanup_endpoint_requires_editor` in `TestPass41_11BMuseumGetIdempotent` assigns directly to the Flask singleton's config dict. The companion tests in the same class (`test_post_rejects_attacker_chdman_path`, `test_convert_e2e_rejects_traversal` etc.) all use `monkeypatch.setitem` correctly. This one is the sole survivor without that protection. If the test is collected before a test that expects `TESTING=False`, the value bleeds.
- Fix: `monkeypatch.setitem(app_module.app.config, 'TESTING', True)` (same pattern as lines 224, 330, 405, 462, 553 in the same file).

**`tests/test_pass45_security.py:81,237,1257,1421,1445,1538,1602` — 7 bare `app_module.app.config['TESTING'] = True` with no teardown (HIGH)**
`test_pass45_security.py` has 7 direct assignments to the singleton Flask app config. None use `monkeypatch.setitem`. They span 6 distinct test methods across `TestPass45_1`, `TestPass45_3AiFillIntFields`, and several others later in the file. Any run ordering that places these tests before a test sensitive to the TESTING flag will observe the mutated global.
- Fix: replace all 7 occurrences with `monkeypatch.setitem(app_module.app.config, 'TESTING', True)`.

**`tests/test_pass41_security.py:848,849` — `hltb_lookup._auth_token = None; hltb_lookup._auth_token_time = 0` without restore (MED)**
`test_hltb_returns_none_on_total_failure` directly resets two module-level cache attributes. `http_get/http_post` are properly monkeypatched via fixture, but the cache attributes are not. If a prior test ran `_get_auth_token()` and cached a real token (possible in integration test order), resetting to None forces a re-auth call. More importantly: if a subsequent test in the same session expects the cache to survive across calls, it will silently miss. Should use `monkeypatch.setattr`.
- Fix: `monkeypatch.setattr(hltb_lookup, '_auth_token', None); monkeypatch.setattr(hltb_lookup, '_auth_token_time', 0)`.

**`tests/test_pass45_security.py:70,92` — `auth_mod.ROLE_PERMISSIONS['admin']` mutated in try/finally with no monkeypatch (MED)**
`test_permission_denied_on_api_returns_403_json` saves and restores via try/finally correctly at the logic level, but the outer `app_module.app.config['TESTING'] = True` (line 81, inside the try) is not restored. If the test raises inside the try block before the finally, TESTING is left True and the permission set is restored — asymmetric state. The fix is to use `monkeypatch.setitem` for the TESTING flag (covered by the HIGH finding above) and optionally `monkeypatch.setattr` for `ROLE_PERMISSIONS['admin']` to make teardown atomic.
- Fix: Convert to `monkeypatch.setitem`/`monkeypatch.setattr` for both mutations so pytest's unwind handles teardown even on unexpected failures.

### Dangerous patterns in test code (dimension 18) — HIGH

**`tests/test_pass40_security.py:921` — `open(path).read()` bare file open inside a loop with no context manager (HIGH)**
`test_no_bare_time_sleep_in_jobs` opens five source files with `src = open(path).read()` bare (no `with` block). If any open raises (e.g., file moved or permissions changed mid-run), the file descriptor leaks. This is also the pattern the synthesis (c-003/c-006 theme "bare open without context manager") called out elsewhere as a LOW finding. Here, it's inside a loop and thus potentially 5 leaked descriptors.
- Fix: `with open(path, encoding='utf-8') as f: src = f.read()` (matches the pattern used in the adjacent method `test_each_job_imports_shutdown_event`).

**`tests/test_pass40_security.py:1017,1040,1053,1074,1084,1201` — 6 more bare `open(path).read()` in TestPass40_12/13/14/16 (MED)**
Six additional direct `src = open(path).read()` calls in `TestPass40_12ToastControllerXss`, `TestPass40_13ShowModalOptInHtml`, `TestPass40_14PsnTrophyDetailXss`, and `TestPass40_16ProxyDeployDocs`. Unlike the loop case (HIGH), each is a single file with no loop — resource risk is bounded to 1 fd per test — but the pattern is inconsistent with the rest of the file (all `_read()` helpers and `read_module_source()` calls use context managers).
- Fix: wrap each in `with open(..., encoding='utf-8') as f: src = f.read()`.

**`tests/test_pass41_security.py` — ~51 bare `body = open(...).read()` calls throughout the file (MED)**
Unlike test_pass40 (which was migrated to `read_module_source()` helpers per c-006 DU-1), test_pass41 retained the direct `open(path).read()` pattern across essentially every source-grep test method (~51 occurrences, confirmed via grep). They are consistently `open(os.path.join(_REPO_ROOT, ...), encoding='utf-8').read()` — readable and portable, but not context-managed. On Python ≥ 3.12 CPython still closes via reference count, but the pattern is fragile under alternate implementations and discourages adopting the shared `read_source()` helper that was extracted for this exact purpose.
- Fix: extract to a `_read(rel)` method (see `TestPass41_2AMigrationDeferForeignKeys._read` at line 225 — the pattern already exists twice in the file) or route through `tests._util.read_source`.

### Accuracy / assertion quality (dimension 1, 2) — MED

**`tests/test_pass40_security.py:175–178` — disjunctive source-grep assertion (MED)**
`test_post_handler_requires_admin`:
```python
assert "g.user.get('role') != 'admin'" in body or \
       "g.user['role'] != 'admin'" in body
```
The disjunction is legitimate (two syntactically equivalent patterns to account for style variation), so the OR is not vacuous per se. However, neither branch pins that the check is actually inside the POST branch of the function — both strings could appear in a comment within the 1500-character window without the guard being live code. The companion test `test_post_rejects_attacker_chdman_path` provides the behavioural coverage, so this is LOW consequence — but the assertion would pass if both forms were only in comments.
- Fix: strip comments via `re.sub(r'#[^\n]*', '', body)` before the assert (same technique used at line 1044–1046 in `test_no_includes_lt_gt_heuristic` in the same file).

**`tests/test_pass41_security.py:97–126` — source-grep on two `api_change_password` functions slices from `src.index(A)` to `src.index(B)` with no guard that A precedes B (MED)**
`test_change_password_does_not_pass_bare_ip_to_rate_limit` and `test_record_login_attempt_uses_composite_bucket` both do:
```python
body = src[
    src.index("def api_change_password"):
    src.index("def api_force_change_password")
]
```
If a refactor renames or reorders the two functions, `src.index("def api_force_change_password")` would search the entire file and potentially return an index before `api_change_password`, silently handing the test a negative-length slice (empty string). `assert "rate_limit_login(client_ip)" not in ""` is vacuously True and the test passes while covering nothing.
- Fix: assert `src.index("def api_change_password") < src.index("def api_force_change_password")` before slicing, or use a dedicated `slice_function(src, "api_change_password")` helper.

**`tests/test_pass41_security.py:995–1000` — `'Pass 41.8' in body` comment-marker pin (LOW)**
`test_null_userid_invariant_documented` checks that `'Pass 41.8'` marker exists in `routes/achievements.py`, then scans a 800-char window for `'009'` and `'user_id IS NULL'`. If the surrounding docstring is reformatted and the marker migrates beyond the window, the secondary assertions fire as false-positives. The prior synthesis already flagged this pattern family (comment-marker presence) as LOW but legitimate for hard-to-test invariants. No new action required beyond what synthesis noted.
- Fix (LOW): widen window or use `body.find('Pass 41.8')` with a larger offset so reformats don't silently break the window.

### Verbosity / parametrisation (dimension 13) — MED

**`tests/test_pass40_security.py:100–158` — `test_bool_fields` loops over 9 keys inline rather than parametrizing (MED)**
`TestPass40_1OtherSettingsValidators.test_bool_fields` loops over a 9-element tuple inline:
```python
for key in ('recursive_scan', 'verify_integrity', 'generate_m3u', ...):
    ok, _, cleaned = validate_rom_tools_value(key, True)
    assert ok and cleaned is True, f"{key} should accept True"
```
When any key fails, the loop stops at that key and the rest are untested. A parametrized form would report the exact failing key name in pytest output and run all 9 assertions regardless of individual failures.
- Fix: `@pytest.mark.parametrize('key', ['recursive_scan', 'verify_integrity', ...])` and split accept/reject into separate parametrized tests.

**`tests/test_pass41_security.py:1367–1400` — `test_each_scan_requires_editor` loops over 5 routes inline (MED)**
Same loop anti-pattern: if the first scan route is missing `@editor_required`, the assert fires and the remaining 4 routes are not checked. Pytest output names only the enclosing test method, not the failing route.
- Fix: `@pytest.mark.parametrize('route', SCAN_ROUTES)` so each route gets its own test node.

**`tests/test_pass41_security.py:1395–1408` — `test_rate_limits_registered` loops over function names (LOW)**
Same pattern: inline loop over `('tools.api_archive_scanner_scan', ...)` with `assert fn in body`. One failing name stops the loop.
- Fix: parametrize.

### Coverage gaps (dimension 3) — MED

**`tests/test_pass41_security.py` — `test_hltb_returns_none_on_total_failure` does not cover `_search_hltb` when auth token retrieval succeeds but search itself fails (MED)**

- Fix: add `test_select_pip_args_falls_back_when_lockfile_missing(tmp_path)` that calls `select_pip_args(tmp_path)` (no lockfile) and asserts the `source == 'requirements'` or equivalent fallback path.

### Performance (dimension 15, 16) — LOW

**`tests/test_pass46_frozen_paths.py:62–101` — `TestPass46_3_FrozenModeSplit.test_split_takes_effect_when_frozen` evicts and re-imports `app` + `config` mid-test (LOW)**
The test manually pops and re-imports several modules (`config`, `settings_manager`, `log_manager`, `routes.scraper`, `app`) — this is correct for the frozen-mode simulation but makes the test ~300–400ms on a warm import. It also explicitly warns "Dependent modules snapshot `config.BASE_DIR` at import time", meaning any order change that causes `app` to be imported earlier would mutate the module cache and make the test's cleanup insufficient. The `reloaded_app` fixture at line 131 uses the same pattern more cleanly.
- Fix (LOW): consolidate the frozen-mode test under the `reloaded_app` fixture pattern; let the fixture handle the cleanup order.

**`tests/test_pass41_security.py:683–743` — `test_each_start_acquires_lock_with_correct_name` starts 9 job classes in a single test method (LOW)**
The method loops over `JOB_MODULES`, instantiates each class, calls `start()`, and makes assertions. A failure on the 5th job class (`PSNRefreshJob`) leaves the remaining 4 unexercised and provides no pytest parametrize node name to identify the offender quickly.
- Fix (LOW): `@pytest.mark.parametrize('modname,clsname,expected_name', JOB_MODULES)` — already available as a class attribute. Three-line change.
