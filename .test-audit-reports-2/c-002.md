**MED** · `tests/test_emulator_registry_routes.py:21` — `test_mutating_routes_require_admin` is pure source-grep with no behavioural assertion. `assert '@admin_required' in src or "permission_required(...)" in src` passes if the decorator appears anywhere in the file, including in a comment or dead function. Behavioural tests (`test_viewer_cannot_create`, `test_viewer_cannot_delete`) exist on lines 109–137 and cover the contract; the grep is superfluous but misleading as the only check in that named test. Fix: either delete the source-grep test (the behavioural tests are the real pin) or pair it with `assert rv.status_code in (302, 403)` from a viewer-role client and rename it to reflect what it checks.

**LOW** · `tests/test_game_query.py:52` — `assert 42 in vals or '42' in vals` is a disjunctive type-ambiguous check. **LOW** · `tests/test_game_query.py:67` — `assert "'Z'" in str(vals) or 'Z' in vals` converts the whole list to a string and substring-searches it, which would pass for `['ZERO']` (contains 'Z'). Fix: `assert 'Z' in vals` directly (exact element membership).

**LOW** · `tests/test_emulator_autodetect.py:45–49` — `test_walk_finds_all_appimages` uses five consecutive `assertIn` calls, none checking that the returned list contains *only* expected names. A walk that includes every file on disk would still pass. Fix: assert `paths == sorted([...expected...])` on the known-structure fixture, or at minimum assert `len(paths) == 5`.

## B. Reliability & Isolation

### Dimension 5 — Flakiness risk

**HIGH** (pre-existing, per synthesis) · `tests/test_graceful_shutdown.py:92` — `assert elapsed < 1.5` with `timeout=0.5` in the underlying call. The synthesis already flagged this. Confirmed still present. The `_FakeJob` `cancel()` method sets `_exit`, so the thread should exit almost instantly — but on a heavily loaded CI runner, thread scheduling overhead plus the `join(timeout=0.5)` inside `request_shutdown` can push the elapsed above 1.5s. The synthesis fix-shape applies: scale to `< timeout * 3.0` or use the alive-check as the sole assertion (the alive-check is already there on line 93).

**MED** · `tests/test_graceful_shutdown.py:114` — `assert elapsed < 1.0` in `test_timeout_caps_drain_wait` with `timeout=0.3`. Under VM/CI jitter a 0.3s timeout can legitimately push elapsed to 0.35–0.4s plus test overhead, approaching 1.0s. The margin is tighter than it looks. Fix: raise to `< timeout * 4.0` or replace with the liveness check (line 116–117 already has the stronger check; line 114 is redundant when the liveness check is present).

### Dimension 6 — Test isolation

**MED** · `tests/test_etag_and_gzip.py:20` — Module-scoped `client` fixture sets `app_module.app.config['TESTING'] = True` on the live app singleton with no teardown. Because `app` is a Python module-level singleton, the `TESTING` flag persists across all subsequent test modules loaded in the same process. If another module runs after this one and expects `TESTING` to be `False` (or unset), it will silently inherit the mutated state. Fix: add `yield c; app_module.app.config.pop('TESTING', None)` in the fixture body (or use `monkeypatch` — but `monkeypatch` is function-scoped and can't be used in a module-scoped fixture directly; the teardown approach is correct here).

**MED** · `tests/test_etag_and_gzip.py:75` — `test_request_parity` (inside `TestCardDataETag`, a non-fixture method) also sets `app_module.app.config['TESTING'] = True` directly on line 75 without any teardown. This is a second independent mutation of the same global, this time inside a test method (not even a fixture). Fix: use the module `client` fixture, or wrap in `try/finally: del app_module.app.config['TESTING']`.

**MED** · `tests/test_graceful_shutdown.py:69–79` — `test_calls_cancel_on_running_jobs` clears `shutdown_requested` before calling `request_shutdown` but has no `try/finally` to clear it afterward. If the two assertions on lines 78–79 raise, `shutdown_requested` is left in the SET state for all subsequent tests in the process. The next test (`test_waits_for_running_thread_then_exits`) does NOT pre-clear it either. Fix: wrap the body in `try/finally: base_mod.shutdown_requested.clear()`, matching the pattern already used in `test_sets_shutdown_event`.

Fix: replace with `from tests._util import read_source` and call `read_source('scraper/hltb_lookup.py')` directly.

## D. Performance & Cost

### Dimension 16 — Fixture scope & shared setup

**MED** · `tests/test_etag_and_gzip.py:17` — The `client` fixture is `scope="module"` and sets `app.config['TESTING'] = True` on the live singleton. Module scope is correct for the gzip tests (they don't mutate state). However the `TestCardDataETag.test_request_parity` method creates its *own* client (line 76) outside the fixture, bypasses the scope, and still sets `TESTING`. The two clients co-exist for the duration of the module. This is needlessly expensive (two app context setups) and the second config mutation is unguarded. Fix: make `test_request_parity` accept the module `client` fixture instead of building its own.

**LOW** · `tests/test_database_backup.py` — Five tests each create a real on-disk `tempfile.TemporaryDirectory()` and write SQLite files. For the read-only verification tests (e.g. `test_backup_creates_consistent_copy`), the `_populate` helper and `backup_database` call are the only per-test variables; a shared fixture for the populated source DB would remove repeated disk I/O. Fix: session- or module-scoped fixture for the source DB, function-scoped for destination paths.
